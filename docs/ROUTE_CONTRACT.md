# 路线通用契约

> 这份文件定义**所有路线必须声明什么**，不定义某条路线怎么跑。
> 具体页面、判据与素材仍在 `docs/maintenance/<路线>.md`；
> 动作级的转场细节在 [页面转场契约](TRANSITION_CONTRACTS.md)；开发顺序见路线变更规范（文档负责人统一入库后补链接）。

## 一、为什么要有这一层

2026-11-24 复核 21 条路线、418 个提交：一次跑通 7/21，单条路线小修在 3 次以内的 8/21。
高频原因前三条占 67%——点完没有回执、同一画面两种用途、弹窗挡住按钮。

这三条**不是某条路线写错了**，而是没有任何一层要求每条路线把「活干完停在哪、会被什么挡住、
点完怎么算成功」说清楚。每加一条路线，就在不同的地方各写一遍，写漏了也不报错。

所以先立一层路线级的**最低声明**：所有路线同一份表，缺了在加载期就起不来。
具体的页面与判据仍然一条一条补，那是第二阶段的事。

## 二、五条声明

| # | 声明 | 回答什么问题 | 治哪个高频原因 | 机器怎么查 |
|---|---|---|---|---|
| 1 | **终点** | 活干完停在哪一页；是否收尾回大厅；不回大厅的合法终点是什么 | 活干完回不去（6%） | 终态名必须在该路线的状态集合里；不回大厅必须写理由 |
| 2 | **覆盖层** | 这条路线会被哪些弹窗、奖励层、确认框挡住 | 弹窗挡按钮（12%） | 类别必须来自全局弹窗守卫的登记表；空集也要显式写 |
| 3 | **空态** | 什么情况算「今天本来就没活干」：已领完、售罄、次数为零 | 空页被当成故障（1%） | 空态名必须在状态集合里，或显式写「无」 |
| 4 | **动作回执** | 点完之后靠什么算成功：页面变了，还是页内内容变了 | 点完没回执（33%） | 开转场契约开关的写 `transition_contract`；否则必须在豁免名单里有理由 |
| 5 | **危险动作** | 这条路线哪些操作不可逆、花资源、会扣费 | 误点不可逆操作 | 引用[安全与支持证据矩阵](SAFETY_MATRIX.md)的行，缺行即不通过 |

五条都是**路线级的最低声明**，不涉及阈值、坐标、模板。写得出来的前提是想过；
想不过来的路线，说明它还没到能上线的程度。

## 三、声明写在哪

写在路线的注册项上，与中文名、默认次数同一处，不再另建一份表：

```python
# games/epic7/modes.py
"hunt": ModeSpec(
    name="hunt",
    label="狩猎",
    ...
    contract=RouteContract(
        mode="hunt",
        terminal="HUNT_HOME",          # 必须是 states 里的某个终态
        finish_at_home=True,           # False 时必须写 finish_note
        overlays=frozenset({"reward_notice", "stamina"}),  # 会挡住本路线的覆盖层
        empty_states=("OUT_OF_TICKETS",),                  # 空态名，或 ()
        action_evidence="transition_contract",
    ),
),
```

字段含义与校验规则见 `games/epic7/route_contract.py`。三条硬约束：

1. **空集也要显式写**。`overlays=frozenset()` 表示「确认过，没有覆盖层」；
   漏写字段与「确认没有」不是一回事，前者会在加载期报错。
2. **终态名必须真实存在**。写一个状态机里没有的名字，加载期报错，不等到实跑。
3. **回执方式只能二选一**：开转场契约，或在豁免名单里写清「用自己的什么机制验收」。
   两条都不占，加载期报错。

## 四、加载期怎么拦

与现有的「接力表态」「转场表态」「导航链声明」同一套做法：`modes.py` 在 import 阶段
调用 `_assert_route_contract_declared()`，三种情况直接抛错：

| 情况 | 结果 |
|---|---|
| 路线没有 `contract`，也不在欠债名单里 | import 失败，提示补哪五个字段 |
| 新增路线想进欠债名单 | import 失败，提示「新路线必须一次写全」 |
| `contract` 里终态、覆盖层、空态与代码对不上 | import 失败，指出具体字段与合法取值 |

### 欠债名单

现有 21 条路线不可能一天补完，允许一份 `CONTRACT_BACKLOG`，每条写明缺哪几项、
为什么还没补（通常是「需要实机确认终点或覆盖层」）。两条规矩：

- **只减不增**：新增路线不许进名单，进了就是 import 错误。
- **公开可查**：`tools/route_compliance.py` 把名单与缺口一起打出来，进 STATUS 的
  「按路线的现行事实」，不藏在代码注释里。

## 五、合规矩阵

```powershell
python -m auto_game_unified.tools.route_compliance
```

输出每条路线一行的矩阵：

| 路线 | 契约 | 终点 | 覆盖层 | 空态 | 回执 | 危险动作 | 结论 |
|---|---|---|---|---|---|---|---|
| 英雄合成 | 已声明 | 通过 | 3 类 | 1 项 | 转场契约 | 有 | 达标 |
| 狗粮 | 欠债 | — | — | — | 缺 | 有 | 欠债 |

`--strict` 时有欠债即返回非零，供发布前检查。矩阵是**声明层**的结论，
不代替实机验收；声明齐了但没在真机跑过，仍然只是「试用」。

## 六、与现有文档的关系

| 文档 | 管什么 | 本页与它的边界 |
|---|---|---|
| 本页 | 路线级最低声明（终点、覆盖层、空态、回执、危险动作） | 不写页面链路与判据理由 |
| [页面转场契约](TRANSITION_CONTRACTS.md) | 动作级：来源页、目标页、页内证据、重试与结论门槛 | 本页的「回执」只声明方式，细节在那里 |
| 路线变更规范（文档负责人统一入库后补链接） | 一次变更的顺序、门与预算是多少 | 本页是「路线必须具备什么」，不是「怎么改」 |
| `docs/maintenance/<路线>.md` | 这条路线在游戏里怎么走、判据为什么这么设计 | 本页只要求它存在且六节齐全 |

## 七、第二阶段：逐条落实（不在本轮）

机制先落地，路线再补。顺序按返工量排，不按字母：

| 批次 | 路线 | 补什么 |
|---|---|---|
| 1（2026-11-24 已补） | 英雄合成、主线、竞技场 | 终点与覆盖层先补，回执已在契约里 |
| 2（2026-11-24 已补） | 刷书签、迷宫强化石、远征 | 空态与终点 |
| 3 | 世界首领战、骑士团、月塔、支线、月光 | 覆盖层 |
| 4 | 其余 | 逐条补齐并跑一次实机 |

每条路线补完的判定：矩阵从「欠债」变「达标」，且该路线手册的「危险边界」与
「已知缺口」两节与声明一致。
