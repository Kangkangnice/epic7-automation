# 路线通用契约

> 这份文件定义**所有路线必须声明什么**，不定义某条路线怎么跑。
> 具体页面、判据与素材仍在 `docs/maintenance/<路线>.md`；
> 动作级的转场细节在 [页面转场契约](TRANSITION_CONTRACTS.md)；业务标准见[路线开发与验收](howto/route_change.md)。

## 一、为什么要有这一层

每条路线在注册时说明业务终点、覆盖层、空态、回执和危险动作。加载时统一校验声明，具体页面和判据由对应路线维护。

## 二、五条声明

| 声明 | 要确认的事 | 结构检查 |
| --- | --- | --- |
| **终点** | 完成后停在哪一页，是否回大厅 | 终态名必须在该路线的状态集合里；不回大厅须说明理由 |
| **覆盖层** | 哪些弹窗、奖励层或确认框挡住该路线 | 类别来自全局弹窗守卫登记表；空集也显式声明 |
| **空态** | 如何确认已领完、售罄或额度归零 | 空态名在状态集合里，或显式写「无」 |
| **动作回执** | 用哪项转场或页面变化证明完成 | 启用转场契约的写 `transition_contract`；豁免须说明理由 |
| **危险动作** | 哪些操作花费资源或不可逆 | [工程安全矩阵](SAFETY_MATRIX.md)须有对应行 |

五条都是**路线级的最低声明**，不涉及阈值、坐标、模板。写得出来的前提是想过；
想不过来的路线，说明它还没到能上线的程度。

## 三、声明写在哪

写在路线的注册项上，与中文名、默认次数同一处，不再另建一份表：

```python
# games/epic7/modes.py
"hunt": ModeSpec(
    name="hunt",
    label="狩猎",
    ...
    contract=RouteContract(
        mode="hunt",
        terminal="HUNT_HOME",          # 必须是 states 里的某个终态
        finish_at_home=True,           # False 时必须写 finish_note
        overlays=frozenset({"reward_notice", "stamina"}),  # 会挡住本路线的覆盖层
        empty_states=("OUT_OF_TICKETS",),                  # 空态名，或 ()
        action_evidence="transition_contract",
    ),
),
```

字段含义与校验规则见 `games/epic7/route_contract.py`。三条硬约束：

1. **空集也要显式写**。`overlays=frozenset()` 表示「确认过，没有覆盖层」；
   漏写字段与「确认没有」不是一回事，前者会在加载期报错。
2. **终态名必须真实存在**。写一个状态机里没有的名字，加载期报错，不等到实跑。
3. **回执方式只能二选一**：开转场契约，或在豁免名单里写清「用自己的什么机制验收」。
   两条都不占，加载期报错。

## 四、加载期怎么拦

与现有的「接力表态」「转场表态」「导航链声明」同一套做法：`modes.py` 在 import 阶段
调用 `_assert_route_contract_declared()`，三种情况直接抛错：

| 情况 | 结果 |
|---|---|
| 路线没有 `contract`，也不在欠债名单里 | import 失败，提示补哪五个字段 |
| 新增路线想进欠债名单 | import 失败，提示「新路线必须一次写全」 |
| `contract` 里终态、覆盖层、空态与代码对不上 | import 失败，指出具体字段与合法取值 |

### 欠债名单

`CONTRACT_BACKLOG` 当前为空。若复核既有声明，使用合规矩阵定位；新路线须一次写全声明。

- **只减不增**：新增路线不许进名单，进了就是 import 错误。
- **公开可查**：`tools/route_compliance.py` 输出声明层的缺口；使用者关心的业务验收状态统一在 [现状速查](STATUS.md)。

## 五、合规矩阵

```powershell
python -m auto_game_unified.tools.route_compliance
```

输出每条路线一行的矩阵：

| 路线 | 契约 | 终点 | 覆盖层 | 空态 | 回执 | 危险动作 | 结论 |
|---|---|---|---|---|---|---|---|
| 英雄合成 | 已声明 | 通过 | 3 类 | 1 项 | 转场契约 | 有 | 达标 |
| 狗粮 | 欠债 | — | — | — | 缺 | 有 | 欠债 |

`--strict` 时有欠债即返回非零，供发布前检查。矩阵是**声明层**的结论，
不代替实机验收；声明齐了但没在真机跑过，仍然只是「试用」。

## 六、与现有文档的关系

| 文档 | 管什么 | 本页与它的边界 |
|---|---|---|
| 本页 | 路线级最低声明（终点、覆盖层、空态、回执、危险动作） | 不写页面链路与判据理由 |
| [页面转场契约](TRANSITION_CONTRACTS.md) | 动作级：来源页、目标页、页内证据、重试与结论门槛 | 本页的「回执」只声明方式，细节在那里 |
| [路线开发与验收](howto/route_change.md) | 业务动作、变更验证、评分和放行 | 本页规定注册声明及其结构校验 |
| `docs/maintenance/<路线>.md` | 这条路线在游戏里怎么走、判据为什么这么设计 | 本页只要求它存在且六节齐全 |
