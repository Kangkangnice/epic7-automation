# 截图与模板采集

## 两类图像的职责

- Fixture：完整游戏窗口截图，保存到 `tests/fixtures/`，用于离线重放真实页面。
- Template：从 fixture 中裁出的稳定局部锚点，保存到 `games/epic7/templates/`，用于线上匹配。

不能只保存按钮裁剪。没有完整 fixture，就无法判断误识别来自背景、弹窗、坐标区域还是相似按钮。

## 坐标基准

当前模板参考尺寸是 `1982 x 1132`，坐标是游戏窗口内部坐标，不是桌面坐标。

- 窗口移动不会改变局部坐标。
- 等比例缩放由匹配器处理。
- 宽高比变化必须重新校准，不能继续使用旧坐标。
- 截图前确认捕获的是游戏窗口，不包含 Codex、桌面或其他应用。

## 选择稳定锚点

优先选择：

- 固定文字或独特字形。
- 按钮图标和轮廓。
- 页面标题、页签状态和固定返回按钮。
- 与动作同时出现的第二个确认锚点。

避免选择：

- 章节场景、角色立绘和大面积动态背景。
- 技能动画、粒子和亮度变化区域。
- 资源数字、红点、传单角标和倒计时。
- 只在某个账号、等级或队伍中出现的内容。

需要背景无关识别时，可使用亮度/颜色掩码、边缘或限定区域匹配，但必须用不同章节背景的截图验证。

## 搜索区域与危险按钮

每个模板都必须有尽可能小的搜索区域。搜索区域除了提高准确率，还要明确排除危险按钮。

例如远征传单只允许识别卡片内部“远征队出发”，搜索区域必须排除右下角“所有远征队出发”。购买操作必须同时识别标题、资源类型、价格和确认按钮，任何一个锚点缺失都不能点击。

## 标准采集记录

每张页面至少记录：

- 页面名称。
- 从哪个页面和动作进入。
- 下一步允许动作。
- 稳定锚点和搜索区域。
- 必须忽略的动态区域。
- 页面可能出现的可选弹窗。
- 禁止点击的控件和资源路径。
- 页面是否能作为循环完成标志。

文件名使用能描述故障或页面的英文小写名称，例如：

```text
tests/fixtures/epic7_expedition/campfire_idle.png
games/epic7/templates/expedition/campfire_idle.png
```

## 入库前无损压缩（体积门槛）

新增或替换 `tests/fixtures/**` 与 `games/epic7/templates/**` 的图片，`git add` 之后、提交之前先压一遍：

```powershell
python tools/compress_images.py --staged          # 只看报告，不写盘
python tools/compress_images.py --staged --apply  # 真压
git add <刚压过的文件>
```

- 压的是**无损**：压完把两边都解码出来逐位比对，不一致就丢弃结果、保留原文件并报错（退出码非 0）。
- 实测收益（2026-09-30，5 张代表样本）：整屏 `1982x1132` 省 18%~19%，
  `3200x2000` 的旧夹具省 23%~26%；模板小图多数达不到门槛，会被自动跳过。
- ⚠️ **不要拿它去压存量再提交**：那只会把压缩后的新 blob 加进 pack，历史里的旧 blob
  一个都不会少，`git clone` 反而变大。存量要瘦身只能走**历史重写**（`git filter-repo`），
  那是另一件事，见下节。

### 存量为什么不能用这个工具瘦身（2026-09-30 实测数字）

- 压之前：`.git` 846.6 MB（loose 479.65 MiB + pack 366.64 MiB），工作区夹具 463 MB。
- `git prune-packed` + `git gc --prune=now` 之后：`.git` **640.4 MB**（省 206 MB，全部对象进单一 pack）。
- `git rev-list --objects --all` 统计：`tests/fixtures/*` 在**全部历史版本**里的 blob 合计 564 MB，
  `docs/manual_review/*` 另外 79 MB。按 20% 的无损收益估，历史重写大约还能再省 120~130 MB ——
  要拿这笔收益必须改写历史并强制推送，代价与收益都写在这里供决策，不默认执行。

### 要走历史重写的话（**一次性、不可逆，默认不做**）

上面那 120~130 MB 只有改写历史才拿得到。它要**强制推送**、会让所有人的 clone 失效，
所以它不是「顺手做一下」的事，而是一次需要你点头的决策。真要做，按这个顺序：

1. **先确认没有别人在推**：`git log --oneline origin/main..HEAD` 与各分支的未推送提交，
   改写会把它们全部换成新哈希。
2. **留一份完整备份**（不是 `git stash`，是另一个目录里的 `git clone --mirror`）。
3. 装上 `git filter-repo`（`pip install git-filter-repo`），然后对**每个历史版本**的 PNG
   做无损重压 —— 关键是 `--replace-blob` / `--blob-callback` 的写法必须调用
   `tools/compress_images.py` 里那套「压完逐位比对像素」的实现，**不能**只调 Pillow：
   历史 blob 一旦压坏无法回滚。
4. 重写完在**新 clone** 上跑一次全量门槛（`python tools/check.py --full`），
   夹具内容不变的话应当是同一批结果。
5. 再 `git push --force-with-lease`，并通知所有 clone 重拉。

⚠️ 别把它和功能改动混在同一段时间里做：重写之后所有本地分支的哈希都变了，
正在开发的分支要么先合、要么重放。

## 判据型模板不许静默降级

> 2026-11-08 从 `AGENTS.md` 移到这里：`AGENTS.md` 只留摘要与指针（它太长会掉遵循率）。
> 这是一整类**静默失效**问题的集中记录，改判据前必须读完。

用来**判页 / 判危险 / 判覆盖层**的模板，**没有「可选」这一档**。
`if path.exists() else None` 会让判据在模板被删后**悄悄消失**：页面认不出来，
或者更糟 ——「覆盖层必须先关掉」这类保护失效，点到覆盖层底下。
（合成 / 传送**消耗资源、不可逆**。装备子页那条判据就是这么丢了半年没人发现。）

一条规矩要三样齐，缺一样当没做：**文档写清 + 代码门槛（加载期或构造期直接报错）
+ 护栏测试**。落地样板：

- `Epic7Navigator._assert_anchor_templates()` —— 凡登记在 `_REGIONS` 里的锚点
- `HeroSynthStateMachine._assert_anchor_templates()` —— 凡登记在 `evidence.atoms` 里的锚点

⚠️ 这类「结构性」规矩要用 **AST / 源码静态守**，因为真出问题的分支**跑夹具到不了**
（2026-10-03 实测：25 张夹具 × 全部状态扫了 464 个动作，那 3 处缺口一个都没覆盖到）。
并且**反向喂违规输入**证明它会红 —— 拿 `git show HEAD:<file>` 的旧版源码当反例最省事。

### 「可选模板」最恶的形态：判据整个不存在

不是判据变弱，是判据整个不存在（2026-10-04 远征实证）。
「可选」听起来像「这个控件不一定出现」，实际代码语义是**「文件不在也当它没命中」**——
于是「模板被删 / 从没做过」和「画面上没这个控件」**在代码里长得一模一样**。
远征栽在这上面：`empty_posters`（传单用完该收工）**模板文件从来就没做**，收工判据整个失灵，
系统在空列表上一直找出发按钮，**空等到超时 6 次**（2026-09-19~10-03 半个月）。

两条加固，落地在 `ExpeditionStateMachine`：

- **`_locate()` 的静默兜底要收口**：原写法对**任何** `None` 模板都 `return None`。
  现在只允许**白名单里的**（`_OPTIONAL_TEMPLATES`）缺席，其余抛 `RuntimeError` 点名。
  「可选」从此是一份**显式声明**，不是默认行为。
- ⚠️ **测试里用假图顶替模板 = 把缺陷焊死**：远征的测试用 `pattern(3)` 造真值数组，
  所以测试全绿；更糟的是有一条断言**「`templates.empty_posters is None`」**，
  把缺陷写成了预期行为。⇒ 凡判据模板，测试必须覆盖**「文件真的存在」**这一层
  （`build_*_templates(真实目录)` + `assertIsNotNone`），别只测假图。

⚠️ 排查同类问题时，**证据包里 `score=None` 是关键信号** —— 它不是「0 分」，是
**根本没打分**（模板不存在，`_locate` 提前返回了）。看到 `None` 就直接去查文件在不在。

### 运行时的静默降级：等一个判据出货，日志整段空白

判据落进死区时 `next_action()` 返回 None —— 不出手、不打分、不报警，日志会**整段空白直到超时**
（2026-10-04 08:34:30 进刻印页 → 08:36:02 超时，中间一行都没有，只能事后翻现场帧才知道卡在哪一档）。
凡是「等一个判据出货」的等待循环，都要有一条**周期心跳**把当前依据打出来
（英雄合成：刻印页等待每 10 秒一行；先例是「中止返回等待」「英雄子页等待」）。
心跳和超时诊断**共用同一份依据产出方法**，别写两遍。

### 一个锚点可以有多个候选模板

同一控件的不同长相，走 `AtomEvidence.alt_template_paths`：
大厅「秘密商店」入口 = 干净版 + 带角标版；英雄合成「SSS 材料」徽记 = 前排展开的大卡
100% + 后排被压暗的小卡 ~90%。判据语义是「**任一候选过阈即命中，取过阈候选里的最高分**」，
候选与主模板**同等必需**。两道关都要能拦「整组为空」：

- 构造期判空必须写 `value is None or (isinstance(value, tuple) and not value)` ——
  只写 `is None` **拦不住空元组**；
- `validate_profile()` 要**逐条**查候选路径（2026-10-04 才补上：此前只查主模板，
  候选被删时它一声不吭 ⇒ 判据少一档长相而静默降级）。

### 「模板量进死区」的三步排查法

同一枚徽记被**画成不同大小**是真实存在的，而且**档位不止一两档**（2026-10-04 二次踩，
推翻了上一条「多候选比多尺度更稳」的判断）：当时只看手上那两张帧（尺寸**恰好相同**）就以为
「只有 100% / 90% 两种画法」，于是补了候选模板；第二天出现 **80% 档**，同一处又静默卡死 90 秒。
所以遇到「模板量进死区（0.55~0.80）」，按这三步走：

- **先做多尺度扫描，再看峰值分布**：把模板在 0.7~1.1 区间逐档扫一遍，看峰值尺度**在不同帧上
  是否变化**。峰值锁在一两档 → 补候选模板就够（「秘密商店」入口那种）；峰值随帧漂移 →
  **补模板就是打地鼠**，必须多尺度扫描（`_SSS_TEMPLATE_SCALES`）。
- **先怀疑尺寸，别怀疑亮度**：`TM_CCOEFF_NORMED` 对**整体乘性亮度**不变 —— 亮度 ×0.45
  分数只从 1.0000 掉到 0.9987，去饱和 50% 也还有 0.9691；而同一区域整缩到 0.80 直接掉到
  **0.2425**。所以「卡片被压暗 / 变灰 / 被图标遮住」这类直觉**先量一遍再排除**。
- ⚠️ 验「共享打分函数的第二个调用方」（如传送页）**必须走生产口径**取参数（真实卡片 y，
  用 `_transmit_target_card()` 拿）。自己穷举位置会把区域挪到能蹭到别处内容的地方，量出
  `transmit_select` 0.9388 这种**假误判** —— 生产口径下它只有 0.4124，零回归。

### 转场契约开关「挂着」不等于「生效」

2026-10-04 英雄合成实证：`_REQUIRE_TRANSITION_CONTRACT = True` 读的是基类
`RouteAction.in_page_evidence`。英雄合成的同页证据当时叫**自造的** `source_observation` ——
名字不齐时开关**开着也管不到**那 12 个同页动作：它们靠 `target_pages` 里塞当前页过检查，
**形式合规、实质没用**（本页永远在集合里 ⇒ 验收永远通过 ⇒ 分不出「点了没生效」和「点了生效了」）。

⇒ 打开某条路线的开关之前，**先跑一遍那个检查函数**，并确认「路线自造的证据字段名」
与「开关读的字段名」是同一个（`world_boss` 打开时踩的是同构坑：字段根本不存在）。
同类「忘了同步」还有一处：开关与 `TRANSITION_EXEMPT` 是**二选一**，两边都留 ⇒ 加载期报错。

## 测试顺序

1. 把新完整截图加入 `tests/fixtures/`。
2. 写一个只描述目标行为的失败测试。
3. 运行该测试，确认它因为缺少新识别能力而失败。
4. 裁剪最少模板或增加最小专用识别逻辑。
5. 运行专项测试直到通过。
6. 加入相似页面、动态背景或危险资源的反例。
7. 运行全量测试和编译检查。

不要先修改阈值再补测试。一个页面的问题优先修正模板、区域或专用前景提取，不能顺手降低所有模式的阈值。

## 当前客户端边界

游戏更新后，旧模板只能作为历史参考，不能直接声称当前版本受支持。尚未采集的页面必须保持安全停止，并在 README 限制清单中记录；首次实测出现后，再按本流程增加 fixture、失败测试和模板。
