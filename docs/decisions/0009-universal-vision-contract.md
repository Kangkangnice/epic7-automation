# 0009. 将跨端视觉识别收敛为共享语义契约

> 本文是共享视觉迁移与新增路线的架构规范。`accepted` 表示采纳规则；现有路线的运行策略和
> 发布状态仍以实机验收为准。未迁移路线的历史覆盖图保留到各自切换。
> 单条路线的执行入口见 [一句话移植到 PC](../PC_TEMPLATE_MIGRATION.md#3-一句话移植到-pc)。

## 背景

当前项目已经把大多数业务路径统一为“窗口截图 → 视觉证据 → 状态机 → 动作 →
转场验收”。PC 客户端与模拟器也已经共享基准画布、绝大多数坐标和路线状态机。

但视觉层仍把两端的渲染差异表示为 PC 覆盖图、局部的 PC 条件分支，以及少量逐锚点的
模糊/缩放兜底。它解决了已知现场，却意味着每出现一个新的渲染变体，就可能需要再采一张
PC 图；随着模拟器、PC 版本和用户机器增加，维护成本线性增长。

“人眼看起来一样”与“原始模板像素可以直接匹配”不是一回事：

- 人识别的是文字、图标、页面结构和业务语义；普通模板匹配比较的是一块 RGB 像素矩阵。
- 字体栅格化、抗锯齿、描边、透明遮罩和局部亮度会改变少量关键笔画，足以让文字模板失分。
- 同一客户端会出现 UI 尺寸漂移；相关性匹配不具备尺度不变性。
- 少量 PC 画面不是“同一个像素长相”，而是同一业务状态多了中间确认页、通知层或不同的
  可点击控件。这是**视觉变体**，不是另一条业务路线。
- 截图通道和输入通道本身也不同；例如 PC 的后台点击、前台滑动和模拟器的 adb 输入不能混为
  同一种能力。

因此不能把“统一”理解成全局降阈值或全局模糊。那会把相似弹窗和底层被遮挡控件一起抬高，
违反项目的失败关闭原则。

## 决定

最终运行时采用**共享语义视觉契约**：所有路线只声明业务页面、允许动作和可证伪的视觉
证据；PC 与模拟器只提供截图/输入适配器。生产路径不再按后端选择 PC 专属模板。

### 范围与硬边界

1. 目标是零 PC 专属模板的运行时依赖。采纳本契约即冻结新增 PC 运行模板。
   既有生产覆盖可保留到对应路线切换完成，随后只将需要的证据留作离线回归数据。
   迁移全部完成后，安装包应排除 PC 覆盖图和离线回归数据。
2. 继续使用当前 `1982 × 1132` 业务画布与窗口局部坐标。不同截图后端先归一为这一坐标系，
   不能让业务状态机知道桌面坐标、DPI 或黑边。
3. 陌生页面、低置信度文本或证据相互冲突时必须安全停止并留诊断；不允许“为了兼容”使用
   固定坐标盲点、放宽全局阈值或 OCR 单独点击。
4. 此决定不改变 PC 输入的真实限制：后台点击、前台滑动/滚轮、权限要求仍属于窗口 I/O 层。
5. 不要求最终用户截图、裁图或安装某套 PC 图片包。启动自检只保存标定数字；诊断截图仍只留
   在用户本机，是否提交由用户自主决定。
6. 新路线在一个基准端定义页面、控件与业务流程即可。对同一 UI 的渲染差异，新增路线不得要求
   人工在另一端复刻开发、给单张图调分或加入锚点白名单。跨端兼容是公共引擎的能力，由自动
   回放和发布验收验证。客户端确实新增业务步骤时，按画面证据补共享转场。
7. 发布门槛为当前发布范围内的模拟器路线全部完成 PC 实机闭环，至少 90% 使用默认公共策略，
   全部零 PC 专用运行模板。极少数有真实差异的路线可在一处集中登记数字标定或明确的业务变体。
   登记须附判据、真机正反例与复核条件；例外计入未使用默认策略的路线数，不得跳过动作契约。
   跳过、超时和缺少真实业务路径均不能计作迁移通过。

### 目标结构

```text
PcAdapter / EmulatorAdapter
        │ capture() → 原始帧，click/swipe/back() → 平台输入
        ▼
ViewportCalibrator
        │ 画布、补边、窗口偏移、局部 UI 尺度（数字化会话 profile）
        ▼
VisualNormalizer
        │ 原图、笔画掩膜、边缘/形状、颜色/几何、受限 OCR
        ▼
VisualMatcher + ScreenContract
        │ 当前页面、可点控件、排他反例、命中依据与分数
        ▼
共享状态机 / Runner / 五段转场契约
```

#### `VisionSession`：一次运行一个不可变的视觉上下文

以每次 `run_mode()` 创建的 `VisionSession` 替代进程级后端开关。它持有：

- `ViewportProfile`：客户端内容区、画布映射、可信的局部 UI 尺度范围；
- `VisualMatcher`：共享模板、匹配策略与诊断出口；
- `ScreenContract`：页面、动作、来源/目标/完成证据；
- `BackendCapabilities`：只描述 I/O 能力，例如是否支持后台点击、滑动和滚轮。

状态机和 evidence 层只接收 `VisionSession` 的观察结果，不读取 `backend == "pc"`，也不读取
全局可变的 matcher 后端状态。这样同一进程可在测试中并行重放不同后端的帧，不会由调用顺序
改变判定结果。

#### `ViewportCalibrator`：先量尺度，再匹配

它在启动和画面明显变化时，用多个稳定且非危险的共享锚点估计画布位置与局部 UI 尺度。结果
需要至少两个互不重叠的锚点支持，取稳健统计值；不足则标定失败、停止在预检阶段。

匹配时先尝试原始尺度，失败后只在该会话可信范围内做局部多尺度搜索。搜索区域可扩张少量
安全边界，但动作坐标永远来自当前帧的真实命中位置，不能用缩放后的历史坐标直接点击。

#### `VisualNormalizer`：一张共享模板，多种可验证表示

共享模板仍是唯一视觉资产。加载后在内存中派生以下表示，而不是产生 PC 副本：

- 原始 RGB：优先路径，保留现有高精度判据；
- 自适应笔画/白字掩膜：忽略抗锯齿、背景和亮度变化；
- 边缘与形状表示：识别图标、按钮外框和文本轮廓；
- 颜色/几何特征：识别红点、亮/灰、选中态、对话框遮罩等不适合模板匹配的状态；
- OCR 文本及其边界框：只用于声明过的文字区域。

正常路线共用同一入口。匹配方法由控件类别或图像信息量选择，阈值、候选歧义检查和拒绝规则
集中在公共引擎，每种表示分别用正例和反例校准。路线配置只说明找什么、在哪里以及何时可点，
默认路径不传入按路线、平台或锚点名称调整的跨端阈值。相似度只能提出位置候选，是否处于前景、按钮
是否可用、最佳候选是否有歧义均由公共判定检查。

2026-11-18 对照用相同的原图、低通和五档尺度扫描共找到了 15 个跨端正例，覆盖世界首领战、
月塔和竞技场，取 0.82 作门槛时 4 个不可当作目标的相似或遮挡反例也全部过线。最低正例
0.8441，最高反例 0.9336，单靠这个分数无法分开两组。实验说明找候选可共用规则，同时需要
对前景和动作语义独立验收。世界首领战离线回放里的逐锚点阈值只保留为实验对照。

#### OCR：加入，但永远不是单独的点击许可

优先复用项目已有的离线 `rapidocr-onnxruntime`。模型替换需要回归识别率、Windows 打包体积、
启动耗时和 CPU 占用。

OCR 只处理 `ScreenContract` 中声明过的有限 ROI 和有限词表，例如页面标题、`确认`、
`开始战斗`、`点击关闭`。一次 OCR 命中还必须同时满足以下至少一项，才可形成动作候选：

1. 页面结构锚点或图标锚点成立；
2. 目标按钮的形状/颜色/几何约束成立；
3. 已处于该动作允许的稳定来源页面。

OCR 置信度低、文本不在允许区域、出现歧义文本或缺少第二证据时，一律视为未知。OCR 的文字
框可以帮助定位按钮，但标题文字绝不能直接充当点击点。

#### `ScreenContract`：用业务语义容纳视觉变体

每个逻辑页面定义多个等价 `PageVariant`，而不是把分支写成“PC 页”或“模拟器页”。例如一个
确认动作可以由“共享图标 + 按钮轮廓”或“确认文本 + 对话框结构”识别；两者都映射到同一个
逻辑页面与动作。PC 才出现的中间确认页也作为同一业务状态的变体存在。

页面识别、动作定位和动作验收必须分离：

- 页面判定至少由页面锚点和排他反例组成；
- 动作判定还需要当前帧中的可点击控件；
- 点击后继续沿用来源退出、目标进入、业务完成的五段证据与两帧稳定门槛。

### 迁移顺序

1. 建立跨端离线语料：为完整帧标注预期逻辑页面、允许动作和安全停止结论；现有 PC 覆盖图
   仅用于定位需要替代的锚点，不能成为生产 matcher 的输入。
2. 先实现 `VisionSession`、标定、统一 `VisualMatcher` 和可解释的匹配结果；旧逻辑仍执行，
   新识别器只读旁观，记录两者结论差异。
3. 先验证公共引擎，用不同类型的页面和弹窗做正反例。校准规则后冻结配置，再回放未参与校准
   的整条路线。卡在外观差异时回到公共策略或窗口标定解决，逐锚点阈值的离线原型只作对照。
4. 复用同一套跨端回放验收各路线，自动比对页面、动作、落点和拒绝结论。结果符合标注期望，
   且无 PC 图片依赖后才切换。需要特调的路线按例外登记并计入预算。
5. 所有路线完成迁移后，删除生产侧 `TemplateDir` 的 PC 覆盖解析与视觉业务分支；保留 I/O
   adapter。安装包和运行期资源检查必须拒绝加载 `templates/**/pc/**`。

### 验收标准

一条路线迁移完成的最低标准：

- 同一批 PC 与模拟器完整帧得到相同的逻辑页面、动作候选或安全停止结论；
- 正例、相似页面、遮罩页和危险按钮页都进入回归矩阵；动作候选不可只测“找得到”；
- 同名控件可以跨路线复用。授权点击前须在当前画面同时确认来源页面、目标控件和业务可执行条件。
  世界首领战试点以可见的路线标题和右下控件共同确认主页，灰态控件仍可辨认页面，但不授予点击许可；
- 同一控件的启用态与禁用态需要比较分数时，两侧使用同一种图像表示与同一尺度。竞技场的选中态
  已在实机出现过原样匹配和低通匹配混比分数导致的误判；
- 文字标签与图标分开显示时，OCR 确认控件身份，布局确认该格内的图标落点。宠物小屋快捷入口已在 PC 实测验证这一区别；
- 每个新视觉表示都记录原始分、归一化分、匹配位置、尺度和拒绝原因，便于诊断；
- OCR 相关用例必须覆盖错字、低置信度、同词不同页、被遮罩和无第二锚点；
- 未知画面不产生点击；
- 打包检查证明运行期没有 PC 专属模板依赖；
- 保留整条路线作为留出测试，使用冻结的公共配置验证跨端识别。若仍需为它单独维护平台图、
  匹配阈值或白名单，这一轮公共方案验收不通过；
- PC 与模拟器各完成真实闭环验收。离线绿色只证明识别契约，不能替代实机闭环。

### 试点交接门槛

第一条路线由共享引擎负责人完成验证。禁止直接以逐锚点调分试验作为后续路线样板。

| 验收项 | 要提交的证据 |
| --- | --- |
| 素材和规则 | 物理去掉 PC 覆盖目录后仍能构建并回放。同一公共定位策略，无平台/锚点匹配阈值特调。 |
| 离线整链 | 用两端已标注的真实帧核对来源、动作、当前落点和结果。缺帧的段落单独标注，混合端回放不得记作任一端完整闭环。 |
| 拒绝条件 | 同名、候选歧义、遮挡、禁用、控件消失、初始落点改变、画面未知。应拒绝的样本不得发出动作。 |
| 真实业务 | 在同一套共享素材下，记录 PC 与雷电从大厅导航到真实奖励入账、返回大厅的完整日志。视觉候选或点击成功不得记为业务完成。 |
| 可推广性 | 冻结公共策略，验证未参与校准的场景，区分图像差异、业务差异和设备输入失败。确认测试命令、规则接口和已知边界可供后续路线复用。 |

以上满足后才将迁移样板交给其他 Agent。试点进度见[现状页的在制记录](../STATUS.md)。

## 后果

收益：

- 新增模拟器或 PC 版本不再首先意味着复制模板、复制阈值或复制路线；
- 视觉判据从“这张图像不像”提升为“当前是否满足页面和动作的语义证据”；
- 现有的失败关闭、诊断、转场契约和状态机可以继续复用；
- 用户无需参与模板维护，适配失败会在预检或安全停止时明确暴露。

代价：

- 需要集中改造 matcher 调用入口，不能只局部给某颗模板加模糊；
- OCR 会增加模型包、启动时间与测试矩阵，必须限制 ROI 和词表；
- 现有 PC 图不能立刻丢弃，它们在迁移期是最有价值的反例和回归依据；
- 视觉语义确实改变、且没有可识别文本/结构/颜色证据的新页面，仍必须停在未知页。
  这不是功能缺失，而是防止自动化猜测性点击的安全边界。

## 考虑过但被否掉的方案

| 方案 | 为什么没选 |
|---|---|
| 继续按需新增 PC 覆盖图 | 能快速救一个现场，但每个渲染变体都增加一份资产与维护点，无法达到零 PC 运行时依赖。 |
| 全局降阈值或默认低通模糊 | 能提高部分正例，却会同时提高相似弹窗和底层控件的分数；这会把“认不出”变成“可能误点”。 |
| 只用 OCR 取代全部视觉识别 | OCR 对文字有价值，但对图标、按钮状态、遮罩层和点击位置不够可靠；单独授权点击不符合失败关闭。 |
| 用固定坐标处理 PC 特例 | 坐标受窗口、DPI、局部 UI 尺度和页面变体影响；它绕开视觉验收，无法面向多用户安全扩展。 |
| 直接训练一个端到端目标检测模型 | 理论上可行，但需要大量标注帧、持续训练与模型发布治理；在现有模板/契约基础上，先走可解释的混合识别成本更低、可证伪性更强。 |
