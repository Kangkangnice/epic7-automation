# NNNN. 一句话说清这个决定是什么（用祈使句，不要用「关于……的思考」）

> 复制本文件到同目录，把 NNNN 换成下一个编号，然后逐节填。
> `status` 只能是：`proposed` / `accepted` / `superseded` / `deprecated` / `rejected`。
> **草稿期（还没提交）可以直接改「决定」正文** —— 一轮里试错三次很正常，
> 别为了守「只增不改」把废案留在正文、再追加一节说明，那样下一个人读前半段会拿到错做法
> （0007 就踩过这个坑）。
> **一旦入库就不要改决策本身**：变了就新开一份，在旧的 `superseded_by` 写新编号；
> 若只是正文里的实现细节写成了废案，允许在开头加一段「现行结论」指针，但决定不动。
> 门禁 `tests/test_docs_index.py` 会检查这几项元数据。

## 背景

当时遇到了什么问题、有什么约束。写事实，不写感想：哪次真机报错、哪个数字对不上、
哪条路走不通。后来的人要靠这一节判断「当时的条件现在还在不在」。

## 决定

我们决定做什么。一句话讲完，然后用列表写清边界 —— 什么在范围内，什么明确不做。

## 后果

这个决定带来的代价与收益，包括**接受了的缺点**。诚实地写缺点，
否则下一个人会以为是疏忽而「顺手修好」，把当初的取舍推翻。
