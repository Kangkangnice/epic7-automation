# 0012. 抗背景改动只给同锚点新增候选，不改既有锚点的口径与阈值

## 背景

大厅判据 `lobby_story` 是一整块含背景的截图（310×60），阈值 0.80、原样口径。
2026-11-21 用户两次更换大厅背景：

- 第一次换成木桌场景，分数 0.933 → 0.83~0.86，余量只剩 0.03~0.06；
- 第二次换成紫黑角色立绘，分数 0.8401，余量 0.04。

大厅是几乎所有路线的起点（导航器先认大厅，再进目标模式），余量掉到 0.04 意味着
一次轻微的渲染差异就会让**全部路线同时起不来**。用户提出「保证无论怎么换背景都认出来」。

可行性实测给出两条硬事实：

1. **纯视觉模板匹配做不到「任何背景」**。大厅文字是白色，背景换成纯白或浅灰时
   白字与底图无对比度：原样口径 0.0933、白字口径 0.0000，两种都认不出。
   只能覆盖现实会出现的背景（已见木桌、紫黑立绘、动画帧三种），并在极端背景下**安全失败、不乱点**。
2. **8 颗大厅锚点逐颗全库审计后，只有 1 颗（`lobby_story`）适合切白字口径**。
   其余 7 颗切过去要么丢真帧（`lobby_arena` 动画帧 0.85→0.71）、
   要么放进冒牌（`lobby_quick_menu_button` 全库过线从 298 涨到 468，蓝四格图标到处都是）。

于是问题变成：**在不动既有判据的前提下，怎么加一层抗背景。**

## 决定

遇到「换背景导致锚点分数被拖低」时，**不改既有锚点的比对口径与阈值**，
而是**给同一个锚点新增一个只含文字的紧模板候选**，用它自己的口径和阈值独立判定。

具体到大厅：

- 保留 `lobby_story`（310×60 / `MATCH_MODE_RAW` / 0.80）一字不动，
  模拟器与旧背景的判定结果与从前逐字节一致；
- 新增 `lobby_story_tight_white`（60×170，只裁「Episode」四字 / `MATCH_MODE_WHITE_MASK` / 0.90），
  白字掩膜把底图压平成「哪些像素是白的」，判据与背景色无关；
- 两张**各带各的阈值**，任一过阈即认大厅；不做「取最高分、按一条线判」。

边界：

- 新增候选必须先过**全库排他审计**（漏掉真页 = 0、放进冒牌 = 0）才能登记；
  本次结果：新紫黑 1.000 / 旧木桌 1.000 / 旧动画 0.931，
  全库过 0.90 的 18 张全是真大厅页，非大厅帧 `arena_mode` 0.234、`story_stage` 0.189。
- 白字锚点**不许进** `SMOOTH_FALLBACK_ANCHORS` / `SCALE_FALLBACK_ANCHORS`：
  低通会把 0/255 掩膜糊开，0.90 这条线是在未糊的域上量出来的，进去就是换了尺子判。
- 其余 7 颗大厅锚点**维持原样**，不跟进切换（审计数据见上）。

## 后果

收益：

- 大厅余量从 +0.04 回到白字口径的 +0.10 以上（新紫黑 1.000），且与背景色解耦；
- 老画面零回归 —— 原模板分数、阈值、口径全部不变，「模拟器零改动」的结构性保证没被打破；
- 判据从「一块含背景的面板」变成「四个字母的形状」，将来整块面板换皮也还有一个候选在。

代价（**接受了**）：

- 同一锚点多一张模板、多一次匹配：大厅判定从一次匹配变两次（热路径只在大厅页付这笔钱，
  原模板先跑，过了就短路不再跑第二张）；
- 白字锚点的 0.90 是**这一批帧**量出来的线，不是理论值。真出现浅色背景时它必然失败，
  这是物理限制，不是缺陷 —— 失败的表现是安全停止 + 诊断留帧，不会误点；
- `_locate` 里多了一处「按锚点名选口径」的分支。这是把口径绑在名字上，
  新增同类锚点时容易漏配，已用护栏测试钉住（`test_dark_portrait_lobby_is_recognized_by_the_white_text_candidate`）。

## 考虑过但被否掉的方案

| 方案 | 为什么没选 |
|---|---|
| 把 `lobby_story` 直接切白字口径 + 重定阈值 | 审计上可行（全库 19 张过线全是真大厅页），但它会改掉既有判据的口径，老画面的判定结果不再逐字节一致，违反「模拟器零改动」；新增候选能达到同样效果且是纯加法 |
| 8 颗大厅锚点全切白字 | 实测 7 颗会丢真帧或放进冒牌（见背景第 2 条） |
| 全局调低阈值 | 已实测否决：×0.9 新增 64 个误判组合，冒牌分可反超 PC 真页 |
| 每换一次背景补一张含新背景的模板 | 被动、无限累积，且没解决「主判据分数被背景拖低」的根因 |
| 「原样或白字任一过阈就算认出」（同一张模板、两个口径、一条线） | 两种口径分数不在同一量纲，共用一条线等于让其中一边按别人的尺子判。本决定允许的 OR 是**两张不同模板各带各的线**，不是这个 |
| 用 OCR 读文字 | 项目不用 OCR；中文识别依赖额外库，速度与稳定性都不如模板匹配 |
| 换大厅时要求用户别换背景 | 用户明确要求「无论怎么更换背景」，产品侧不接受这条约束 |
