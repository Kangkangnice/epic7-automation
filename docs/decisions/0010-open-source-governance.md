# 0010. 开源维护以仓库契约和可复验证据为准

## 背景

项目从单机日常路线发展为公开仓库。使用手册、路线数量、个人工作目录和维护流程曾被多份文档重复记录，
新贡献者需要猜测当前规则。仓库已具备 PR 检查、完整帧回归、发布构建脚本与自动生成的路线状态。

## 决定

- README 只承担上手导航和支持范围入口。长寿文档集中在仓库内，分别承担操作、事实参考与架构解释。
  单一事实由其所有者维护，生成页通过 CI 检查。文档索引保留每份长寿文档的可达链接。
- 用户报告走 Issue，代码审阅走 PR，长期技术选择走 ADR，未完的现场验证继续按 [0005](0005-handover-lives-in-docs-wip.md)记录。
  公开文件和评审内容需可脱离个人技能、路径、账号和本机临时文件阅读。
- 将检查与变更面对应。提交前钩子提供定向反馈，PR CI 验证干净检出的完整行为，真实游戏完成证据由维护者复核。
  给没有游戏账号的贡献者提供离线可验证的贡献路径。
- 保持 `core` 的独立依赖方向。游戏业务依赖核心观察与动作契约，桌面装配路线并消费结果。
  每次核心边界变更保留兼容入口与回归证据，迁移进度记录在架构说明。
- 由维护者验收并发布对应提交的工件。包内容、第三方许可、支持范围和回退步骤进入发布手册。

## 后果

同一文案随其事实源一起维护。新模块、文档或发布规则可以按所属责任区独立审阅。
现有用户的路线行为继续由真实帧、转场契约和以前验收过的实机路径提供基线。
