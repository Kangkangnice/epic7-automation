# 0002. 判据必须能证伪，不是「分数够高」

## 背景

这个项目靠模板匹配认页面。它最容易出的错不是「认不出」，而是**认出了错的结论** ——
两种情况在日志里长得几乎一样，但后者会让人对着错误的对象点下去，比认不出危险得多。

两次真实事故：

- **2026-11-07 竞技场「更新交战对手」**：半透明模态框压暗了对手行，
  「能不能打」靠的红色像素占比从正常值掉到 `0.0000`，于是三名都不可挑战
  被判成可打，弹窗永远轮不到点。补图只能解决「认不出」，解决不了这个。
- **2026-11-08 英雄合成红点**：靠「模拟器标框 + 3px 内缩」判定，
  PC 上立绘边框和红点连成一片，boundingRect 贴框被否决。翻卡动画里才偶尔命中，
  表现成「时好时坏」。

同时存在一种持续诱惑：调阈值、换比对口径，把分数凑上去。

## 决定

1. **每颗判据都要能回答一句**：靠哪一维排除了「外观同类、语义不同」的对象？
   答不出来就不是判据，是猜测。
2. **阈值必须有实测余量**：写出正例分布与**全库反例最高分**。
   反例要排除同类弹窗的其它样本，否则「最高分 0.9992」全是同族帧，毫无意义。
3. **禁止全局调阈值**。实测过：×0.9 会新增 64 个误判组合，冒牌分能反超真页。
4. **判据依赖「会被遮罩盖住的画面」时，必须问一句**：遮罩压上来它会变成什么？
   红/绿状态色、血条、数量角标全属于这一类。
5. **反向验证必须真的还原旧行为**。曾写过一个恒等式变异，
   两条用例照样绿，是假的反向验证。

## 后果

- 每颗锚点都要有正例帧、全库反例扫描结果、以及一句「为什么它能证伪」。
  这部分成本是硬性的，省不掉。
- 有些看起来「分数够」的方案会被否掉。例如低通 σ=2.0 能把 0.6681 抬到 0.9221，
  但它会把全库跨页分一并抬 0.2，页面排他性直接破 —— 分数好看不等于可用。

## 考虑过但被否掉的方案

| 方案 | 为什么没选 |
|---|---|
| 全局阈值 ×0.9 | 实测新增 64 个误判组合，冒牌分可反超 PC 真页 |
| 低通口径统一换分 | 全库跨页分同抬约 0.2；月塔「战斗指南」的确认按钮会撞到 0.9387 |
| 放宽判据区域 / 去掉内缩 | 只是把「贴边被否决」换成「把背景当成红点」，问题形态变了没变好 |
