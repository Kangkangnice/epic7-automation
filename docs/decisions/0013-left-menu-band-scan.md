# 0013. 左侧菜单布局随账号变化时按整条菜单带扫描并补白字文字候选

## 背景

2026-11-21 用户换用 MuMu 并换了一个账号跑每日任务，刷书签在「大厅缺少导航锚点
`lobby_shop_entry`」失败。图标与文字均未改变，背景也不是主因；真正差别是当前账号
没有左侧菜单里的「光辉里程碑」，其后整列入口上移约 93px：

- 有里程碑的账号：`??` 图标中心约 `(82, 521)`，原搜索区 `(0,430,220,230)` 命中 1.0000；
- 无里程碑的账号：图标中心约 `(82, 428)`，图标实际占 y≈397~459，原搜索区只框到下半截，
  87×62 的完整模板放不进去，分数 0.2738；
- 把区域扩到 y=300~660 后，干净模板仍只有 0.6404、带角标模板 0.5721
  —— 当前帧的红色 N 角标与 2026-09-27 存档的角标模板形态不一致。

同一失败帧上，左侧另外两颗入口也没过阈：`lobby_sanctuary` 0.7415、`lobby_activity`
0.2467。三者都是「单项坐标写死」造成的问题；人眼按文字和图标能在任意一行找到它们。

## 决定

大厅左侧竖排入口不再按单项写死 y 区间，改为在**整条菜单带**内扫描，命中哪里就点哪里；
原样候选全部不过阈时，才启用各自独立的白字文字候选。

- 统一扫描带 `LEFT_MENU_REGION = (0, 250, 240, 700)`，覆盖 y=250~950 的有限区域，
  同时用于 `lobby_shop_entry` / `lobby_sanctuary` / `lobby_activity`；
- `lobby_shop_entry` 保留干净版与带角标版两张原样模板（阈值 0.82 不动），新增
  `lobby_shop_entry_text_white`（只含「秘密商店」四字 / `MATCH_MODE_WHITE_MASK` / 0.90）；
- `lobby_sanctuary` 保留原文字模板（0.82 不动），新增 `lobby_sanctuary_text_white`
  （只含「圣域」二字 / 白掩膜 / 0.90）；
- `lobby_activity` 保留前两张原样模板，新增按当前真机帧重裁的 `lobby_activity_alt.png`
  （原样 / 0.82），处理上移后的图标与角标形态；
- 白字候选只在原样候选全部不过阈时才试，**不拿白字分与原样分比高低**，沿用
  `decisions/0012` 的「同锚点新增候选、不改既有口径与阈值」原则；
- 三颗入口的点击点取匹配中心，不写死坐标；菜单项增减导致的位置变化由扫描带吸收。

新候选入网前的实测：
- 两种账号布局的 512 张夹具排他审计，阈值 0.90 下白字候选过线的 20/17 张全部是大厅页，
  `lobby_activity_alt` 在夹具库中 0 命中，负例 `arena_mode` / `story_stage` 均远低于线；
- 失败帧上新候选分别达到 shop 1.0000 / sanctuary 1.0000 / activity 1.0000，
  原账号布局上的老模板仍保持原有分数与点击点。

## 后果

收益：
- 账号缺少任意上游菜单项时，三颗入口都能按画面实际位置定位，不再随账号进度失败；
- 判据从「某个 y 坐标上的图标」变成「整条菜单带内的文字/图标」，与人眼找按钮的方式一致；
- 老账号布局继续由原模板命中，判定与点击点逐字节不变。

代价（**接受了**）：
- 搜索带比原来宽约 3 倍，每次匹配略慢；仍是有限的 240×700 区域，不是整屏扫描；
- 同一锚点多一张模板、多一次匹配，只在原样候选失败时才付这笔钱；
- 若游戏把菜单改成可滚动或移出左侧 240px，本方案仍会安全失败并留诊断帧，
  届时需在 `LEFT_MENU_REGION` 上继续扩展，而不能靠调阈值硬扛。

## 考虑过但被否掉的方案

| 方案 | 为什么没选 |
|---|---|
| 只把三颗入口的原区域各自向下/向上扩一点 | 仍绑在「当前账号菜单项数量」上，下次增减还要再改；不符合不写死坐标的原则 |
| 调低阈值让旧模板在新账号上过线 | 实测干净模板扩大区域后只有 0.6404，调到 0.60 会把别的页面冒牌放进来 |
| 每换一个账号补一张新模板 | 被动无限累积，且没有解决「位置可变」这个根因 |
| 用 OCR 读左侧文字 | 项目不引入 OCR；白字掩膜在 512 张夹具上已能覆盖两种账号布局与已见主题 |
| 改成固定坐标点击 | 菜单位置会随账号进度变化，固定坐标正是本次事故的来源 |

## 后续核查（2026-11-22 当晚）

当事帧（`lobby_menu_items_missing_20261121`）原抓取时**通道顺序是错的**：ADB 通道
拿到 BGR 却原样当 RGB 用，R/B 互换。截至今日本决策的结论逐条复核如下：

- **整列上移约 93px 的判断成立**，与通道无关。按正确通道重存后
  `lobby_shop_entry` 0.6434、`lobby_sanctuary` 0.7415，仍不过阈；
- 失败帧上三颗入口由候选兜住（shop 1.000 / sanctuary 1.000 / activity 1.000），
  修复通道后复测仍是 1.000 / 1.000 / 1.000；
- ⚠️ 唯一被推翻的是 `lobby_activity_alt.png` 的**颜色**：它裁自错乱帧，
  于是把灰色日历拍成了暖色。2026-11-22 已按修正后的帧重裁（避开左上 N 角标），
  全库 470 帧扫描中仅来源帧 ≥0.80。

一张按错误通道裁出来的橙版模板。
