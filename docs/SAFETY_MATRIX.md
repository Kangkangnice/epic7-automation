# 安全与支持证据矩阵

供路线开发和验收使用。用户可在[现状速查](STATUS.md)查看各路线的适用范围和实机验收概况。

## 二、通用护栏

- 改变页面或资源的动作按五段证据验收：来源进入、候选动作、来源退出、目标进入和业务完成。来源仍稳定时可按契约在限额内重试。来源消失、目标尚未稳定时等待。页面未知或证据冲突时保存诊断并安全停止。[页面转场契约](TRANSITION_CONTRACTS.md)
- 全黑帧只允许返回无动作或抛 `UnrecognizedScreen`。关键判据模板缺失时，装配即报错。资源路线加入 `RESOURCE_ROUTES` 后由公共用例验证这两项。页面互斥和相邻页冲突目前由各路线的反例覆盖。[跨路线安全用例](../tests/test_safety_fail_closed.py)
- 商店购买或刷新的同一事务仅提交一次，传送确认后单向推进到结果阶段。社区兑换和竞技场购旗回执不明时原地停止整轮，保留现场对账。刷书签会结束本路线并保存诊断，仍可能触发回大厅和后续任务，请立即点「安全停止」结束整轮，再核对余额和货架。[刷书签异常与收尾](maintenance/shop_refresh.md#异常与收尾)
- 冻结画面会让延迟输入落到下一页。月塔启用画面静止时不重试，远征待按路线确认是否启用。竞技场使用独立循环，仍需单独验证冻结帧下的重试行为。

## 三、证据采集与复核

- 每条新路线在危险动作表留一行，写明资源和不可逆边界、前置判据、回执及对应的护栏用例。
- 验收绑定路线、后端、游戏客户端及版本、待发布提交或工件和设置。记录相关账号状态、授权入口及环境。固定样本、干跑、实机闭环、重复运行和异常分支各凭对应证据确认。
- 危险动作提交前保留能同时确认意图、对象、数量、价格和可用控件的整帧。提交后保存真实回执、实际完成量、资源变化和合法终点。每日编排还需确认上下游衔接。干跑和现场日志仅记录实际覆盖范围。
- 一次独立启动只给一个结论，进程内多轮是业务量。先判越权、重复提交等不安全情况，再按首个故障、声明的提前停止条件及业务目标判定。异常后回到大厅仍保留原故障和已完成量。只读巡检单独核对实际读数。
- 支持声明由独立验收人核对原始材料，含危险动作前置帧、业务回执、资源对账和终点。原始截图与日志留在本地，公开记录使用脱敏结论及可追溯回归证据。[实机验证](howto/live_verification.md) · [路线开发与验收](howto/route_change.md)
