## 一、危险动作 × fail-closed 依据

「危险」的定义：花出去就回不来 —— 体力、天空石、金币、挑战券、英雄材料、传送、领取。

| 路线 | 危险动作 | 靠什么拦住误点 | 对应测试 |
|---|---|---|---|
| 英雄合成 | 融合（吃材料）、传送（不可逆） | 材料不可逆保护：材料卡被覆盖层盖住时宁可不点（`hero_synthesis.py` 三处显式判断）；SSS 优先，非 SSS 才刻印；传送前有独立确认页 | `test_hero_synthesis.py`、`test_hero_evidence.py` |
| 竞技场 | 买票（花天空石 / 友情点）、刷新对手、开战（耗券） | 无票判据（`no_ticket`）+ 买票弹窗识别后再决定；买票前有拦停点 | `test_epic7_arena.py`、`test_arena_purchase_popup.py` |
| 刷书签 | 金币购买、天空石付费刷新 | 购买 / 刷新各有一道**单击闩锁**（没建立起来直接判失败，不重发）；价格与「已售」回执校验；同行购买约束 | `test_shop_refresh_*.py` |
| 远征 | 进入副本（耗体力）、招募 | 每个动作先确认来源页，目标页连续两帧才提交；海报耗尽走 `PostersExhausted`（退出码 2，不算失败） | `test_expedition_runner.py`、`test_expedition_resume.py` |
| 剧情 | 进关卡、快速战斗（耗体力） | 体力弹窗走共用 `stamina.next_stamina_decision`；叶子买到上限即 `StaminaExhausted` 干净收尾，不硬闯 | `test_epic7_story.py`、`test_ticket_exhaustion.py` |
| 狗粮 | 进关卡（耗体力） | 复用剧情那套体力判定；叶子按钮不可用即 `StaminaExhausted` | `test_epic7_fodder.py`、`test_fodder_runner.py` |
| 月塔 | 每层 15 体力 | **明令不补体力**：体力不够只识别、绝不点购买，走 `StaminaExhausted` | `test_epic7_tower.py` |
| 主线补星 `story_star` | 进关卡（耗体力） | 复用主线 `stamina.next_stamina_decision`；小节满星（绿勾）才不重打；动作总数 `_MAX_ACTIONS=200` 有界；战斗只在共享判据判不出且帧有效时用本路线 HUD 锚点补正，结算页 / 无效帧不放行；⚠️ **六章扫完收工 / 资源耗尽未真机验** | `test_story_star.py`、`test_safety_fail_closed.py` |

### 跨路线护栏（2026-11-09 新增）

上面每条各管自己的业务，但「认不出画面还敢点」是**跨路线**的通病，所以另有一份公共护栏：
[`tests/test_safety_fail_closed.py`](../tests/test_safety_fail_closed.py)。它只钉三种输入里的两种：

- **UNKNOWN（全黑帧）**：11 条会花资源的路线，要么返回 `None`、要么抛 `UnrecognizedScreen`，
  **不许**给出带坐标的动作。实测现状：10 条抛异常、英雄合成返回 `None`，全部合格。
- **关键模板缺失**：模板根换成空目录后，装配阶段必须抛 `FileNotFoundError`
  （而不是带着半套判据跑到真机上）。
- **判据冲突**（同一帧同时像两个页面）：**⚠️ 没有统一护栏** —— 各路线靠自己的
  「页面互斥 / 全负样本扫描」兜，见第三节的固定样本列。

加新路线时：往 `RESOURCE_ROUTES` 里加个名字，就自动被问一次「你认不出画面时会不会照样点」。

## 二、不可逆动作怎么防重复

场景：**动作已经成功，但回执没认出来**（转场动画慢 / 抓帧失败 / 目标页判据刚好不命中）。
这时如果主循环重发同一下点击，就等于点第二次 —— 传送第二个英雄、买第二份商品。

现役三道防线，各自解决一类：

| 防线 | 拦什么 | 代码位置 | 测试 |
|---|---|---|---|
| **事务闩锁** | 同一次购买 / 刷新里，确认键只允许按一次 | `shop_refresh.py::mark_purchase_confirm_clicked` / `mark_refresh_confirm_clicked`（`pending.confirm_clicked` 置位后一律返回 `False`） | `test_shop_refresh_runner.py` 两处「第二次返回假」的断言 |
| **阶段单向推进** | 传送确认后不再发确认动作 | `hero_synthesis.py::TransmitPhase`（`CONFIRMING → TRANSMITTED` 只走一次，回退需显式重置） | `test_hero_synthesis.py` 的传送阶段用例组 |
| **冻结不补点** | 画面完全不动时不重按同一坐标（那一下会被游戏攒着，等下一屏兑现） | `transactional_runner_base.py::_retry_block_reason` + `_RETRY_REQUIRES_MOTION` | `test_epic7_tower.py` 的「画面冻住只点一次」 |

⚠️ **第三道只对月塔开启**（`_RETRY_REQUIRES_MOTION = True`），远征与竞技场仍是默认放行。
这不是漏写 —— 2026-10-09 定这条时用户明确否掉了「一律禁止重试」（会把「真的没点到」也禁掉），
所以它按路线逐个开。**远征要不要开属于行为变更，等用户拍板**；
竞技场有自己的 `run()`，压根不走这道闸门。

### 这张表暴露的三类缺口

1. **「干跑」几乎全空** —— 除成就外没有一条路线留下过 `--live` 之前的干跑记录。
   干跑本身很便宜（不点鼠标、只回答「这一步会点哪」），缺的是**习惯**不是能力。
2. **「2 轮」大面积空缺** —— 只有剧情、圣域、成就有第二轮以上的记录。
   这一列的含义是「第一轮撞运气、第二轮证明可重复」，缺它等于只跑通过一次。
3. **异常恢复看着最满，但那是假的满** —— 打勾的多是「弹窗被守卫接住了」这类**单点**证据，
   不是「整条路线在异常后还能自己跑完」。

⚠️ 只有证据齐全（五列都不空）的组合才允许在 README 标记「支持」——
按现在的表，**没有一条路线够格**。这也是为什么 README 用的是「已实机跑通」而不是「支持」。

## 四、怎么更新这页

- 跑完一轮实机后，把「1 轮 / 2 轮」从 ⚠️ 改成 ✅，并在备注里写**日期 + 结果**；
- 新增路线时两节都要加行：第一节写它花不花东西、靠什么拦；第二节先把五列全填 ⚠️；
- 素材张数不要抄进来 —— 一律链 [`STATUS.md`](STATUS.md)；
- 这页由人维护，**没有机器门禁**。它的可信度取决于改它的人是否肯写实话。
