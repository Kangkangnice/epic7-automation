# 想法池（随手记 · 未排期）

这个是**想法的暂存区**：项目平时开发时突然冒出来的念头，先记在这里，免得转头就忘。
想动手的时候，从下面挑一条就行。

它不是任务清单：**不排期、不承诺一定做、也不代表已经评估过能不能做**。
真要开工时，先把那条下面的「开工前要定的问题」想清楚，再按
[EXTENDING.md](EXTENDING.md) 走新增路线的流程；同时把这条从本页挪到
[TODO.md](TODO.md)（已经确认要做的工程待办）或 `docs/wip/`（正在做、还没做完的活）。
做完或决定不做了，也在这里标一句，别留悬案。

**和 [TODO.md](TODO.md) 的分工**：那边是**已经确认要做**的稳健性、转场、PC 迁移工程待办，
每条勾选前要满足它末尾的「待办完成定义」；这边只要求把想法说清楚，**没有验收要求**。

记一条的最小格式：标题 + 为什么会冒出这个想法 + 想做成什么样 +（可选）开工前要定的问题。
不写方案、不写排期、不写负责人。

## 1. 新增路线：主线补星

- **状态**：想法（2026-11-09 记）
- **为什么**：现在打主线是为了快速通关、拿成就、推进度；但主线关卡有星级要求，
  还有对应的完美奖励。推完进度之后，这些星往往没满，得回头补。
- **想做成什么样**：做一条自动化路线，专门把没满星的关卡补到满星，顺带把完美奖励拿到手；
  归到**按需**那一组（内容一直都在、跑不跑看当下需不需要，见
  [USER_GUIDE.md](USER_GUIDE.md)）。目前只能手工一关关补，很慢。
- **开工前要定的问题**（现在不拍板）：
  - 怎么判断「这一关没满星」，按什么顺序补（章节 / 关卡 / 星级从低到高）；
  - 补到什么程度算收工：全满、只补到够领完美奖励、还是由用户指定范围；
  - 完美奖励是路线自己领，还是只把关卡打完、留给人工领；
  - 能不能复用现有主线 `story` 的导航、队伍和战斗流程，不另起一套。
- **翻资料**：新增路线流程 [EXTENDING.md](EXTENDING.md)、
  主线手册 [maintenance/story.md](maintenance/story.md)、
  分组口径 [maintenance/daily_tasks_grouping.md](maintenance/daily_tasks_grouping.md)。

## 2. 复查文档治理的实际效果

- **状态**：想法（2026-11-09 记）
- **为什么**：2026-11-08 有个 Agent 做了文档治理、宣称完成；但「做完了」是它的说法，
  还没人复核过结果是不是真的对得上现在的项目。
- **想做成什么样**：**只做检查，不在这一条里改文档**。找时间过一遍，能确认的勾掉；
  发现问题先记下来，改不改、怎么改到时候单独定。
- **检查清单**（到时候逐条打勾）：
  - [ ] `docs/` 里现在到底有哪些文档，是不是都能从 [README.md](README.md) 点到、没有断链；
  - [ ] 每份文档还符不符合现状：有没有写着已经不存在的功能、路线、入口；
  - [ ] 有没有文档跟代码冲突（尤其路线名单、PC 放行名单、默认值、次数这类业务规则）；
  - [ ] 治理定下的规矩本身有没有在跑：STATUS 由代码生成、索引即白名单、
        决策记录带状态日期，这几道门禁实跑一遍；
  - [ ] 有没有「两份文档讲同一件事、说法还不一样」，以及该删没删的在制品。
- **已经撞见的一例（2026-11-09，当晚已修好）**：复审机制从「游标」换成
  「按本次改动即时判定」，但 [README.md](README.md) 一度还写着旧机制、链到已删的
  `doc-review-cursor.txt`，文档检查因此报错；当晚已随治理改动改对。
  留作以后复查的样本：重点看「机制换了、说明没换」这一类，而不是只查断链。
- **现成入口**：[README.md](README.md) 第五节「这套机制还在运转吗」、
  `python -m auto_game_unified.tools.doc_review`（复审游标）、
  治理定案 [decisions/0004](decisions/0004-four-channels-for-docs.md)。

## 3. 路线的自由度再高一点

- **状态**：想法（2026-11-09 记）
- **为什么**：现在几条路线基本是「勾上就按固定方式跑一遍」；只想做其中一部分，
  或者想避开某些会花资源的操作，只能不勾整条，颗粒度太粗。
- **想做成什么样**：给路线加一些可选开关，例如：
  - 主线：可以指定打哪些关卡 / 章节范围，而不是从头一路推到尾；
  - 竞技场：可以选择要不要花资源刷新对手，以及其它消耗类动作的开关；
  - 其它路线照这个思路再收集，不一次定完。
- **开工前要定的问题**（现在不拍板）：开关放界面还是放参数、默认值取什么、
  会不会跟现有的次数和业务规则打架 —— **默认行为必须保持现状，别顺手把规则改了**。
