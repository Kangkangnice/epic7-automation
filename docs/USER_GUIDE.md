# 使用手册

本手册面向日常运行和故障留证。默认支持基线是 Windows 上的雷电模拟器；`pc` 后端目前用于采集和开发验证，没有一条路线通过 PC 验收。

## 1. 安装与运行前检查

要求：

- Windows；
- Python 3.10 或更高版本；
- 已安装 `requirements.txt` 中的依赖；
- 模拟器中的《第七史诗》窗口标题为“第七史诗”；
- 游戏语言为简体中文（模板按中文界面采集，换语言会导致判定大面积失效）；
- 模板基准画面为 `1982 x 1132`，窗口宽高比、游戏 UI 和显示缩放没有在采集模板后改变；
- 模拟器窗口被其他窗口遮挡也可以；助手读的是窗口画面、点击走模拟器自己的输入通道，期间的鼠标可以照常用（建议不要最小化）。

建议从仓库父目录安装和启动：

```powershell
cd D:\AI\codex\auto_game
python -m pip install -r auto_game_unified\requirements.txt
python -m auto_game_unified.main --help
```

第一次运行或游戏更新后，先执行干跑。只有识别结果与当前页面一致时才进行一轮实跑。

## 2. 桌面界面（推荐）

先启动雷电模拟器并进入《第七史诗》，再从仓库父目录启动中文桌面界面：

```powershell
cd D:\AI\codex\auto_game
python -u -m auto_game_unified.desktop
```

桌面界面提供：环境检测、任务勾选（每条路线一行，勾选框 + 次数框）、开始任务/安全停止、实时日志、打开日志/诊断目录和一键导出诊断 ZIP。默认一条也不勾；勾选的先后就是执行顺序，界面用 ①②③ 标出。界面上**不再区分正式 / 实验**，启动前也没有「可能不稳定」的二次确认（2026-10-20 起：十五条路线均已实机验证）。英雄合成固定运行一轮，世界首领战固定每天 2 次（每日上限）——这两条的次数框置灰不可改，其余路线按默认次数预填、可自行调整（竞技场默认预填 10 次）。

进入界面后点击一次“检测环境”。检测通过后切换功能不会要求重复检测；点击“开始任务”时，助手会在后台自动快速复检模拟器和截图，并校验**所选每一条**路线的资源。复检失败时不会启动自动化。

当前推荐用**免安装版**：解压 ZIP、双击 `Epic7AutoAssistant.exe` 即可，不需要装 Python、不需要安装过程，删文件夹就算卸载（运行记录写在 `%LOCALAPPDATA%\Epic7AutoAssistant`，不在解压目录里）。桌面助手的界面上只有“模拟器（雷电）”一个后端，**日常就用它** —— PC 客户端只用于采集模板与开发验证，**十一条路线在 PC 上都没有验收过**（见 [自动化稳健性待办](TODO.md) 的 PC 迁移矩阵），所以它默认不露面：确实要采 PC 模板时，先设环境变量 `EPIC7_SHOW_PC_BACKEND=1` 再启动助手。开始按钮在环境检测通过前保持禁用。

英雄合成固定执行一轮完整扫描，世界首领战固定每天 2 次 —— 这两条的次数框置灰不可改；骑士团捐赠（每天一次）、迷宫强化石（每天一次）、圣域收菜（每天一次）、支线故事与月光剧场（一次跑到没有可打的为止）同样置灰。其余路线由用户填次数：刷书签可以填 `0`（只扫不刷新），别的路线必须是正整数。对刷书签填 `N`，会检查初始页面和 `N` 个刷新后页面，总计 `N + 1` 批；`N = 0` 就是只查初始页面这一批。

活动的起点是**人工停好的「选第一张卡」页**，助手不负责从大厅导航过去，也不会按返回键回大厅；请先把游戏推进到该页面再点开始。局内每轮只会滑动摇杆走位，遇到升级三选一就停下来选卡，选完继续；「确认」和「重新抽取」两颗按钮永不点击。

## 4. 选择要跑哪几条路线

**桌面助手是唯一的交互入口**（上一节），命令行编号菜单已经删除 —— 以后改菜单只需改一处。

在助手界面里：勾选要跑的路线、填次数（默认次数已经填好，有每日上限的置灰），**勾选的先后就是执行顺序**（界面上用 ①②③ 标出第几个跑）。一次勾多条时会按顺序串起来跑，两条之间先回家再进下一条；一条都不勾则无法开始。

路线按 **每日 / 按需 / 赛季 / 活动** 分成四栏：

- **每日**：几乎每天都要跑的（竞技场、刷书签、世界首领战、骑士团捐赠、迷宫强化石、圣域收菜、社区签到）。
- **按需**：内容一直都在、但跑不跑看当下需不需要（英雄合成、主线、狗粮、支线故事、月光剧场）。
- **赛季**：按赛季轮换（远征、月塔）。
- **活动**：限时活动，随活动开合出现（类幸存者小游戏）。

**每一栏的名字本身就是勾选框**：点一下就把这一栏全部勾上，再点一下就把这一栏全部取消，别的栏一条都不动。只想跑某一栏里的其中几条，就单独点那几条。

活动路线与其它路线互斥：勾它会清掉其他路线，勾其他路线也会清掉它（它的起点需要人工停在「选第一张卡」页，也不参与回家衔接）。

命令行仍然可以直接调用同一条通道，供开发调试与自动化脚本使用：

```powershell
cd D:\AI\codex\auto_game
# 不写 --daily-tasks 就是默认清单；写了就按写的顺序跑
python -u -m auto_game_unified.main --daily --daily-tasks story:2,arena:1 --live --confirm RUN
```

次数写法为 `路线:次数`，不写次数则用该路线的默认值。运行期间不要操作鼠标键盘或覆盖游戏窗口，随时可在助手界面点「安全停止」。

## 5. 干跑诊断

干跑只截图、识别并输出当前状态的第一步，不执行点击，也不需要 `--live`：

```powershell
cd D:\AI\codex\auto_game
python -u -m auto_game_unified.main --mode story
python -u -m auto_game_unified.main --mode arena
python -u -m auto_game_unified.main --mode expedition
python -u -m auto_game_unified.main --mode fodder
python -u -m auto_game_unified.main --mode hero_synthesis
python -u -m auto_game_unified.main --mode shop_refresh --max-cycles 1
```

`--start-state` 只用于离线/干跑诊断，必须是对应模式允许的状态。实跑时传入该参数会被拒绝。

竞技场、主线和远征实跑都不需要你告诉它「从第几步开始」：启动时会先看画面，停在半路就从那一步接着跑；停在别的页面就照旧一路返回大厅，而且每返回一页都会再检查一次，中途扫到可接力的画面就地接管。详见 README 的「开局接力」。

- **竞技场**：整轮六个环节除了局内都接得住 —— 竞技场模式选择 / 对手列表 / 对战详情 / 准备战斗 / 战斗结果页 / 结果确认中（段位提升弹窗）；停在局内也会把这一局监督完再继续（不会按 `Back`）。只有「买票弹窗压住的队伍页」不接力（认错会点到弹窗上），会走老流程。
- **主线**：关卡入口、队伍准备、助手选择、剧情播放、跳过确认、通关提示、额外奖励和各种结算页都接得住；停在局内也不会按 `Back`，直接把这一局交给战斗监督等结算。想让它从关卡入口老老实实重开，先把游戏切回大厅即可。
- **远征**：导航链的战斗菜单 / 赛季菜单 / 远征主页，以及通缉传单、难度确认、公开招募、队伍选择等业务页都接得住。

其余路线（狗粮 / 英雄合成 / 刷书签 / 活动挂机）的开局行为没变：一律受控回大厅后按原流程进入。

## 6. 模拟器前台实跑

实跑必须同时提供 `--live`、`--confirm RUN` 和正整数 `--max-cycles`。先从一轮开始：

```powershell
python -u -m auto_game_unified.main --mode story --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode arena --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode expedition --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode fodder --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode hero_synthesis --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode shop_refresh --window-backend emulator --max-cycles 1 --live --confirm RUN
```

一轮完整通过后，再增加 `--max-cycles`。不要用“连续点击了多次”判断完成轮次；程序只在对应业务闭环证据成立后计数。

模拟器战前页出现系统赠送的“快速战斗”时，不需要手动处理。主线、竞技场、远征和狗粮会先确认快速按钮与白底切换键，再切回普通战斗并继续。这条规则不分平台（平台上没有分叉），但 PC 侧没有实机验收过。

## 8. 运行期间如何判断是否正常

正常的动作日志应体现以下顺序：

```text
动作候选 → 执行点击 → 等待确认 → 转场确认 → 业务成功
```

点击后暂时没有反应时，程序应保留原目标进行受限重试；只有目标页面或业务结果证据出现后才会记录成功。动态立绘、呼吸动画和局部粒子变化不能单独证明英雄已经切换。

竞技场会在原页面连续存在时用同一坐标最多尝试四次；一旦确认原页面已经离开，就只等待目标页面，不再点击旧坐标。对手详情、队伍页、刷新后的安全列表和结算返回列表都需要连续两帧才能提交状态。

竞技场无论第一轮就没有旗帜，还是运行中途耗尽，都会在点击“战斗开始”后处理同一个购买弹窗。购买框出现第一帧时程序立即冻结背景“战斗开始”，连续两帧确认后才进入购买判断，不会透过半透明遮罩重复点击旧按钮。

竞技场旗帜不足时，只允许左侧已选中的 `100 友情点 → 5 旗帜`。程序不识别会变化的“持有”余额；右侧 `30 钻石 → 5` 永久禁止。合法弹窗证据不完整时会保存现场并按资源不足停止，不会猜测购买。

刷书签只识别誓约和神秘，友情书签、英雄、装备和其他商品全部忽略。顶部扫描完成后必须看到不同的列表指纹并重新稳定，才扫描底部；刷新确认框离开后还必须看到不同于刷新前的列表指纹，才提交 3 钻石和刷新次数。购买弹窗与原商品类型或视觉价格不一致时不会确认。购买确认和刷新确认均最多点击一次，回执不明确时保存来源、动态峰值和最终现场并停止。本轮日志分别统计初始/付费页面两种书签的购买次数、钻石和金币，不保存历史文件。

当前版本已经完成誓约与神秘的真实商品行、购买价格和购买后 `0/1` 已售槽位实证，两种购买事务均允许实跑。**默认次数是 `0`**：进店扫一遍、把当前货架（含游戏自己随时间刷出来的）想要的买掉，一次都不付费刷新 —— 0 次不花天空石。想顺带付费刷新就在次数框里填正数，首次建议先填 `1`，核对完整的顶部扫描、底部扫描、购买、刷新和最后一批扫描日志后，再提高次数。不能把业务预期价格直接当作视觉识别结果。

进入战斗后不需要等到我方获得行动回合。模拟器版会根据右上角“自动关闭”图标请求开启自动，右下角人物头像稳定出现后才确认成功。敌方连续行动或技能动画导致头像暂时不可见时，日志会记录“来源已离开、人物头像待确认”并继续等待，不会再因 15 秒内看不到我方技能而报错。

如果页面证据不足，正确行为是记录 `UNKNOWN`、保存诊断并安全停止，而不是继续猜测点击。详细判定规范见 [页面转场契约](TRANSITION_CONTRACTS.md)。

## 9. 停止、退出码与通知

- 按 `P`：用户手动停止，退出码 `130`；
- `0`：达到目标轮次；
- `1`：未知页面、转场超时或运行故障；
- `2`：允许的资源耗尽停止。

可选通知通过环境变量启用，没配置就安静跳过，挂了也不影响退出码。

QQ 机器人（官方开放平台 C2C 私聊；免费，需按 README「安卓结束通知（官方 QQ 机器人）」完成一次性注册与取 `user_openid`）：

```powershell
$env:EPIC7_QQBOT_APP_ID = "你的 AppID"
$env:EPIC7_QQBOT_CLIENT_SECRET = "你的 AppSecret"
$env:EPIC7_QQBOT_USER_OPENID = "你收到的 user_openid"
```

## 10. 日志与诊断文件

- 文件日志：`runtime_logs/epic7_<mode>.log`；
- 当前监控帧：`runtime_diagnostics/epic7_<mode>/current.png`；
- 失败诊断：`runtime_diagnostics/epic7_<mode>/` 下带时间和原因的截图；
- 离线回归样本：`tests/fixtures/`，这些文件属于测试证据，不要当作运行垃圾删除。

反馈故障时，请至少保留：完整错误前后日志、最终诊断截图、运行模式、窗口后端、当时肉眼看到的页面和是否发生过真实点击/消耗。

## 11. 常见问题

### 点击切换英雄后没有反应

先看日志是否出现“等待确认”和受限重试。如果日志直接写成功但页面没变，应保留完整日志和诊断；这是转场证据与日志语义需要审计的信号。不要连续手动点击干扰现场。

### 两个英雄副本长得完全一样

不能依赖立绘差异。识别应观察点击后的动态过程、中心选中框/列表状态以及切换完成后的稳定页面；动态区域只提供辅助证据，不能单独确认成功。

### 识别到 SSS 后为什么退出

SSS 表示目标英雄已经达到最高合成等级。正确业务分支是退出合成，并在后续页面对无用副本执行受保护的传送流程；材料选择前必须优先完成 SSS 安全判断。

### 游戏更新或分辨率改变后大量 UNKNOWN

停止实跑，先保存现场并执行干跑。按 [截图与模板采集](TEMPLATE_CAPTURE.md) 重新采集模板，为新页面补固定样本和回归测试，不要降低阈值后直接实跑。

### 战斗开始按钮变成快速战斗

这是系统赠送快速战斗次数覆盖了普通按钮。模拟器版会自动点击右侧切换键回到普通战斗；日志应依次出现 `switch-to-normal-battle`、普通战斗开始动作和战斗监管。若没有切换，保留当前截图与完整日志，不要手动连续点击。

### 通知失败但流程已经结束

通知属于附加能力，不参与业务成功判断。根据终端退出码和自动化日志判断流程结果，再单独处理通知侧的问题：QQ 机器人看 `EPIC7_QQBOT_APP_ID` / `EPIC7_QQBOT_CLIENT_SECRET` / `EPIC7_QQBOT_USER_OPENID` 是否配齐、机器人后台是否开启了主动推送能力、`user_openid` 是否仍是有效会话（需对方先给机器人发过消息）。

更多故障定位步骤见 [故障排查](TROUBLESHOOTING.md)，后续路线审计项见 [自动化稳健性待办](TODO.md)。

## 12. 安全边界

- 所有点击必须由当前截图中的预期页面和元素触发；
- 关键模板缺失、证据冲突或状态未知时危险动作失败关闭；
- 不确认资源类型和价格时不购买；
- 已确认的不可逆动作不因回执识别失败而盲目重复；
- 实机控制必须由用户明确授权，且游戏窗口保持前台；
- 修改识别逻辑前，先用现场截图建立可复现回归测试。
