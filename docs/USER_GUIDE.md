# 使用手册

本手册面向日常运行和故障留证。默认支持基线是 Windows 上的安卓模拟器；`pc` 后端已在多条路线上实跑通过，具体名单与凭据见 `desktop/catalog.PC_READY_ROUTES`（第 7 节）。

## 1. 安装与运行前检查

要求：

- Windows。源码运行使用 [README](../README.md) 的 Python 3.11 环境和依赖安装说明；
- 模拟器中的《第七史诗》窗口标题为“第七史诗”；
- 游戏语言为简体中文（模板按中文界面采集，换语言会导致判定大面积失效）；
- 模板基准画面为 `1982 x 1132`，窗口宽高比、游戏 UI 和显示缩放没有在采集模板后改变；
- 模拟器窗口被其他窗口遮挡也可以；助手读的是窗口画面、点击走模拟器自己的输入通道，期间的鼠标可以照常用（建议不要最小化）。

源码命令从 `auto_game_unified` 的父目录运行。以下示例的 `python` 指安装了项目依赖的 Python。

第一次运行或游戏更新后，先执行干跑。只有识别结果与当前页面一致时才进行一轮实跑。

## 2. 桌面界面（推荐）

先启动安卓模拟器并进入《第七史诗》，再从仓库父目录启动中文桌面界面：

```powershell
python -u -m auto_game_unified.desktop
```

界面左侧是四个入口，底部是「关于」：

- **每日任务** —— 勾路线、填次数、检测环境、开始 / 安全停止；
- **运行日志** —— 实时日志全文，运行异常需要留证时看这一页；
- **实用工具** —— 与路线无关的小工具，目前是**连点器**（见 2.1）；
- **次元探查** —— 内置的第三方代码直接跑「次元探查」，不是本助手的路线（见 2.2）。

2026-11-09 起只有这一套界面（Qt / Fluent）。旧的那套 Tk 界面已经删除，
不要再找「另一个入口 / 另一个图标」。

「每日任务」页提供：环境检测、任务勾选（每条路线一行，勾选框 + 次数框）、开始任务/安全停止、实时日志、导出诊断包。默认一条也不勾；勾选的先后就是执行顺序，界面用 ①②③ 标出。界面启动前会检查所选后端支持的路线，名单由[当前现状](STATUS.md)生成。英雄合成固定运行一轮，世界首领战固定每天 2 次（每日上限）——这两条的次数框置灰不可改，其余路线按默认次数预填、可自行调整（竞技场默认预填 10 次）。

进入界面后点击一次“检测环境”。检测通过后切换功能不会要求重复检测；点击“开始任务”时，助手会在后台自动快速复检模拟器和截图，并校验**所选每一条**路线的资源。复检失败时不会启动自动化。

**跑完自动关机**（2026-11-12，2026-11-14 修正）：适合「晚上挂着跑、跑完就睡觉」。开关在「开始任务」左边，**默认关闭，而且每次打开助手都会回到关闭** —— 关机是不可逆的，上次开着不该让下一次也开着。打开之后：

- 任务结束后**先请模拟器自己退出**（最多等 60 秒），退干净了才继续 —— 模拟器还开着就关电脑，它会被强行结束，第二天开机会进「启动修复」界面（2026-11-13、11-14 各发生过一次，日志见 `C:\Windows\System32\Logfiles\Srt\SrtTrail.txt`）；
- 模拟器退出后**倒计时 60 秒**才真的关，期间底部会出现「取消关机」，点一下就撤销；
- 模拟器 60 秒还不退，仍按原流程关机，日志会写明「本次可能不干净」；
- **自己点「安全停止」不触发**（说明人还在电脑前）；正常跑完、某条路线失败、资源耗尽都会触发；
- 排定之后又点「开始任务」会自动撤销，避免下一轮跑到一半被关掉；正在关模拟器那几十秒里点「开始任务」会被拦下并说明原因。

**跑完看「运行结果」卡**（2026-11-12，2026-11-13 改为说明体）：一张卡上先给总账（`任务 8 项 · 完成 7 项 · 无剩余内容 1 项 · 总用时 18 分 40 秒`），下面一条路线一行，写清**做了什么 · 做了多少 · 用了多久**，失败那条再接一句人能读懂的失败原因。例如「刷书签 · 完成 · 1/1 轮 · 购入 5 件（誓约 3 / 神秘 2 / 友情 0）｜刷新 3 次 · 钻石 240 · 1 分 12 秒」「竞技场 · 完成 · 10/10 轮 · 玩家对战 · 胜 7 / 负 3 · 6 分 05 秒」（结算日只能打 NPC 时会写「NPC 对战」）。这张卡**报收获，只额外报刷新花掉的钻石**（其余金币收支看日志）；竞技场认不出胜负时那一局单列「未知」，不当成输，也不输出推算的数值 —— 那几条没有累计计数的路线（圣域收菜、骑士团捐赠）只报「精灵之森三行产出与照料均已处理」。结果会存进会话存档，关掉助手再打开仍看得到上次那一条。

每日任务最末尾还会**额外走一趟支线故事**，把这一期的刷新倒计时读下来（不打图、不消耗次数），显示在悬浮便签的待办下面那一行，例如「支线刷新：剩余 13 天 11 小时（11-12 23:41 读）」。同一趟还会**读取月光剧场入口卡左上角有没有绿色 F**——有就写「｜月光剧场免费已更新」，没有就写「｜月光剧场免费已用」，两句都挨在倒计时后面；它只站在支线故事页上看，**不会进剧场**。读不到就是「这次没读到」，**不算这一轮失败**。

如果对应版本的 GitHub Release 提供免安装 ZIP，解压并双击 `ArkyAssistant.exe`。运行记录写在 `%LOCALAPPDATA%\ArkyAssistant`。源码启动步骤见 [README](../README.md)。桌面助手的界面上有两个后端：**“安卓模拟器”日常就用它**；“PC 客户端”2026-11-01 起重新露面，但**只有已放行的路线才让在界面跑**（现行条数与名单见 [STATUS.md](STATUS.md) 第一节、本手册第 7 节，唯一出处是 `desktop/catalog.PC_READY_ROUTES`；勾到未在该后端放行的路线只跳过那一条，其余照跑，日志会说明）。其余路线仍按 [PC 客户端接入指南](PC_TEMPLATE_MIGRATION.md) 逐条验收；开发验证不受这层限制，用命令行 `--window-backend pc`。开始按钮在环境检测通过前保持禁用。

### 2.1 实用工具：连点器

**它做什么**：在指定坐标按固定间隔左键单击，直到手动停止。
它不识别画面、不判断点到什么、不做事后检查，点击落点完全由所选坐标决定。

**怎么开**：

1. 把鼠标移到要点的位置（比如结算页的「确认」、批量领取的按钮）；
2. 点「拾取位置」，倒计时 3 秒结束时记下光标所在的点。也可以直接填 X / Y；
3. 填间隔（毫秒，最小 50，默认 500）；
4. 点「开始连点」。

**怎么停**：

- **按 P**（随时有效，鼠标被按在目标点上时这是唯一不靠鼠标的出口）；
- 或者把鼠标抢回来点界面上的「停止」。注意：抢回鼠标后，下一次点击会把光标移回目标点，
  因此优先用 P 键停止。

**几条要提前知道的**：

- 运行期间鼠标会被固定在目标点，无法同时进行其他鼠标操作；
- P 是普通字母键，不会被程序独占：连点期间游戏也会收到它；在其他窗口输入 P 同样会触发停止。
- 位置是**屏幕物理像素**。改了显示缩放、换了显示器、游戏窗口挪了位置，都要重新拾取；
- 它和「每日任务」**不能同时开**：两边都在发点击会互相干扰，界面会直接拦住并说明原因。


### 2.2 次元探查（可选源码集成）

本入口在源码环境中调用单独提供的第三方 E7auto。它单独启动和停止，每日任务使用自己的路线清单。标准发行包不包含该组件。

**怎么开**：在「次元探查」页选好**阶段**（1~5）、**阵容**（暗双子队 / 平民替换队）、
**完成轮数**，点「开始次元探查」。进度和它打出来的日志就显示在这一页，不用另开程序。

**怎么停**：点本页「停止」。它运行在同一个程序里，**关闭主窗口会一并结束该流程**（界面会拦住并提醒）。

**几条要提前知道的**：

- **只支持 PC 客户端**：STOVE / Steam 版《第七史诗》（窗口标题「第七史诗」、进程 `EpicSeven.exe`）。
  模拟器里的游戏画面它认不出（UI 布局与字体渲染不同，实测入口模板结构分只有 0.51，门槛 0.8），
  该流程不支持模拟器；
- 它和「每日任务」「连点器」三者**不能同时开**：两套点击会抢同一个游戏窗口，界面会直接拦住并说明原因；
- 它开跑会**自动放弃未完成的旧探查**并结算该半局，开始前不要保留未完成探查；
- 它会自己调整游戏窗口大小；下次开跑本助手会自动改回，不用手动还原；
- 阶段和阵容是它原样带过来的固定配置：账号缺对应英雄、目标阶段没解锁、或遇到没登记的内容，
  它会停下来并在本页写明停止原因；
- 需要相应窗口权限。源码集成从工作区根下的 `vendor/e7auto/` 读取单独取得的组件及配置。

| 补星、狗粮、世界首领、支线、月塔 | 使用生命之叶 | 使用 / 不使用 | 使用 |
| 补星、狗粮、世界首领、支线、月塔 | 生命之叶使用上限 | 0–99 片（0 表示不限） | 不限 |
| 刷书签 | 购买友情点数 | 购买 / 不购买 | 购买 |
| 刷书签 | 友情点数购买上限 | 0–99 个 | 10 个 |
| 迷宫 | 购买友情点数 | 购买 / 不购买 | 购买 |
| 社区签到 | 兑换行动力 | 兑换 / 不兑换 | 兑换 |
| 社区签到 | 兑换强化石 | 兑换 / 不兑换 | 兑换 |

对手偏好按对手行上显示的积分挑选；积分读不出时本轮不启用，按原顺序挑选并在日志写明。英雄名单按图鉴头像识别对手队伍，只有库内已收录的英雄可选；名单内可按属性、职业、星级筛选，也可按名字搜索，未收录分类的英雄仍可按名字找到。同一名英雄只会在一边（勾了这头就自动从另一头移出）。优先名单只影响先后：含名单内英雄的对手优先开战（命中越多越靠前），一个都没有出现时按常规选择，并不是只打这些。只命中避战名单即跳过该场；两份名单都命中时按「两份名单都命中时」选项处理，不比命中数量。整页都被否掉时刷新若干页，仍无可用对手即停止。生命之叶使用上限填 0 表示不限；关闭「使用生命之叶」后，体力不足即停止。会消耗体力的路线共用同一个「行动力不足」弹窗，补充方式一致。游戏每日另有 30 次付费刷新上限，友情点旗帜每日仅可购买一次。刷新对手会中断连胜；天空石购旗仅推荐赛季结算前冲排名时开启。涉及付费货币的购买默认不执行，需明确开启并受次数上限约束；未确认资源类型和价格时不购买，证据不足时失败关闭，不可逆动作不因回执模糊重复点击，认不出页面时保存现场并停止。

## 4. 选择要跑哪几条路线

**桌面助手是唯一的交互入口**（上一节），命令行编号菜单已经删除 —— 以后改菜单只需改一处。

在助手界面里：勾选要跑的路线、填次数（默认次数已经填好，有每日上限的置灰），**勾选的先后就是执行顺序**（界面上用 ①②③ 标出第几个跑）。一次勾多条时会按顺序串起来跑，两条之间先回家再进下一条；一条都不勾则无法开始。次数最多可填 999（刷书签这类一轮只扫一次的路线，半天下来可能要跑上百轮）。

路线按 **每日 / 按需 / 赛季 / 活动** 分成四栏：

- **每日**：几乎每天都要跑的（竞技场、刷书签、世界首领战、骑士团捐赠、迷宫强化石、圣域收菜、社区签到、成就领取、宠物领养）。执行顺序见[现状速查](STATUS.md)第三节。
- **按需**：内容一直都在、但跑不跑看当下需不需要（英雄合成、主线、主线补星、狗粮、支线故事、月光剧场、企鹅批量购买）。
- **赛季**：按赛季轮换（远征、月塔）。
- **活动**：限时活动，随活动开合出现（活动小游戏、活动剧情）。

**每一栏的名字本身就是勾选框**：点一下把这一栏全部勾上，再点一下全部取消，其他栏保持不变。只想跑某一栏里的其中几条，就单独点那几条。

活动路线与其它路线互斥：勾它会清掉其他路线，勾其他路线也会清掉它（它的起点需要人工停在「选第一张卡」页，也不参与回家衔接）。

**后端不支持的路线只跳过它自己**：例如在模拟器下勾到「主线补星」（该路线当前只在 PC 客户端放行），
或在 PC 下勾到还没放行的路线，助手不会把整批拦下，而是跳过那一条、照常跑其余勾选，
并在日志里写明跳过了谁。**只有所选路线全都不支持时才会报错**并提示切换后端，
不会出现「什么都没跑却算完成」。「开始任务」前的模板复检也按同一份名单走，
被跳过的路线不会再拿「缺图」挡住其他路线。

命令行仍然可以直接调用同一条通道，供开发调试与自动化脚本使用：

```powershell
# 不写 --daily-tasks 就是默认清单；写了就按写的顺序跑
python -u -m auto_game_unified.main --daily --daily-tasks story:2,arena:1 --live --confirm RUN
```

次数写法为 `路线:次数`，不写次数则用该路线的默认值。运行期间不要操作鼠标键盘或覆盖游戏窗口，随时可在助手界面点「安全停止」。

### 4.1 开始任务后的便签窄条与悬浮球

点「开始任务」后，主窗口会收起来，屏幕上**直接展开那个窄条**（就是下面说的「今日游戏便签」），跑的时候能随时看进度和三行日志。想让它让位，点窄条右上角的「收起」，就变成一颗写着「进行中」的小球（运行中会轻轻呼吸；跑完或按 P 停止后主窗口回到「运行日志」页）。

- **球可以拖**：按住拖到合适的位置，松开即记住，下次打开仍在原处。
- **点一下球**又能展开窄条：上面是可编辑的一条今日游戏目标，中间是本次勾选的路线进度，下面是实时日志。旧版存档里的三条目标会合并成这一条，已填内容不会丢失。
  「已结束」表示该项已退出，具体业务结果见结果卡。跳过与未轮到的项目保持「待执行」。
- **窄条贴着球展开**，并一定会被夹在屏幕内；**不会自己收起来**，只有点「收起」才收。
- **想回主界面**点窄条上的「主界面」；回到主界面后，操作栏会出现「到悬浮球」，点它就能回到球（球还在原来的位置）。
- **运行中关窗口不会退出**：会把窗口收成球、任务继续跑；真要退出请先点「安全停止」。
- ⚠️ 运行中助手仍会移动真实鼠标去点游戏，编辑便签尽量挑路线之间的空档；要立刻停下按 P（和自动化的急停键是同一个）。

## 5. 干跑诊断

干跑只截图、识别并输出当前状态的第一步，不执行点击，也不需要 `--live`：

```powershell
python -u -m auto_game_unified.main --mode story
python -u -m auto_game_unified.main --mode arena
python -u -m auto_game_unified.main --mode expedition
python -u -m auto_game_unified.main --mode fodder
python -u -m auto_game_unified.main --mode hero_synthesis
python -u -m auto_game_unified.main --mode shop_refresh --max-cycles 1
```

`--start-state` 只用于离线/干跑诊断，必须是对应模式允许的状态。实跑时传入该参数会被拒绝。

启用开局接力后，程序会在已验证的画面接管，也会复查返回大厅途中的页面。各路线可接管的页面见[开局接力覆盖面](RESUME_COVERAGE.md)。

- **竞技场**：整轮六个环节除了局内都接得住 —— 竞技场模式选择 / 对手列表 / 对战详情 / 准备战斗 / 战斗结果页 / 结果确认中（段位提升弹窗）；停在局内也会把这一局监督完再继续（不会按 `Back`）。只有「买票弹窗压住的队伍页」不接力（认错会点到弹窗上），会走老流程。
- **主线**：关卡入口、队伍准备、助手选择、剧情播放、跳过确认、通关提示、额外奖励和各种结算页都接得住；停在局内也不会按 `Back`，直接把这一局交给战斗监督等结算。想让它从关卡入口老老实实重开，先把游戏切回大厅即可。
- **远征**：导航链的战斗菜单 / 赛季菜单 / 远征主页，以及通缉传单、难度确认、公开招募、队伍选择等业务页都接得住。

开局接力的覆盖面比上面举例的三条广：装了接力探针的路线，停在业务页会就地接管（不按 `Back`、不重新导航）；
没有探针的路线一律受控回大厅再进。**逐条状态看[现状速查](STATUS.md)的「开局接力」列**（该列读
`MODE_SPECS[...].resume_probe` 是否为 `None`；逐环节清单见[开局接力覆盖](RESUME_COVERAGE.md)）。

## 6. 模拟器前台实跑

实跑需要 `--live` 与 `--confirm RUN`。`--max-cycles` 对可调次数的路线必填正整数；次数框置灰的固定次数路线不传也会取默认值；刷书签允许填 `0`（只扫不刷新）；每日编排的次数写在 `--daily-tasks` 的 `路线:次数` 里。先从一轮开始：

```powershell
python -u -m auto_game_unified.main --mode story --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode arena --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode expedition --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode fodder --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode hero_synthesis --window-backend emulator --max-cycles 1 --live --confirm RUN
python -u -m auto_game_unified.main --mode shop_refresh --window-backend emulator --max-cycles 1 --live --confirm RUN
```

一轮完整通过后，再增加 `--max-cycles`。不要用“连续点击了多次”判断完成轮次；程序只在对应业务闭环证据成立后计数。

模拟器战前页出现系统赠送的“快速战斗”时，不需要手动处理。主线、竞技场、远征和狗粮会先确认快速按钮与白底切换键，再切回普通战斗并继续。这条规则不分平台（平台上没有分叉），PC 上同样生效。

## 7. PC 后端

`--window-backend pc` 负责客户区校准、窗口截图和输入适配。
PC 默认后台点击，滑动、滚轮和 ESC 会用前台输入。已放行的路线使用相同的业务入口，
生产模板解析仍支持已有 PC 覆盖。窗口、采集和共享迁移规范见 [PC 接入指南](PC_TEMPLATE_MIGRATION.md)。

**哪些路线能在 PC 上跑，以 `desktop/catalog.PC_READY_ROUTES` 为准** —— 名单旁边逐条写了
实跑凭据和遗留问题。**现行条数与名单看 [STATUS.md](STATUS.md) 第一节**（唯一出处是
`desktop/catalog.PC_READY_ROUTES`；本手册不写死会漂移的数字）。界面上勾到没放行 / 只有 PC
素材的路线只跳过那一条、其余照跑（日志会说明），全不可用才报错；命令行
`--window-backend pc` 不受这层限制，那是开发验证用的。

⚠️ 两条注意事项：

- **滑动**：PC 的滑动是 `SendInput` 按下 → 分步移动 → 抬起。刷书签、骑士团捐赠、迷宫强化石
  三条已在 PC 客户端实机跑通（日志合计数千次动作，2026-11 记录），可用。`duration` 的时长语义
  标定在 adb `input swipe` 上，幸存者与主线补星换到 PC 后尚未复验。
- **认不出的页**：停止任务，按[排错手册](TROUBLESHOOTING.md)留存本机诊断。
  开发者按[PC 接入指南](PC_TEMPLATE_MIGRATION.md)核对截图口径、适配器和公共识别。

只在采集/验证场景使用 PC 干跑：

```powershell
python -u -m auto_game_unified.main --mode story --window-backend pc
python -u -m auto_game_unified.main --mode hero_synthesis --window-backend pc
```

候选模板不能代替真实 PC 截图证据。

## 8. 运行期间如何判断是否正常

正常的动作日志应体现以下顺序：

```text
动作候选 → 执行点击 → 等待确认 → 转场确认 → 业务成功
```

点击后暂时没有反应时，程序应保留原目标进行受限重试；只有目标页面或业务结果证据出现后才会记录成功。动态立绘、呼吸动画和局部粒子变化不能单独证明英雄已经切换。

竞技场会在原页面连续存在时用同一坐标最多尝试四次；一旦确认原页面已经离开，就只等待目标页面，不再点击旧坐标。对手详情、队伍页、刷新后的安全列表和结算返回列表都需要连续两帧才能提交状态。

竞技场无论第一轮就没有旗帜，还是运行中途耗尽，都会在点击“战斗开始”后处理同一个购买弹窗。购买框出现第一帧时程序立即冻结背景“战斗开始”，连续两帧确认后才进入购买判断，不会透过半透明遮罩重复点击旧按钮。

竞技场旗帜不足时，仅购入左侧已选中的 `100 友情点 → 5 旗帜` 报价，一次运行只提交一次。购买后弹窗未关闭只表示回执未明，程序停下保留现场等待对账，不重复提交、不点取消，也不按资源耗尽收工。天空石购旗与金币刷新暂不支持：两份报价与选中态素材在模拟器和 PC 均缺失，开启后按证据不足安全停止。程序不识别会变化的“持有”余额。

刷书签识别誓约、神秘与友情点三类商品，按游戏内固定标价扣**金币**；友情书签、英雄、装备和其他商品忽略。次数填 `0` 只关闭付费刷新，首屏仍会买。顶部扫描完成后必须看到不同的列表指纹并重新稳定，才扫描底部；刷新确认框离开后还必须看到不同于刷新前的列表指纹，才提交 3 钻石和刷新次数。购买弹窗与原商品类型或视觉价格不一致时不会确认。购买确认和刷新确认均最多点击一次，回执不明确时保存来源、动态峰值和最终现场并停止。本轮日志分别统计初始/付费页面两种书签的购买次数、钻石和金币，不保存历史文件。

当前版本已经完成誓约与神秘的真实商品行、购买价格和购买后 `0/1` 已售槽位实证，两种购买事务均允许实跑。**默认次数是 `0`**：进店扫一遍、把当前货架（含游戏自己随时间刷出来的）想要的买掉，一次都不付费刷新 —— 0 次不花天空石。想顺带付费刷新就在次数框里填正数，首次建议先填 `1`，核对完整的顶部扫描、底部扫描、购买、刷新和最后一批扫描日志后，再提高次数。不能把业务预期价格直接当作视觉识别结果。

进入战斗后不需要等到我方获得行动回合。模拟器版会根据右上角“自动关闭”图标请求开启自动，右下角人物头像稳定出现后才确认成功。敌方连续行动或技能动画导致头像暂时不可见时，日志会记录“来源已离开、人物头像待确认”并继续等待，不会再因 15 秒内看不到我方技能而报错。

如果页面证据不足，正确行为是记录 `UNKNOWN`、保存诊断并安全停止，而不是继续猜测点击。详细判定规范见 [页面转场契约](TRANSITION_CONTRACTS.md)。

## 9. 停止、退出码与通知

- 按 `P`：用户手动停止，退出码 `130`；
- `0`：达到目标轮次；
- `1`：未知页面、转场超时或运行故障；
- `2`：允许的资源耗尽停止。

业务完成后若回首页未得到确认，命令行和每日任务结果会显示「收尾待确认」，并保留已经确认的结果。
如果刚执行了购买、制作或领取，先核对游戏里的实际结果，再决定是否重跑。

可选通知通过环境变量启用，没配置就安静跳过，挂了也不影响退出码。

在 [QQ 开放平台](https://q.qq.com)创建机器人并取得 AppID 与 AppSecret。由收通知的用户先给机器人发送一条私聊消息，
从机器人收到的 `C2C_MESSAGE_CREATE` 事件读取该用户的 OpenID，用于下面的 `USER_OPENID`。
主动消息的权限和接收设置以[腾讯接口文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)为准。

设置变量后从同一个 PowerShell 启动助手，或写入当前 Windows 用户的环境变量后重新打开助手。

```powershell
$env:EPIC7_QQBOT_APP_ID = "你的 AppID"
$env:EPIC7_QQBOT_CLIENT_SECRET = "你的 AppSecret"
$env:EPIC7_QQBOT_USER_OPENID = "你收到的 user_openid"
# 可选：$env:EPIC7_QQBOT_BASE_URL = "https://sandbox.api.sgroup.qq.com"  # 联调用沙箱，默认正式环境
```

把 AppID、AppSecret 和 OpenID 保存在本机。发送失败时根据通知日志和 QQ 平台配置排查，自动化结果和退出码仍反映游戏任务。

## 10. 日志与诊断文件

- 文件日志：`runtime_logs/epic7_<mode>.log`；
- 当前监控帧：`runtime_diagnostics/epic7_<mode>/current.png`；
- 失败诊断：`runtime_diagnostics/epic7_<mode>/` 下带时间和原因的截图；
- 离线回归样本：`tests/fixtures/`，这些文件属于测试证据，不要当作运行垃圾删除。

反馈故障时，请至少保留：完整错误前后日志、最终诊断截图、运行模式、窗口后端、当时肉眼看到的页面和是否发生过真实点击/消耗。

## 11. 常见问题

### 点击切换英雄后没有反应

先看日志是否出现“等待确认”和受限重试。如果日志直接写成功但页面没变，应保留完整日志和诊断；这是转场证据与日志语义需要审计的信号。不要连续手动点击干扰现场。

### 两个英雄副本长得完全一样

不能依赖立绘差异。识别应观察点击后的动态过程、中心选中框/列表状态以及切换完成后的稳定页面；动态区域只提供辅助证据，不能单独确认成功。

### 识别到 SSS 后为什么退出

SSS 表示目标英雄已经达到最高合成等级。正确业务分支是退出合成，并在后续页面对无用副本执行受保护的传送流程；材料选择前必须优先完成 SSS 安全判断。

### 游戏更新或分辨率改变后大量 UNKNOWN

停止实跑，先保存现场并执行干跑。按 [截图与模板采集](TEMPLATE_CAPTURE.md) 重新采集模板，为新页面补固定样本和回归测试，不要降低阈值后直接实跑。

### 战斗开始按钮变成快速战斗

这是系统赠送快速战斗次数覆盖了普通按钮。模拟器版会自动点击右侧切换键回到普通战斗；日志应依次出现 `switch-to-normal-battle`、普通战斗开始动作和战斗监管。若没有切换，保留当前截图与完整日志，不要手动连续点击。

### 通知失败但流程已经结束

通知属于附加能力，不参与业务成功判断。根据终端退出码和自动化日志判断流程结果，再单独处理通知侧的问题：QQ 机器人看 `EPIC7_QQBOT_APP_ID` / `EPIC7_QQBOT_CLIENT_SECRET` / `EPIC7_QQBOT_USER_OPENID` 是否配齐、机器人后台是否开启了主动推送能力、`user_openid` 是否仍是有效会话（需对方先给机器人发过消息）。

更多故障定位步骤见 [故障排查](TROUBLESHOOTING.md)，后续路线审计项见 [自动化稳健性待办](TODO.md)。

## 12. 安全边界

- 所有点击必须由当前截图中的预期页面和元素触发；
- 关键模板缺失、证据冲突或状态未知时危险动作失败关闭；
- 不确认资源类型和价格时不购买；
- 已确认的不可逆动作不因回执识别失败而盲目重复；
- 实机控制必须由用户明确授权；PC 客户端默认走后台通道（纯点击不抢前台，2026-11-09 起），滑动、拖拽、ESC 仍会短暂前置并在之后还原原窗口；也可在界面关掉「不占用前台」切回全程前台（见 [PC 客户端接入指南](PC_TEMPLATE_MIGRATION.md) §2.2）；
- 修改识别逻辑前，先用现场截图建立可复现回归测试。
