# 竞品功能全景与差距对照（开发新路线前必读）

> 数据来源：`script_RWLC.lua`（2114 个 `zs_`/`dj_`/`hs_` 函数）、20 个内嵌界面定义
> （405 个参数）、主插件 4901 条明文。**本文所有数字都是脚本统计出来的，不是估的。**
> 复现方法见 §6。

## 0. 这份文档解决什么问题

过去判断「某功能要不要做」靠印象、靠游戏截图，已经错过两次：

| 错误 | 当时依据 | 实际情况 |
|---|---|---|
| 以为竞品做了征召 / 世界竞技场 | `arena_mode.png` 页面上有三个卡片 | **征召 0 实现**；世界竞技场只有一个**从未被读取的死开关** |
| 以为竞品在「每日领取世界竞技场」 | 参数名 `领取_世界竞技场` | 那个变量全文件只被**赋值**两次，没有任何地方读它 |

**规矩（写在这里，防止再犯）**：

1. 范围由**竞品代码**决定，不由游戏界面决定 —— 游戏里有的，脚本不一定做。
2. 判断一个功能存不存在，看**消费点**（谁读它、谁调它），不看变量名、不看参数名。
3. 引用结论必须能指到「哪个文件的哪一段」，指不到就标「待确认」。

## 0.1 ★ 第一原则：先查反编译产物，不许猜

**任何「竞品是怎么做的」结论，必须先在反编译产物里搜到对应代码；搜不到就写「未确认」，不许写推测。**

**这条规矩是被一次真实的翻车逼出来的（2026-10-22，竞技场「避开英雄」）**：

| 我做的 | 实际 |
|---|---|
| 假设它用**图片模板匹配** | 它用的是**找色**：`ddzs(区域, 颜色, 点阵, 0.9)` |
| 花两小时调 SIFT / SSIM / 模糊归一化 / 二维裁剪 | 数据就在 `竞技场数据初始化()` 里：**286 个英雄**，每个一组「基础色 + 编码点阵」 |
| 拿 `H.rc` 里 361 张 `英雄_*.png` 当识别模板 | 那 361 张**不参与识别**（用在木龙编队等别处） |

**资料一直都有，是没查。** 所以定成原则。

### 固定动作（按顺序，不许跳）

```
① 查明文 → e7out/mainplug_strings.tsv（8092 条，全部 OK）
             按关键词搜，拿到对应的 hex
② 拿 hex → 在 e7lua/plugin_E7_main.lua 里搜
             命中处就是「函数体」所在（控制流完整，只是函数名是 a[23] 这种索引）
③ 读函数体 → 它到底调什么？
             搜 ddzs / findPic / .png / ddzs9 这类关键字，一眼就能分出找色还是找图
④ 业务主体 → 直接读 e7lua/script_RWLC.lua（全明文，2129 个函数）
⑤ 落结论 → 必须指到「哪个文件、哪一段」；指不到 = 写「未确认」
```

### 禁止事项

- ❌ 从**游戏界面**有什么，推断脚本做了什么（游戏有征召/世界竞技场，脚本一个都没做）
- ❌ 从**参数名 / 界面文案**推断实现（`领取_世界竞技场` 那个变量从没被读过）
- ❌ **先假设一种技术路线，再花时间验证它**（最快掉坑的方式）
- ❌ 把「资源包里有什么」当成「代码用什么」（361 张图 vs 286 组颜色，两回事）

### 解密算法（别记错方向）

```
加密: in[i]  = (out[i] - 0x1F + i) & 0xFF
解密: out[i] = (in[i]  + 0x1F - i) & 0xFF
i 从 0 起、不回绕；中文按 UTF-8 字节计数（不是按字符）
```

⚠️ 曾经写成按字符索引，解出来全是乱码，误以为「找不到」。**索引必须是字节。**

## 4. 结论：差距分三类

**A. 整条路线缺（竞品有、我没有，8 条以上）**

按实现深度排：**讨伐 27 / 祭坛 26 / 深渊 16 / 星座 11 / 裂缝 13 / 次元 65 / 商人 23 / 宠物 53**
外加**背包清理（220 函数）、邮件（25）、召唤（11）**这几项系统功能（成就 32 已于 2026-11-08 补上 `achievement` 路线，不再算「整条路线缺」）。

**B. 我有但很浅（同一条路线，竞品参数 8~12 个，我 0 个）**

冒险、支线、竞技、远征、骑士团、圣域、迷宫、商店 —— 这 8 条是「已经能跑，但不可调」。

**C. 我有竞品没有**

`world_boss`（竞品并进骑团）、`hero_synthesis`（竞品在「升星」模块）、`community`。
这三条不用对照竞品，按自己的需求演进。

## 5. 开发一条新路线之前的固定动作

1. 在这份文档里找到对应模块，看清它的**函数密度和参数清单**。
2. 去 `RWLC.lua` 把那几个 `zs_`/`dj_`/`hs_` 读一遍（§6 有定位命令），确认：
   - 它到底做什么（不是名字写的什么）
   - 有没有前置条件（体力、票、次数上限）
   - 失败/中断怎么收尾
3. 回到本项目，对照 `docs/EXTENDING.md` 的四步登记，写清「我们做哪几条、明确不做什么」。
4. 参数直接照抄竞品的字段语义（`族_子项`），不要自己发明名字。

## 6. 复现本文数据（别凭印象）

```bash

python -c "

s = open('.reverse/work/e7lua/script_RWLC.lua', encoding='utf-8', errors='replace').read()
pat = re.compile(r'\[\"((?:zs|dj|hs)_([^\"]+))\"\]\s*=\s*function')
m = collections.defaultdict(collections.Counter)
for full, rest in pat.findall(s):
    m[rest.split('_', 1)[0]][full[:2]] += 1
for mod, c in sorted(m.items(), key=lambda kv: -sum(kv[1].values())):
    print(mod, dict(c), sum(c.values()))
"
```
