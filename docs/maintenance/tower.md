## 这条路线在游戏里干什么

每天从大厅进「战斗」选月塔，一层层往上打：选队伍、开打、打完在三个装置里挑一个、
看结算再进下一层，队伍与层数一路记住。每层要花体力，**明令不补体力**；打满最顶层、
弹出「征服欧多马顿塔」那一屏就是整个环节的最终终点，认出即收工回大厅，一个按钮都不点。
中途某一层打不过属于正常收工，不重打、不点「大厅」，收尾统一回家。

## 页面链路

```
大厅 → 赛季页 → 月塔主页 → 楼层列表 → 准备战斗 → 战斗 → 三选一装置页 → 结算页 →（下一层）准备战斗 …
                                                              └─ 最顶层：征服欧多马顿塔（终点，收工）
                                          └─ 打不过：FAILED 结算页（正常退出）
```

- 大厅到月塔主页走导航器判据；路线内是状态驱动、提交才前进、目标页连续稳定才算转场成功。
- 点击点一律用 `TowerStateMachine` 的 `_POINT_*` 常量，不靠 `match.center` —— 裁剪会带动点击点，**判据与点击点必须分离**。
- 征服屏、FAILED 屏与主页/楼层列表/准备战斗/战斗/三选一/结算各环节都能开局接力；唯一还缺「阶段选择」屏（每月首次进场弹一次，按游戏默认选中的阶段直接确认，等取到帧再补判据）。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **终点只认标题，不为「征服」另做按钮判据**：最顶层的「征服」按钮与普通层「下一层」是同一个绿色槽位、逐像素一致，**只有文字不同**；征服弹窗半透明、不遮这个按钮，同一枚模板会同时命中两屏，做了也没用，而两个文字点的是同一个坐标。⇒ 动作照旧走「下一层」，判据只加一条标题（全月塔分离度最干净的一条）；`RESULT` 分岔靠「点完之后落到哪」自己分，终点页排在准备战斗之前，**宁可早收工，不可把终点当下一层**。
- **认出终点抛异常，不返回空**：返回空只会让主循环空转到超时报假故障，而「打满了」是正常业务退出，走资源耗尽通道照常收尾回家。抛之前先复核标题，结论门槛要求连续稳定，单帧抖动不该宣布「打满了」。**别把这一屏当过场页点掉**：点「点击关闭」会回主页但进度已清空，再走既没业务又可能误开新一轮。
- **报「某判据失效」先怀疑自己的取图链路**：截图接口返回 RGB，直接按 BGR 写盘会红蓝对调，把暖色存成冷色，读回来就误判成「这一层是蓝光、判据失效」。⇒ 通用纪律：先问「X 真的不在，还是我没去看那一块 / 拿错了尺子」，第一嫌疑人是取图链路，不是游戏。
- **重试靠「画面冻没冻」判，不列动作名单、不赌时长**：右下角绿色按钮槽**转场后会换按钮**，基类「再按同一坐标」的前提不成立，重试那一下正好按在下一屏按钮上（把战斗点起来）。加大 settle 是拿固定值赌转场时长（随负载波动，赌不赢还拖慢真失效的发现），列「禁止重试名单」又会把「真的没点到」也禁掉（用户否掉）。用户拍板的口径是：**画面还在动 ⇒ 确实没生效 ⇒ 允许补点；画面完全冻结 ⇒ 游戏正忙 ⇒ 只等不补点**（补的那下会被攒着，等下一屏一次性兑现）。闸门由本路线一行声明开启，别的路线逐帧行为不变。
- **冻结判据是「逐字节相同」，不是「画面差多大」**：待机帧平均差很小会被整片判成冻住、判据恒真，而同一套算法跨页差很远，没有统一阈值；「平均差小」不等于没动（大量像素在变、只是幅度被摊薄）⇒ 必须问「有没有一个像素变过」。另要先分诊全黑帧（窗口被遮挡取不到画面），把「取不到」和「冻结」分开报，否则复盘会误判成「游戏在加载」。
- **护栏必须数点击次数**：只断言「settle 够大」是空护栏（当年加大后实跑照样重试）。反向验证要**成对**（判据恒真 / 恒假两个方向都要红，才算两头都钉住），且「变红」不等于「有效」，要先证明用例真跑起来了。曾加过一条「目标页特征出现就判源页不在」的**假防线**——拆掉后测试照样全绿，是零增量，已删除；**判据不许静默失效**，保留的只是「源页判据在目标页必须不过阈」这条前提护栏。
- **弱证据不许推翻强证据**：自动战斗状态里「底部四格底座颜色」（强）与右上角共享图标（弱）强弱悬殊；旧代码无条件信图标，图标是亮灰底裁的、叠在月塔深色书架背景上去均值后被吃掉，擦着阈值就点开关、把坐标弄丢。远征/竞技场亮灰背景能自愈、只有月塔炸，是同一个 bug 抄了三遍只有这里的背景让它掉进死区。⇒ 收口成一份共享 `resolve_auto_state()`：**图标只在布局看不出长相时才作数**，布局已给结论就不改判；过渡态兜底必须保留（否则「未知」不许点自动、战斗干等到超时）。「缺坐标」从一帧判死改成有界等待，等判据抖回来。补这条时踩过 `continue` 忙循环（sleep 在循环末尾、单测假时钟看不出来），改用 if/else 并加一条源码结构护栏。
- **赛季页判据不许塞会变内容**：曾把「远征队」三字当第三个锚点，随赛季换内容就整页认不出，月塔连自己一行代码都没跑到（根因在导航器不在本路线，详见 [expedition.md](expedition.md) 赛季页判据节）。
- **半透明遮罩会让底页判据继续成立，是「少了一个页面」不是「判据不灵敏」**：战力差「战斗指南」弹窗盖在准备战斗页上，底下「战斗开始 / 准备战斗」照旧命中 ⇒ 状态永远停在准备战斗、每帧都点被弹窗压住的位置。⇒ 按**弹窗标题**新增一页（复用主线同款标题模板，同一后端同一渲染），准备战斗分支先认弹窗、命中就发确认；这条动作的「动作来源是否还在」按弹窗判、不按准备战斗页判（否则弹窗关掉后底下仍是准备战斗页会被当成没点动反复重试）；落点写成「战斗 / 准备战斗」两个，退回准备战斗页下一帧重新判，不空等超时。主线那套要「标题 + 不再显示勾选」两个锚点，本弹窗没有勾选项、套上去恒假 ⇒ 只能按标题判。「确认重置阶段」与它同布局同位置，但**两个业务常量分开写**，将来挪一个不该连带另一个。
- **打不过 = 正常业务退出，不是故障**：FAILED 结算页上「战斗画面 / 三选一」都不成立，监督等不到「打完」就报假故障。⇒ FAILED 页并入「打完」判据、三选一分支与战斗分支都先判它、并显式加进开局接力（人停 FAILED 屏启动时直接收工，否则会回大厅重进塔重打同一层再输一遍）。判据本体早就在库、异常类也备好，缺的是接线。语义（用户口径）：**打不过 ≠ 打满**——打满是完成、打不过是队伍强度不够，但对主循环都是正常业务退出，不许报成故障；不点「大厅」、不重打。
- **PC 差异只补图、尺寸漂移靠缩放兜底**：字形不同按 `templates/<路线>/pc/` 分层回落补同名覆盖图，阈值与业务代码一行不动；「打完」判据要求「决定装置」与提示语同时命中，其中一张没补图就永远看不到打完了。夹具按「模拟器基线」与「PC」分两个目录放，别把同一页的另一平台渲染混进基线目录靠放宽门槛过测试；按钮「选中 / 未选中」两态不必担心，归一化相关会把整体亮度差抹掉。PC 两次启动之间还会把同一套 UI 画小一点，相关匹配不归一化尺度，而同一颗按钮一帧要原尺寸、另一帧要缩一点，**没有任何单一尺寸能同时服务两档** ⇒ 登记进 `core/matcher.py` 的缩放兜底名单，别因为「现在过了」把它们删掉。

## 危险边界

- **明令不补体力**：每层花体力，体力不够不购买、不补充，这是用户拍板的口径，不许加补体力的动作。
- **打满即收工（用户拍板：打满最顶层 = 征服欧多马顿塔 = 最终终点）**：认出征服屏一个按钮都不点；具体层数属现行事实，见 [STATUS.md](../STATUS.md)。
- **打不过不重打、不点「大厅」**：重打只会再输一遍，收尾由基类统一回家；正常收工与异常退出的收尾路径不同，别混。
- **购买类弹窗一律只点取消**（战力差「确认」是允许点「确认」开打，与购买无关）；全局弹窗接触点见 [ARCHITECTURE.md](../ARCHITECTURE.md)「全局弹窗守卫」，全局危险动作与拦截机制见 [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
- 认不出 / 超时 / 资源耗尽 → 安全停止留证，不猜着继续点，见 [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- **通用教训**：判据要能证伪（拆掉它测试得变红，别留空护栏）、模板不含会变内容、先证伪自己的尺子再怀疑游戏、弱证据不许推翻强证据、反向验证要成对且先证明用例跑起来。
- **事故编号只作索引**：历史编号沿用下来、并不按时间对齐，还有插队的小节号；改文档时别为讲清顺序重排或复用编号，更别重复。
