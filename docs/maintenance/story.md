## 这条路线在游戏里干什么

推进剧情关卡：从大厅进主线、选关卡和队伍、打完结算，再进下一关或重打同一关，打满设定轮次后回大厅。战前剧情可以跳过，战斗走自动，每打一关消耗行动力（体力），见底会弹「行动力不足」。**想连打同一关时**游戏不给「下一关」，而是落在「无法前往下一个关卡」页，右下角「重新进行」是常态落点、不是异常分支。

## 页面链路

```
大厅 → 主线入口 → 关卡入口 → 助手选择 → 队伍准备 →（战前剧情 跳过 ⇄ 跳过确认）→ 战斗
     → 结算确认 → 通关提示 →（下一关入口 / 无法前往下一关 → 重新进行）→ …
```

- 战果链的点击可能接「战后过场」，跳完落到哪页取决于这一下战斗打没打完：打完给战果、没打完回战斗中、纯剧情回剧情播放。
- 「无法前往下一关」页左下是「离开 / 大厅」、右下是「重新进行」，两颗按钮都在右下角。
- 陌生的模态通知窗由**全局弹窗守卫**处理，不是主线状态机里的页面（理由见下节）。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **「重新进行」`retry_stage`**：只裁「重新进行」四个字、只框右下角那颗。**模板不含体力数字**（每局都变），区域**绝不放宽到「离开 / 大厅」**——那两颗与它同位置、语义完全相反，点错就退出关卡。反向护栏在 `tests/test_epic7_story.py`。
- **有路可走先走路（用户 2026-10-18 口径）**：「两个都遇到时先走『进行下一个任务』，没有它才点『重新进行』」。落地靠位置：`retry_stage` 判定放在 `next_action` 最后，`complete` / `next_stage` / `prepare_battle` 都在上面。两颗按钮同位置 ⇒ **造不出「同屏都有」的真实帧**，别拼合成图，那只会验出拼接 bug。
- **同一屏只记一局**：看到这一页 = 一局刚打完；点歪重试会再判同一屏，重复记账会把设定轮次提前收工；达到目标轮次时**在点击之前**停住，不点这一下（与狗粮「到目标轮数就停在这页」一致）。
- **契约漏落点会把动作整个吞掉**：转场逻辑里，新页面既不在 `target_pages`、又不等于来源页 ⇒ 动作被丢成 `None`，什么都不点、干等到超时。分诊口诀：日志见「转场超时 + 当前已确认页面=X」，先查上一个动作的 `target_pages` 有没有 X——有才是真没转场，没有就是契约漏了，**补声明即可，别动判据和阈值**。
- **跳过剧情不再穷举落点**：落点取决于战斗打没打完，穷举名单「加一格只挡今天这一格」已被证伪。改成结构性判据：页面离开来源页、且状态机算得出下一步 ⇒ 转场完成；**还停在原页一律不算**（fail-closed）。其它动作仍要求落点在名单里，见 [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- **PC 差异靠白掩膜、不补图**：关键判据全是白掩膜找形状（`find_prepare_battle_button` / `find_watch_story_button` / `find_story_skip_button` / `find_battle_guide_dont_show`），掩膜抹平底图 ⇒ 换渲染方式几乎不影响，业务代码零改动；认不出时退回「右下角按钮布局」的几何判据。**别为了更稳补 PC 图或调阈值**，那会把「手动 / 自动」判反。
- **低通口径被否决**：战力差距警告（「战斗指南」）双锚点要求同时命中，PC 上标题不过阈；换低通确实能过，但它丢掉颜色区分能力，月塔「战斗指南」的确认按钮会跟竞技场刷新的「确认」撞上（掩膜口径靠底色蓝 vs 绿分开，一模糊成两块白字）⇒ **拿排他余量换分数**，不能用。落法是自真机帧裁 PC 图，模拟器仍加载共享图，见 [PC_TEMPLATE_MIGRATION.md](../PC_TEMPLATE_MIGRATION.md)。
- **「行动力不足」的购买按钮**：弹窗底部改成三颗按钮后购买被挤到中间，旧搜索框够不到它。修的是**共享几何**（搜索框左扩），不是给 PC 开小灶——老夹具里还是两颗按钮，说明是游戏 UI 改版，模拟器同样会遇到。
- **模态弹窗盖在结算页上**：「给予协助的朋友」压着时，底下「确认」按钮仍露着并命中 ⇒ 页面判定看着正常、真点下去却打在弹窗死区，表现是「认得出这页、就是点不动」。这类**只能靠守卫先吃掉弹窗，别去调页面判据**。
- **全局通知窗（支线故事通知 / 获得奖励 / 解锁缘分 …）**：正文、插画、奖励图标、角色名每次都变 ⇒ 只锚固定标题 + 底部「点击关闭」，**两锚点同时命中才算**（「点击关闭」是通用控件，单锚会在别的领奖弹窗误命中）。标题是排他判据、只裁固定字；OK / 关闭只给点击点、单独绝不参与判定，缺一返回 `None` 不动手。守卫挂在 `runtime.capture` 上、每帧都过（含等待转场），放全局任何路线撞上都能自愈，放进单条路线其它路线照样卡住。
- **「解锁缘分」走 PC 单独留口（用户 2026-11-07 拍板）**：「所有改动只能在 PC 里面，不能影响模拟器，不能改公共地方」。落地为 `games/epic7/global_popups_pc.py` + `templates/global/pc/`，`games/epic7/global_popups.py` 一个触点没动，`main.py` 只加一处 PC 分支注入：给 `_find_popup` 套包装，先问「是不是解锁缘分」，不是就原样交回，**继承**连续帧确认、点击预算与熔断，不另起第二套循环。图只在 `global/pc/`：模拟器回落不到 ⇒ 加载全 `None` ⇒ 误调用也原样返回。
- **每局结算帧不再落盘（用户 2026-11-08 要求）**：旧做法每轮往 git 加一批全屏 PNG，是仓库变胖主因；现在只在认不出 / 超时 / 手动停止这类真故障时由 `Runtime.save_diagnostic` 存诊断帧。

⇒ 通用结论：**模板不含会变内容**（体力数字、角标、角色名、正文、奖励图标）；**判据要能证伪**（反例、双锚点缺一不认、把锚点塞回去反向护栏必须变红）；**陌生页要有逃生门**（守卫每帧自愈、认不出就安全停止留证，不猜着继续点）；**遮罩压上来先想它会不会反转判据**——补图只解决认不出，解决不了认出了错的结论。

## 危险边界

- **这条路线会花资源**：每打一关消耗行动力。体力见底弹「行动力不足」时，监督循环冻结背景点击、交还守卫处理，**不许连点「战斗开始」**。
- 「重新进行」与「离开 / 大厅」同位置、语义相反：靠「只裁四个字 + 只框右下角那颗」拦住误点；**不许**把 `retry_stage` 提到前进判据前面，**不许**把区域放大到包含左侧退出按钮，**不许**删掉第二张反例夹具（只剩一张就是「记住了一张图」）。
- 认不出 / 超时 / 目标不对 → 安全停止留证，不猜着继续点，见 [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- 轮次记账不许改成「看几帧灰 / 数红点」这类省事口径：主线按轮次记、同一屏只记一次。
- 全局危险动作与拦截机制见 [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
