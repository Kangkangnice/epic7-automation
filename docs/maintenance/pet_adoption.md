## 这条路线在游戏里干什么

每天领取一次免费宠物领养，然后进入宠物商店查看底部三种宠物用品。
宠物有增益效果，领养所得也是后续合成的材料，所以即使当天不买东西，
这一步也有收益；商店用品按周刷新，需要时可在路线设置里分别开启购入。

* **免费领养**：每天一次，不消耗任何资源。没有免费标记的领养一律不执行。
* **宠物商店用品**：一般饲料（一周 3 次）与两种宠物玩具（各一周 1 次）。
  两个购入开关默认都关闭，开启后只买可购买的行，冷却中或本周已购入的跳过。
  购入是**两下**：点该行的「购买」→ 弹「购买商品」确认框 → 点框里绿色的「购买」。
* **一轮范围**：进宠物小屋 → 处理领养段 → 进商店 → 滑到底确认三件用品 →
  （开着购入时按行各买一次）→ 收工回大厅。次数固定为 1，不提供调整。

⚠️ 默认不买时路线**照样进商店并滑到底**，这是业务流程，不是可以省掉的步骤。

## 亮态购入（2026-11-16 补采后接线）

商店用品当天全在冷却或本周已购入时，三行右边是一串灰字「N小时后可购买」；
额度刷新后那串灰字消失、右边出现「N/N + 绿色购买」。判「这一行能不能买」
就看**同一行里有没有那串灰字**，不去 OCR 读 `N/N`（数字每天变，模板不可靠）。

三条硬规矩，改之前先读：

1. **用商品名定位，不用「购买」两个字**：上面两行宠物领养券也有「购买」，
   拿它定位会点到 500 天空石的礼包。商品名（一般饲料 / 宠物玩具）只出现在用品行。
2. **同一行一轮只买一次**：饲料一周 3 次，买一次只是 `3/3 → 2/3`，那一行**仍旧是亮态**；
   不按行记账就会在同一行上反复回购，把一周额度一口气花光。玩具一周 1 次，
   买完那行自己变灰，另一行照常买 —— 所以上限落在「行」上，不落在「品类」上。
3. **确认框只认自己发起的那一单**：`pending_buy` 为空时出现「购买商品」框，
   说明是上次中断留下的，绿色「购买」与「取消」都不点，安全停止留证。

判据图：商品名两张（`supply_food_name` / `supply_toy_name`，正例 0.986、
跨页最高 0.337）；确认框的两颗**复用企鹅批量购买**那一套（同一个弹窗，
不复制副本）。确认框是全游戏通用的，所以页面组合要求「标题 + 购买两字 +
底页仍是宠物商店」（遮罩下商店标题 0.9998，别的路线底页不是商店）；
全库 439 张整帧里只有本路线自己那张弹窗帧被认成「购买确认」。

## 页面链路

```
大厅 → 右上角蓝四格 → 快捷菜单第 2 行中间「宠物小屋」
宠物小屋
  ├ 底部绿色「领养」→ 领养宠物弹窗
  │    ├ 免费态：左按钮带「免费」标记 → 点它 → 弹出领养结果 → 点掉 → 回小屋
  │    └ 已领完态：左按钮是紫色券图标 + 数量 → 点底部「点击关闭」→ 回小屋
  └ 左下蓝色「宠物商店」→ 商店
       ├ 上半部：宠物领养券（金币 / 天空石）→ 一律不买
       └ 滑到底：一般饲料 / 宠物玩具 / 宠物玩具
            └ 该行可购买且开关开着 → 购买 → 购买商品确认框 → 购买 → 回商店
```

领养弹窗是半透明遮罩，底下宠物小屋的元素仍然可见且能匹配到高分。
因此弹窗必须排在小屋之前判。

## 判据为什么这么设计

**核心分界是「免费」与「领养券」，不是按钮位置。** 两态的按钮都在左侧、
长得相近，但语义相反：一个不花资源，一个会消耗宠物领养券。所以：

* 「今日免费已用完」用**紫色券图标**作正向证据。它在真机上 1.0000，
  全库其它帧最高 0.1572，阈值 0.80 两侧余量都很厚。
* 免费态需要自己的「免费」标记模板。**绝不靠「没找到券图标」反推可领** ——
  那样一旦券图标因抗锯齿、遮罩或改版掉到阈值下，就会点到付费按钮上。
* 两态都认不出时抛 `UnrecognizedScreen` 安全停止并留证，**一个领养按钮都不点**。

其余几条：

* 页面标题只裁固定中文字，避开模拟器 FPS 数字、返回箭头与账号相关背景。
  宠物小屋背景因账号而异，不进模板。
* 快捷菜单入口只裁小房子图标本体，避开会出现的红点角标。
  第 4 行「英雄休息室」也是房子形状，靠搜索区域（只罩第 2 行那一格）
  与图标形状差异排除，实测那个只有 0.5610。
* 商店「小时后可购买」只取固定文字，避开左侧会变的小时数；
  三行用多目标匹配逐行检出，不靠单次最佳匹配。
* 「点击关闭」是全游戏通用控件，跨页同形分数可到 0.9971，
  所以只在已确认的领养弹窗里用它定位，不拿它判页。
* 动作出口验收全部登记（`target_pages` / `in_page_evidence`），
  走基类主循环的机器强制校验。

## 危险边界

| 动作 | 风险 | 拦截方式 |
|---|---|---|
| 点错领养按钮 | 消耗宠物领养券 | 只认正向判据；两态都不认得就安全停止，不猜坐标、不点任何领养按钮 |
| 宠物商店上半部「购买」 | 花金币 / 天空石买领养券 | 上半部只滑过，不产生任何点击；下滑动作的落点是左下空白说明区 |
| 底部用品「购买」 | 花红叶 / 天空石 | 三道：①开关默认关闭；②落点由**商品名**派生（券行没有用品名，误点不到礼包）；③同一行一轮只买一次，买完仍是亮态也不会回购 |
| 购买确认框的绿「购买」 | 真扣费、真减周额度 | 只认**自己发起**的那一单（`pending_buy` 为空时两颗按钮都不点），落点是「购买」两字的模板中心而不是写死坐标 |
| 领养结果弹窗 | 未采到，误点可能连点 | 当前不产生进入该页的点击；遇到未登记页面一律安全停止 |

安全铁律：认不出就留证停止，不把「没看见」当成「可以做」的理由。
离线护栏见 `tests/test_pet_adoption.py`，尤其是
`test_unknown_adopt_popup_stops_without_any_click`、
`test_paid_state_never_clicks_a_ticket_button` 与
`test_purchase_dialog_without_a_pending_buy_stops`。

## 已知缺口

1. **免费领养按钮 / 领养结果弹窗模板未采集**。采集当天免费额度已用完，
   画面停在付费态。当前路线能完整跑通「今日已领完」的一轮，
   但不会真的领到宠物。按用户 2026-11-15 的决定，这条已放进默认连打清单末尾，
   目的是次日实测采图：免费刷新当天会在领养弹窗安全停止，同时保存整屏诊断帧
   与证据包（含每个判据的真实分数），按帧补齐「免费」判据即可。
   单条失败不影响其余每日项（编排记为失败后继续下一条）。
   补图动作与接线位置写在 [`../wip/2026-11-15-pet-adoption.md`](../wip/2026-11-15-pet-adoption.md)
   （该交接单为在制品临时凭证，合并后删除；补图接线后以本手册与 TODO 为准）。
2. ~~**宠物用品「可购买」亮态未采集**~~ ← **2026-11-16 已补采并接线**：
   额度刷新当天采到亮态整帧、购买确认框、购买后回列表三帧，判据与动作都已登记，
   实机跑通「开框 → 确认 → 回列表 → 收工」（退出码 0，本轮购入一般饲料 1 件）。
   仍未验证的是「买完那一行转灰」的收尾形态（饲料一周 3 次，要买满 3 次才见灰）——
   不影响正确性：按行记账已经保证一轮不在同一行回购。
3. **PC 客户端未做**。只提供了模拟器素材，界面在 PC 后端按路线跳过本项，
   其余勾选照常执行。迁移矩阵见 [`TODO.md`](../TODO.md)。
4. **免费态未实机验证**。`--max-cycles 1` 完整链路、半路开局接力、
   `--max-cycles 2` 两轮连续均已实机跑通（2026-11-15，退出码 0、正常收尾回大厅），
   加上 2026-11-16 的购入闭环（退出码 0）—— 但走的都是「今日免费已用完」这一条路径。
   免费领养动作本身仍要等「免费」按钮模板采到后实机验证。
5. **停在购买确认框上开局不会接力**。对话框不在接力名单（它是扣费动作，接了等于
   替人确认）；这种开局会走「回大厅」那条路并在 45 秒后失败收场 —— 刻意 fail-closed，
   人工关掉弹窗再跑即可。
