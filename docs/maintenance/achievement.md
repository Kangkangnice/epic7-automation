## 这条路线在游戏里干什么

每天去成就页把能领的奖励领掉：从大厅快捷菜单进「成就」，逐个分类看「全部领取」亮不亮、有没有「持续效果上升」要处理，领完把奖励弹窗关掉、升级剧情跳过，每个分类都确认「全部领取灰 + 没有升级按钮」才收工、自己回大厅。这是**领取类路线**（用户口径「有就领、没有就走」），不花资源，排在每日清单最后。

## 页面链路

```
大厅 → 快捷菜单 →「成就」→ 成就页（左列逐个分类进入）
  ├「全部领取」绿 ⇒ 点 ⇒ 弹「获得成就奖励」⇒ 点「点击关闭」⇒ 一轮领不完就继续
  └ 按钮转灰后：左下「持续效果上升」⇒ 点 ⇒ 过剧情（跳过）⇒ 关掉升级弹窗
      ⇒ 回头再看还有没有新的可领
每个分类都确认「全部领取灰 + 没有升级按钮」⇒ 收工回大厅
```

- 右栏分类里只处理有奖励可领的那几个；**最后一个要解锁、领取形式也不同**，不在这条链里。
- 领完成就会让**别的**分类冒出角标，所以切分类优先挑「有角标、且不是刚点过的」那一个，收敛更快。
- 奖励 / 升级弹窗是半透明遮罩，由状态机**先于**成就页判定（理由见下节）。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **收工标志不是「红点都没了」（用户 2026-11-08 口径）**：红点只表示「这个分类有新达成的成就」，**不代表「没有奖励可领」**——现场帧反例是当前分类无红点、但「全部领取」亮着、列表里还写着「领取」。旧实现只对**当前停留**的分类查按钮颜色与升级按钮、其余只数红点 ⇒ 某分类红点先消失就永远不去看它的按钮。⇒ 改成「每个分类逐个走进去」，`_visited` 记录进去过的分类，红点只用来决定**先去哪个**、不参与收工判断。这一维排除的是「有红点 ≠ 有可领」。
- **要证伪的是「有没有进去看过」，不是「灰了几帧」**：一帧「全部领取灰 + 没有升级按钮」就把当前分类记进 `_visited`。早先「连续几帧灰 + 点同一个图标原地复核」在真机上走不通——点已选中的图标不产生画面变化，主循环等转场超时后反把整条路线判成完成。
- **同一帧只决策一次**：`_frame_key` 下采样算 MD5、`next_action` 缓存答案，主循环一轮问几次都不许推进 `_visited`（否则一帧内凑满分类、提前收工）。收工没有捷径：`_visited` 覆盖全部分类才 DONE，`switch-class` 每次只挑还没进去过的，绝不原地复核。
- **弹窗必须排在成就页前面判**：奖励弹窗是半透明遮罩，底下成就页元素照样高分命中（`page_title` / `claim_all`）。`_PAGES` 的顺序就是判定顺序，**不许为了好看把整页调到前面**，否则状态机会对着被盖住的按钮点。
- **「全部领取」亮 / 灰不能靠模板分**：两个状态形状完全相同、只差颜色与亮度，而 `TM_CCOEFF_NORMED` 是去均值归一化、本来就不看绝对亮度 ⇒ 互相命中。⇒ 用「按钮区里够绿够亮的像素占比」这一维区分；且搜索区必须**紧贴按钮**，放宽到把周围暗背景算进分母，亮态占比就掉下来、余量不够。
- **效果升级的剧情直接复用主线**：用户原话「跟主线里面那种剧情一模一样的，你就点击右上角的跳过」⇒ `build_achievement_templates` 直接读主线的跳过 / 跳过确认共享图，**不另存第二份**。
- **左列分类只按位置办事**：分类名（记忆之根管理院 / 元老院 …）**不参与识别**——换账号分类名可能不同，按名字认会白认不出，位置是稳定的。⇒ 靠「位置」这一维排除「同名不同账号」。
- **角标靠饱和度、不靠形状**：橙红实心圆按色相 / 饱和度 / 明度 / 面积 / 填充比判；卡片上的金色装饰饱和度不够，不会落进来。
- **快捷菜单入口被角标压着**：图标左上角常挂「橙红角标 + 数字」（未领成就数，天天在变），与图标本体重叠。解法与大厅蓝四格一致——**从角标下边缘起裁**，只取「图标下半 + 下面的『成就』二字」⇒ 角标免疫。**两个平台的角标下边缘位置不同、不能互相套用**，套错就把角标边缘裁进去、而里面的数字天天在变；验收要钉住「把角标抹掉仍命中」，证明模板真的不靠它。
- **页面身份与导航器共用同一张图**：导航器新增「成就页」，判据就是左上角「成就」两字——**与路线自己的 `page_title` 同一张图，不另存第二份**。弹窗开着时导航器也报「成就页」（遮罩透出标题），这对导航是好事；路线内部仍由状态机自己先判弹窗。
- **共享层放模拟器图、`pc/` 放覆盖**：这是 `games/epic7/template_paths.py` 的默认约定（共享图是模拟器口径、`pc/` 是覆盖）。最初共享层放的是 PC 图副本，因为 `build_navigation_templates` 是所有路线共享的装配、缺一张整个导航器就起不来——不能让一条「只有 PC 素材」的路线把别的路线一起搞挂；现在反过来对齐默认约定。**别把 PC 图放回共享层**，有反向用例钉着。
- **开局接力直接调状态机自己的 `observe_page`**：不另定阈值、不加新锚点；停在成就页时额外把 `entry="achievement"` 交还导航，省掉「回大厅再走一遍」那一趟。
- **量分是一次性探针，不是 `tools/audit_docs.py`**：后者查的是文档里引用的路径 / 符号是否存在，**与模板分数无关**（名字太容易混，写明）。裁图规矩必须遵守：紧裁目标控件、不含会变的数字 / 角标、正例近满且反例够低才算站得住。

⇒ 通用结论：**模板不含会变内容**（未领数字角标、分类名、奖励图标 / 正文）；**判据要能证伪**（正反例、反向护栏、「把角标抹掉仍命中」）；**同一形状的两种状态别靠去均值归一化硬分**，要换到颜色维度；**陌生页要有逃生门**（全黑帧不产生任何点击、认不出就安全停止留证）。

## 危险边界

- 这条路线是领取、**不花资源**；但「全部领取 / 关闭 / 跳过 / 效果升级」都是真实点击，靠页面互斥与 fail-closed 拦误点：全黑帧只许返回 `None` 或抛 `UnrecognizedScreen`，**不许给出带坐标的动作**，见 [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
- **弹窗必须排在成就页前面**：半透明遮罩下整页锚点照样高分，把整页调到前面会对着被盖住的按钮点。
- 收工不许抄近路：必须每个分类都走进去、当场确认「全部领取灰 + 没有升级按钮」；**不许**退回「红点都没了」或「连续几帧灰 + 原地复核」这类省事口径（用户 2026-11-08 亲眼看到一个分类还剩一堆没领、汇总却打了勾）。
- **领取优先于效果升级（用户口径）**：「我们就把所有的有红点的都点完，然后把它全部都领取完」——「全部领取」绿时即使「持续效果上升」也在，先点领取；不许改成自动择优或反过来。
- 认不出 / 超时 → 安全停止留证，不猜着继续点，见 [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- 平台差异只存在于**图片**与窗口 I/O，业务代码一套、两个客户端共用，阈值不分平台；PC 改动不许影响模拟器。
