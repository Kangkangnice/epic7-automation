## 这条路线在游戏里干什么

每天进一次圣域，把「精灵之森」里刷出来的材料收掉：哪一行长成了就点「领取奖励」，
弹出来的成长完成提示要自己点掉，第三行旁边亮起来的「照料」也顺手点掉、加速生长。
三行都不可领、照料也不亮就收工回大厅。用户口径是「先把部分刷新的这些流程走通」，
所以本轮只做最上面那一行「精灵之森」，另外两行先不碰。

## 页面链路

```
大厅 → 圣域主页 → 精灵之森 →（可领行：领取奖励 → 成长完成弹窗 → 点击关闭 → 回本页）
                            →（照料按钮亮：点照料 → 按钮转灰）
      → 无可领行且照料不亮 → 回大厅收工
```

- 大厅入口是左侧竖排菜单**最上面**那个「圣域」（在「光辉里程碑」上方）。领奖弹窗
  **不会自己消失**（与用户口述不符，以实测为准），必须自己点掉，**别改成等待**；
  「照料」不换页，把关靠下一帧重新判页面看按钮转没转灰。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **五个「可领」特征只用「领取奖励」字形**：蓝底 / 白边框 / 闪烁 / 红点都不当判据。
  闪烁只压底色亮度不改形状（模板匹配本就归一化），红点是通知角标、看过通知会先于
  「领取奖励」消失 ⇒ 拿它当必需条件会**漏领**，只做旁证；蓝底白边在淡入与弹窗遮罩下
  都会变，是已知会骗人的一维。只认字形，别为闪烁降阈值。
- **圣域标题刻意不裁短前缀**：主页判据用的是右侧第一行「精灵之森」，不是左上角
  两字标题「圣域」——有别的关卡标题恰好以「圣域」开头，短标题会是别的标题的前缀而
  误命中。⇒ 通用结论：**短标题可能是长标题的前缀，认整行 / 专属文字，别认短词。**
- **「照料」在不在与能不能点，是两道独立判据**：模板匹配对「形状一样、明度不同」
  天然失明，亮态与冷却灰态照样都命中 ⇒ 单靠模板会把「不能点」当成「能点」。
  能不能点改看「文字白不白」（文字自己的颜色，与背景无关）。
- **能不能点绝不用按钮绝对亮度**：圣域是 3D 昼夜场景、药丸半透明，拿一个状态完全
  相同的参照物一量，它自己就随背景大幅变化 —— 白天冷却中的按钮会被误判成可点，
  而那是**会真点下去**的。⇒ 通用结论：**凡判据依赖会被昼夜 / 遮罩盖住的画面
  （绝对亮度、状态色、血条、数量角标），都要问「背景变了它会变成什么」**，
  只补图解决「认不出」，解决不了「认出了错的结论」。
- **行必须按 y 排序，不许按分数排序**：相邻两行分数只差一点点、帧间还互相反超，
  按分数排会在两行之间来回跳，表现是「同一材料反复点、另一行永远轮不到」。
- **弹窗必须判在精灵之森「之前」**：弹窗只把底页压暗，底页标题在遮罩下仍然命中，
  只靠它分不出「弹窗开着 / 关着」。顺序反了就会对着盖着弹窗的画面去点「领取奖励」，
  那一下点在遮罩上、什么都不发生，然后重试到报错。
- **`popup_close` 不排他但不构成风险**：它是游戏通用的「获得奖励」弹窗底部控件，
  命中是**对的**（确实是同一种控件），动作只是「点掉它」、无副作用。真要给它找专属
  锚点做不到 —— 那个弹窗标题与物品图标每次都变，没有稳定特征。
- **淡入 / 淡出的半透明区间靠「连续两帧一致才采信」挡住**：那一瞬页面像「今天收完了」，
  但它只持续极短，主循环取样间隔远高于它 ⇒ 两帧不可能同时落进这个窗口。别把取样
  间隔调太快，那样这条论证就不成立。
- **导航层必须认得圣域主页**：转场靠「观察报出目标页名」才算成功，少了这一环，
  「大厅 → 进圣域」永远验收不通过、一路重试到超时。锚点复用「精灵之森」那一行，
  不另存一份。
- **通用教训**：接力 / 判页常是「几个候选页里认出当前哪一个」，且同一页的可领 /
  不可领、亮 / 灰两态都要各自接住；阶段机只有明确证据才推进，认不出的页面原地等、
  超时失败退出，不猜不硬点。

## 危险边界

- **不可逆的是「领取奖励 / 照料」这两个点掉动作**：靠「字形判可领」「文字白不白判
  可点」「行按 y 排序」「弹窗先判」四道拦住误点与漏领；尤其不许用绝对亮度放行
  冷却中的照料按钮。
- **领奖弹窗必须自己点掉**，不许改成等待；弹窗判在底页之前，否则点击落在遮罩上。
- **`claim-row` 刻意用「弹窗出现」当出口证据**：万一那一下没生效、弹窗不出现，
  就用同一坐标重点，然后**响亮地失败**（留诊断 + 退出码非 0），不许悄悄跳到下一行。
- **失败要真失败，不许「优雅收尾」**：动作耗尽时别覆写成「已收尾」返回成功 ——
  那会让用户看到「任务完成」而实际一个材料都没领到。必须是退出码非 0 + 失败通知。
- 认不出 / 超时 / 点击始终不落地 → 安全停止留证，不猜着继续点，见
  [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- **别改用户拍板的口径**：本轮只做「精灵之森」一行（已知且被认可的范围）；
  「先不读金额 / 数量」，只在日志写点掉了哪一行；「点照料没有弹窗」是用户判断、
  尚未实点，别替用户点掉。全局危险动作与拦截机制见
  [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
