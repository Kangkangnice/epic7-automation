# 路线终点与回大厅

路线终点是其业务和局内退场已处理完、可以交给公共回大厅流程的位置。有固定数量时先核对实得量，自然结束或资源用尽时先取得对应证据。验收结果的分类以[路线开发与验收](../howto/route_change.md#一次启动只有一个结论)为准。

## 路线与公共收尾的分工

| 谁负责 | 需要确认的事实 |
| --- | --- |
| 路线 | 记下已经确认的业务结果，处理本路线的结算、房间和浮层，用正向页面证据确认已离开局内。 |
| 公共回大厅 | 从可接管的页面用快捷菜单返回酒馆或大厅。仅在允许输入且有预算时按返回键恢复，等画面变化再继续，最后用大厅判据确认。 |
| 每日编排 | 需要回到大厅的任务确认回到大厅后才交给下一条。游戏内的自然结束、回大厅成功和整项任务成功各自记录。 |

先用页面专有证据确认已脱离局内，再识别可操作的返回入口。迷宫商店等浮层会压暗快捷菜单，图标仍可能匹配过阈。迷宫流程应先离开商店及房间，退出迷宫并确认详情页，再交给公共收尾。[迷宫强化石维护手册](labyrinth_stone.md)

## 异常时保留什么

- 确认业务已发生而收尾失败时，保留实得量和最后可靠画面，按收尾失败记录。
- 社区兑换和竞技场购旗已提交、回执仍不明确时，路线保留现场，当次每日编排也停止。刷书签会保存诊断并停止该路线，目前仍可进入普通失败收尾和段间检查。[刷书签异常处置](shop_refresh.md#异常与收尾)
- 人工停止后停止发输入。其他运行故障按已声明的安全恢复路径处理，保留原始错误和实际落点。
- 需要人工摆到指定起点、没有导航器的活动小游戏按已声明豁免结束，由使用者确认落点。

新增或调整路线时，给正常完成和可预期提前停止各准备一个终点正例，以及最接近的局内或浮层反例。使用[路线通用契约](../ROUTE_CONTRACT.md)登记终点和覆盖层，用[验收记录](../howto/route_acceptance.md)保存本次真实结果。收尾入口、豁免和回归分别查[公共回大厅实现](../../games/epic7/home_return.py)、[回大厅声明](../../games/epic7/finish_home.py)和[收尾回归](../../tests/test_home_return_failure.py)。

## 狗粮

大厅从「支线故事」进入指定的特别篇和关卡，进入队伍配置后开打。处理结算并确认「重新进行」出现时计一轮。仍有计划次数才重开，跑满后交给公共回大厅。获准补体力时按设置处理。入口到重复挑战的实机闭环待验。[导航声明](../../games/epic7/modes.py) · [路线实现](../../games/epic7/fodder.py) · [回归](../../tests/test_fodder_runner.py)

## 活动小游戏

活动当前已过期。历史路线由玩家手动打开首卡页，选卡后在局内移动，升级时选强化，结算后点「重新进行」，以回到首卡页为一轮终点。游戏停在活动内部，玩家确认退场。复刻时重新验收入口、操作与连续两轮。[路线实现](../../games/epic7/survivor.py) · [回归](../../tests/test_survivor_runner.py)

## 活动剧情

玩家手动停在本期「观看故事」页并单独启动。打开故事后按画面处理剧情、战斗和结算，回到观看列表后再进入下一段。用票券标记与返回后的列表、按钮变化判断进度，连续两次有效往返无进展也会停止。结束时留在当前页面，由玩家退场。本期「已看完」正例仍待取证。[路线实现](../../games/epic7/activity_story.py) · [回归](../../tests/test_epic7_activity_story.py)

## 世界首领战

大厅从快捷菜单进入「骑士团」和「世界首领战」。允许接手已识别的队伍、战斗或结算页。按当日剩余额度出战，完成结算后检查可领奖励。选择队伍已禁用时，仍先检查可领取宝箱，再交给公共回大厅。目标候选有剩余次数时的出战、领奖与收尾待验。[路线实现](../../games/epic7/world_boss.py) · [回归](../../tests/test_world_boss_runner.py)
