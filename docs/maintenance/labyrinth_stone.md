# 迷宫强化石（`labyrinth_stone`）—— 维护手册

> 改这条路线之前先看这一份。判据的**实测依据**都写在代码注释里，
> 这份文档只负责「改哪里、缺口在哪、怎么验」。

## 这条路线要干什么

每天一次，完整链路（2026-09-25 全段接通）：

```
大厅 → 战斗菜单「一般」页 → 迷宫卡片 → 迷宫列表第一个「混乱的提雷尔城」
  → 详情页（确保选中 1 区域）→ 选择队伍 → 战斗开始 → 跳过开场剧情
  → 十字路口房间：开地图 → 往左上拖到最上方出口 → 点出口 pin → 传送确认
  → 传送落地房：点左下 W 徽记往西走 → 流浪商人（蓝松鼠）→ 商店买目标商品
  → 退出商店 → 暂停菜单 → 放弃战斗 → 确认放弃 → 详情页 → 右上角快捷菜单 → 酒馆 → 大厅
```

**目标商品（2026-11-07 起四类）**：强化石走「类别写着强化石 + 名字里带石」两道文字锁；
友情点数、圣约书签、神秘书签走**商品图标**（三张图直接借 `templates/shop_refresh/`，
与秘密商店是同一个商品、同一张图，不另存第二份）—— 类别标签会随商店变，图标不变。
实测（阈 0.80）：两种书签真行 0.9815 / 0.966，迷宫现有真帧最高 0.559 / 0.391
⇒ 不会把强化拳套之类误认成书签；认不出只是少买，不会误买。三张图共用同一搜索区
`(830, 150, 200, 982)` 与同一阈值；按钮上有没有白字（没卖完）仍是共同的最后一道锁。
接线回归用例：`tests/test_labyrinth_stone.py::test_a_bookmark_row_is_bought`。

⚠️ **缺口**：目前没有「迷宫商店恰好刷出书签」的真帧，上面的接线验证是把秘密商店真帧里的
图标块平移到迷宫商店真帧上做的。首次实跑若书签没被买走，先看运行时诊断帧与图标分数，
再补一张迷宫商店书签行的真夹具。

迷宫**不消耗门票**，所以随时可以实跑验证；商店里当天没有可买的目标商品是**正常结局**
（会走「下滑三次 → 离开」的收尾分支）。

## ⚠️ 什么时候才能「放弃」（2026-09-25 真机翻车后立的规矩）

**症状**：刚进迷宫、还没走到第一个十字路口，就开暂停 → 放弃战斗 → 回大厅；
传送落地后往西赶路那段也一样。日志还写「已完成一遍」。

**根因**：房间里的判据是「**没看见**开地图的蓝菱形 ⇒ 这一段认输 ⇒ 放弃」。
而进迷宫有**两段走路**，走路期间画面一直在变、控件还在淡入 —— 菱形模板
在走路第一帧只有 **0.337**（站定才 1.000），阈值 0.80 根本过不去。

> 用户原话：「你放弃战斗的这一个理由是什么？**你是看到了什么东西**才去选择放弃？……
> 我们正常人至少得先到流浪商人那边，进商店，发现里面的强化石都卖光了，才收工。
> **你跟那个菱形有什么关系？**」

于是判据分成两类，**不许混**：

| 情形 | 属于 | 处理 |
|---|---|---|
| 走路 / 过场 / 控件淡入期间认不出锚点 | **还没到** | 抛 `UnrecognizedScreen` **等**，绝不放弃 |
| 商店确认没有可买的强化石了 | **做成了**（唯一正当收工） | 正常回家，算完成 |
| 地图拖 3 次仍找不到出口 / 往西走 3 间房还没到商人 / 撞上真战斗 | **做不成**（看得见的事实或有界重试走完） | 回家 + **记真实原因** + Runner 报错（退出码 1） |

⚠️ **「没看见某个东西」永远不能当放弃的理由** —— 那等于闭着眼睛按不可逆按钮。
`_open_pause` 的 docstring 里写死了只有两个地方能调它，改代码前先读那段。
⚠️ **回家 ≠ 完成**：`_check_cycle_completed` 会拿 `blocked_reason` 卡一道闸，
非空就 `RuntimeError`（退出码 1），绝不写「已完成一遍」。

## 有界重试（「搜不到就收工」的另一半）

这条路线**没有任何一处会原地打转或猜坐标**，代价只是少买一次（迷宫不花门票）：

| 卡在哪 | 行为 |
|---|---|
| 地图拖了 3 次仍看不到目标出口 pin | 关地图 → 记原因 → 回家报错（`map_done`） |
| 传送落地后往西走满 3 间房还没到商人 | 记原因 → 回家报错 |
| 商店里一行都配不上「强化石」标签 | 下滑 3 次 → 离开 → 收工（**正当收工**，算完成） |
| 走路期间认不出锚点 | **等**，不收工（见上一节） |

## ⚠️ 六条实测事实（决定了写法，改之前先读代码里的依据）

1. **迷宫房间会被 `battle_scene_visible` 误报成战斗中** ⇒ `_BATTLE_ENTRY_ACTION = None`。
   房间与真战斗靠 `morale_smiley` / `battle_turn_bar` 分开，**`battle` 页必须排在 `room` 前面**
   （战斗画面左上角也有士气笑脸，实测 0.9890）。
2. **迷宫详情页会来两次**（进场前 / 放弃后），画面一模一样、下一步相反
   ⇒ 靠 `entered` 这个跨帧进度标记区分；接力落在迷宫里时必须 `mark_entered()`。
3. **蓝色控件别拿 BGR 画面去量**：`load_template` 会把模板转成 RGB，
   夹具/探针用 `cv2.imread` 直接读会让蓝菱形从 1.0000 掉到 0.2528。
4. **W 徽记是半透明的**：142×142 的模板在传送落地房只有 0.61，换 **90×90** 升到 0.83~1.00；
   而 `redo_W` 那间房**根本没有** W 徽记（0.31）⇒ 「点不到 W」是**还在走路**，要等。
5. **商店类别标签在购买按钮下方 139 px、行距 217**（配对容差 60）：配不上对的行**一律不点** ——
   认不出是不是强化石就不买（现有样本里配不上对的正是要跳过的「强化拳套」）。
6. **左上角开地图那颗蓝菱形也是半透明的**：走路第一帧模板只有 **0.337**（站定 1.000），
   两条判据取**或** —— 模板 ≥0.30 **或** 蓝色块占比 ≥0.15（只看色相/饱和度，
   **不看亮度**，免得又被淡入骗一次）。走路帧蓝色 0.20、站定 0.27~0.28。
   判据本体在 `evidence/labyrinth_stone.py::map_button_blue_blob`。

## ⚠️ 商店：买什么要过三道关（2026-09-25 真机买错东西后重做）

**事故**：除了强化石，还把**强化拳套**（18,000）买走了。花的是真金白银。

**根因**：「类别标签 → 购买按钮」的偏移**方向写反了**。实测是**类别在按钮上方 82**，
代码写的却是 `+139` ⇒ 每一行都拿**下一行**的类别标签来判断自己是什么商品。
因为强化石常常连着几行，错位后大部分行仍然「看起来对」，只有边界那几行露馅 ——
而 `shop_mostly_bought` 上恰好只剩「强化拳套」亮着，它借到了下一行「强化石」的类别。

| 关 | 问什么 | 口径 | 实测 |
|---|---|---|---|
| ① 类别 | 这一行的类别标签写着「强化石」吗 | 类别中心 y ≈ 购买按钮 y **−82**（±60） | 两张帧 9 行全部吻合（差 81~83） |
| ② 商品名 | 这一行的商品名里有「石」字吗 | 「石」中心 y ≈ 购买按钮 y **−34**（±30） | 强化石 0.94~1.00 / 强化拳套 0.51 / 友情点数 0.46 |
| ③ 买过没 | 按钮上还亮着白字吗 | **白字像素数** ≥ 400（窗口 ±(58,23)） | 亮行 817~844 颗 / 售罄行 0~3 颗 |

⚠️ ①②**缺一不可** —— 事故那次就是①单独失灵。两条问的是不同的事，不会一起错。
⚠️ ③ 的口径改过两次，两次都是真机事故逼的（详见下面 2026-10-19 那一节）：
先「相对亮度」→ 被压暗骗；再「最亮一颗」→ 被**一颗**游离白像素骗；
现在「一片白字」= 窗口收进模板 footprint + 数够不够多。
**别把它改回任何一种「取极值」的写法**，极值天然只有一颗像素的鲁棒性。

**再加上**：不是本路线点出来的购买确认框一律按**取消**（`buy_armed`）——
认不出买的是什么就绝不替人按「确定」。

⚠️ **教训**：原来那条测试断言的是 `(1792, 299)`，也就是**友情点数**的按钮，
它一直在为「买错东西」背书。判据对了不等于断言对了 —— 断言值必须能说清
「这一行到底是什么商品」，所以这次是**用 OCR 把两张商店帧逐行读出来**才核对出来的。

## 2026-10-04：游戏记住「赛季」页，迷宫进不去（上表那条缺口第一次真机爆发）

**现象**：当天 07:32 那次每日任务，迷宫强化石 ✗ —— 圣域收完菜回到家点了「进入战斗菜单」，
落在**「赛季」页**之后就再也不动，干等约 92 秒报
`RuntimeError: 导航开始前应处于[大厅]`（诊断帧
`runtime_diagnostics/epic7_labyrinth_stone/20261004_081751_685808_expected_lobby.png`）。

**根因**：游戏**记住**上次停在哪个标签页。前一天跑过远征（它要点「赛季」），第二天从大厅
点进「战斗」就直接落在赛季页；而**迷宫入口只在「一般」页**。当时这条链的 `- 第一跳` 写的是
`("lobby", ("battle_menu",), ...)` —— 只认「一般」页，落到赛季页就没有下一步可走。
（同一天竞技场那次 ✗ 是另一个独立原因：游戏掉线，见
`runtime_diagnostics/epic7_arena/20261004_081019_044061_*.png`。）

**修法**（照抄远征那条早就写对的链）：

1. 第一跳接纳两个落点：`("lobby", ("battle_menu", "season_menu"), "lobby_battle", …)`；
2. 加第二步 `season_menu → battle_menu`，锚点是新模板
   `templates/navigation/battle_general_tab.png`（「一般」标签条，
   `_REGIONS = (100, 165, 250, 105)`），并带 `skip_if_observed=("battle_menu",)`
   —— 已经站在「一般」页就别再点那一栏。

**模板从哪来的**：就是这次卡住的那张真机帧，`x 105..345 / y 175..265`（240×90，
与「赛季」条同尺寸且紧挨在其左侧）。选它没选合成图，是因为**需要点它的时候它就是这个样子**
（未选中态）。位置这么定是有量化依据的 —— 同一格里，「一般」在一般栏帧是选中态
（亮度 82.6/标准差 44.9），在赛季栏帧是未选中态（55.6/18.2），赛季格刚好反着，两者互换吻合。

**分离度（生产口径：3 通道 + TM_CCOEFF_NORMED，全夹具 236 张）**：

| 样本 | 分数 |
|---|---|
| 赛季页（本次卡帧） | 1.0000 @ (105,175) |
| 赛季页（旧夹具 `expedition_season_menu`） | 0.8668 |
| **一般页**（`epic7_labyrinth_stone/battle_menu`，不能点它） | 0.3532 |
| 其余 233 张最高 | 0.3691 |

门槛 0.82，正负之间隔着 0.45，余量充足。

**回归防线**：`tests/test_navigation.py` 三条 ——
`test_labyrinth_navigation_switches_back_from_the_remembered_season_tab`（复现本次事故，
断言两次点击 `(1819,537)` + `(225,220)`）、
`test_labyrinth_navigation_leaves_the_general_tab_alone_when_already_on_it`、
`test_general_tab_candidates_cover_both_source_pages`（分数写死在断言里；该用例 2026-10-13
改名并扩写为「两张候选」口径，见下节）。

## 2026-10-13：游戏记住的标签页**不止「赛季」一种**（第三个标签页）

**现象**：10-12 23:01 那次每日任务，迷宫强化石又 ✗ —— 但这次**不再**卡在赛季页：日志里
`点击验收=生效 从=大厅 到=战斗菜单 耗时=3.5秒`、`页面=战斗菜单 置信度=1.000`，
导航认为已经就位；迷宫路线接手后却报 **`迷宫强化石画面[战斗菜单·一般页]未识别`**，
不点任何地方、干等 60 秒超时（诊断帧
`runtime_diagnostics/epic7_labyrinth_stone/20261012_230105_464105_unknown_screen_unresolved.png`
与 `…20261012_230202_433099_timeout_battle_menu.png`，日志
`runtime_logs/epic7_labyrinth_stone.log` 23:01:01~23:02:02）。

**根因**：那天「战斗」菜单停在的既不是「一般」也不是「赛季」，而是**第三个标签页**
（当天写着「事件」）。而当时的判页口径是「顶栏标题在 **且** 『赛季』没被选中」——
第三个标签页**同样满足**，于是它被当成了一般页（还给了满分 1.000）。后面是连锁反应：

1. `observe()` 报 `battle_menu` ⇒ 「切回一般页」那一步被 `skip_if_observed=("battle_menu",)` 跳过；
2. 迷宫路线在第三页上找「一般」页那四张卡片 ⇒ 判「认不出」；
3. 60 秒超时，当天强化石一块没买。

**修法**：把这一屏按「**哪个标签被选中**」分成三页，而不是按「赛季有没有被选中」：

| 选中态 | 页面名 | 谁在这页 |
|---|---|---|
| 「一般」选中 | `battle_menu` | 迷宫入口 |
| 「赛季」选中 | `season_menu` | 远征 / 月塔入口 |
| 都不是 | `battle_other_menu` | 没有路线入口，只是路过 |

判据落在 `navigation.py` 的 `observe()` + 新锚点 `battle_general_active.png`
（「一般」**选中**态，与 `battle_general_tab` 严格同框 `(105,175,240,90)`）。

⚠️ **为什么不认第三个标签的文字**：它会变 —— 09-25 的帧上写着「**活动**」、10-12 的帧上写着

## 2026-10-19（同日第二次）：商店里对着「售罄行」连点 4 次，然后回家耗满 120 秒

**症状**：每日任务里「迷宫强化石 ✗」，报错是**回家**报的，不是路线报的：

```
19:36:18 已保存诊断 .../20261019_193618_371454_retry_exhausted_buy-stone.png
19:38:21 模式=labyrinth_stone 异常收尾=回首页失败
         原因=RuntimeError: 返回首页失败：超过 120 秒仍未回到大厅
```

诊断图是**商店页**（「商人」）。两张图（19:36 的重试耗尽、19:38 的回家超时）是同一页。

**根因（两处，必须都修）**：

**① 判「卖没卖完」的口径被一颗像素破了。**
现场帧里最底下那行「下级装备强化石 0/1」的按钮被**窗口底边裁掉半截**，
它**右边**紧挨着下一行天头被切断的白字碎片（纯白）。旧窗口 `BUY_PAD_HALF = ±(80,32)`
比按钮模板（116×46）左右各宽 22px ⇒ 把碎片圈了进来 ⇒ 一整块 **143** 的灰按钮
被量出 **239**（阈 200）⇒ 判「还亮着」⇒ 点 (1792,1061) 四次，页面上什么也没发生。

`runtime_logs/_probe_buy_white_pixels.py` 的逐行读数（V≥200）：

| 帧 | 行 | 窄窗口 ±(58,23) | 宽窗口 ±(80,32) |
|---|---|---|---|
| `shop.png` | 4 行「1/1」全亮 | **835 / 844** | 835 / 844 |
| `shop_mostly_bought.png` | 「1/1」亮 | **844** | 844 |
| `shop_mostly_bought.png` | 4 行「0/1」售罄 | **0** | 0 |
| 真机帧(本次) | 3 行「1/1」亮 | **817 / 835 / 844** | 817 / 835 / 844 |
| 真机帧(本次) | 「下级神器强化石 0/1」售罄 | **0** | 0 |
| 真机帧(本次) | 底边被裁的「0/1」售罄行 | **3** | **38** |

⇒ 真阳性地板 **817** ↔ 必须挡住的天花板 **3**，阈值取 **400**（两头各留 400 上下）。
改法：`button_live_v`（取最亮一颗）→ **`button_white_pixels`（数一片白字）**，
窗口收进模板 footprint。**这是「取极值」第二次栽在单点噪声上，别再改回去。**

**② 回家流程在 `unknown` 页上把同一招重试到超时。**
商店页对导航层是 `unknown`；那颗「蓝色四格」被商店浮层盖着，模板却照样命中
**0.835**（阈 0.80）⇒ v2 每轮点它一次、空等 12 秒，**同一行重复 8 次**才报 120 秒超时。
这违反了「未登记页必须有有界逃生门」那条铁律。
修法见 `games/epic7/home_return.py` 模块 docstring 的
「『重看一遍』≠『重试同一招』」一节：连续两次无效即停用该动作、落到 ESC 兜底。

**以后看到这条报错怎么分诊**：`回首页失败 / 超过 120 秒` 先去看**当时停在哪个页面**
（报错里现在带 `最后一帧认作页面=…`，日志里有 `动作前页面=` 和 `点击验收=无效`）。
若同一动作的「置信度」反复是**同一个数字**（比如一直 0.835），几乎可以断定是
**判据在这一页上不成立**（控件被盖住 / 被压暗），不是转场慢 —— 转场慢的话置信度会跳。

复现探针（都是只读的，可重跑）：

- `runtime_logs/_probe_buy_stone_row.py` —— 逐行打印三道锁的判定与白字像素数
- `runtime_logs/_probe_buy_white_pixels.py` —— 三张商店帧逐行量白字像素（新旧窗口对照）

**⚠️ 这条修法只是「止损」，不是「回家能自己从商店走出来」。**
ESC 的「连续 2 次无效就报错」（2026-09-25 定的）在**未登记页**上同样生效：
停用点击后落到 ESC，两下都没换来页面身份变化就报
`连按 2 次 ESC 页面都没有变化（停在页面=unknown）`。
实测这条路径现在**32 秒**就收场（原先 120 秒），报错里带页面身份，日志里有
`状态=停用该动作改走ESC兜底` —— 但它仍然是 ✗。
**真正的修法永远在上游**：让路线自己正常走完（这里就是第①条），
别指望回家流程替它擦屁股。
