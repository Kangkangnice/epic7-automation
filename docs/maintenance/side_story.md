## 这条路线在游戏里干什么

一期支线故事在**同一条运行内**按 `_SEG_LABELS` 的段位顺序一次跑完：
① 普通关卡 → ② 摩罗戈拉据点 → ③ 哥布林据点 → ④ BOSS 难度阶梯。
段与段之间不需要人手动导航；④ 地狱级打满、点「离开」回地图才收工回大厅。
**这条路线会花资源**：进场打关卡与难度要行动力，据点与 BOSS 有一次性入场次数，
误点会真打错本，下面「危险边界」写了怎么拦。

⚠️ **顺序是用户 2026-11-12 逐条拍板的**（原话「摩拉格拉、哥布林，然后再到骷髅头」）。
旧版本把 ② 写成 BOSS、把据点放到最后，是反的；改段位顺序前先回看这一句。

## 页面链路

```
大厅 → 支线故事页 → 右上「支线故事」标签 →「可进入的支线故事」列表 → 普通那条的「入场」
    → Episode 详情页（左下角有「剩余 N 天 N 小时」）→ 冒险
    → 关卡地图 → ① 普通关卡（准备战斗 → 队伍 → 战斗 → 结算 → 蓝箭头进下一关）
        → ② 摩罗戈拉据点  → ③ 哥布林据点（各一次，打满点「离开」回地图）
        → ④ BOSS 难度阶梯（骷髅节点 → 选难度 → 队伍 → 战斗 → 下一个难度 / 重新进行）
        → ④ 打满点「离开」→ 关卡地图 → 收工回大厅
```

① → ② → ③ → ④ **一条运行内连起来**（用户拍板「123 一定要连起来」）：① 场景页
连续无箭头就点「离开」回地图、切 ②；②③ 据点「次数用尽」点「返回」退场、场景页
「离开」回地图后推进下一段（摩罗戈拉 → 哥布林 → BOSS）；④「次数用尽」是**最后一段**，
点「返回」退场、地狱级场景页点「离开」，回地图即收工。段间靠**段落账本**推进，
只在有明确证据的动作上走；接力落在地图页时另由「入场限制 0/1」气泡数自证段位，
不靠上次运行留下的记忆。

**入口不走「快速入场」**（2026-11-12 用户要求）：有活动时那颗按钮会被活动条目顶掉，
怎么点都进不去普通支线。改点右上标签进列表，再挑普通那条。列表里活动条目与普通条目
**同色**（都是亮绿字），只能靠横坐标分：右下的「入场」在 ≥1700，左下的「剩余 N 天」
活动标记在 ≤1650。PC 上点完「入场」还会多一层「期次主页」，点右侧「故事」才到
Episode 详情（模拟器没有这一层，两颗模板在模拟器口径下是空元组）。

**只读巡检复用同一条入口链，但止步于 Episode 详情页**：每日任务跑完所有路线后额外
走一趟，只为把那一行倒计时读下来（见下「只读巡检」）。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **地图节点只认图标、不认名字牌**：点名字牌没反应，点图标才让角色走过去＝选中。
  名字牌文字固定、每期不变，适合**认**；图标会被选中角色挡住，适合**点**，两者不是
  同一个东西。又因「点空白会拖走视角」，坐标不能写死，必须每帧模板定位后再点。
- **BOSS 徽章只裁骷髅那一块**：城堡主体会被角色遮挡、红色标签横幅所有节点同形，
  只有骷髅徽章是 BOSS 独有、且角色站上去仍露在一侧 ⇒ 裁徽章才能在「所有节点长得像」
  里把 BOSS 单独挑出来；退回整钮或带横幅的裁法都会混进假阳性。
- **摩罗戈拉节点走双候选（清晰态＋雾态）**：单候选跨帧会被负例反超，补上雾态那版
  才把所有地图帧盖住 ⇒ 同一对象有稳定两种长相时走多候选，别指望一张图通吃。
- **「准备战斗」是常显按钮，必须等地图稳定后才点**：角色永远站在某个节点上，点了
  目标、人还在走路时按它 = **进错关卡**。判据靠「中部内容区连续稳定」这一维，
  不是靠「按钮亮不亮」——按钮一直是亮的，分不出站位有没有落定。
- **平移动作名必须带次数**：相机跟角色走，目标可能不在视野内，要滑动扫寻。同名
  动作会被主循环判「转场未完成、还在来源页」而不断重发，变成原地反复拖动 ⇒ 每次
  平移用带序号的动作名区分，扫寻有上界，找不到就原地等超时，绝不瞎点。
- **据点场景页与普通场景页视觉不可分 ⇒ 走状态制**：两页都有「离开」「大厅」
  「重新进行」、都没蓝箭头、都没「下一个难度」；任何「看到这一页就点离开」的纯页面
  判据都会在 ① 上误触发。改成在**据点队伍页**先由「可完成1次。」置位，把「离开」
  门控在「确实在据点里」的上下文里。
  ⚠️ **这条置位还得再加一道段位门禁**：④ 地狱级队伍页也有次数气泡（那一档要打满才走），
  同一张气泡图照样命中；不排除 ④ 就会把「打完一把」误判成「据点打完」直接点「离开」，
  5 次打不满。⇒ 通用结论：**页面长得一样时，靠进入这一页之前的状态区分，不靠这一页本身；
  而状态位本身也要有能证伪它的第二维，别让它一置位就永远为真。**
- **判据顺序：先认专属场景页，再判「重新进行」**：BOSS / 据点场景页上「重新进行」
  同样命中、蓝箭头同样为 0，若先按通用场景页逻辑走，会「若干帧后自判整条收工」。
  必须先把「下一个难度」/「据点模式」这些专属证据判掉，才轮到通用按钮。
- **`entry_exhausted` 是「这一段打完了」，不是收工**：它读游戏自身「可入场次数已
  全部耗尽。」这句真相源，同时覆盖 ②③ 据点次数用尽与 ④ 地狱级打满两种终点，比自己
  数「重新进行点了几下」稳（不怕少点 / 多点一次）。命中后由段落账本决定后果：点
  「返回」退场、回地图推进下一段，**不再就地收工**；**只有 ④（最后一段）打满、
  点「离开」回地图才收工**。
- **两个据点在 BOSS 之前、BOSS 收尾**（用户 2026-11-12 拍板）：这是游戏给的本期顺序，
  不是视角或平移的取舍 —— 别拿旧版「先打 BOSS 不用动视角」那套理由去改回来。
  由此推出两处不能写反的后果：②③ 打满只推进下一段，④ 打满才抛 `SideStoryCleared`；
  「下一个难度」只在 ④ 段且**没有蓝箭头**时才允许点（图还没走完就升难度会打断连打）。
- **BOSS 首进场不能交主线直接确认**：粘性难度档位是上一次的遗留，必须由「变更 →
  中级行 → 选择队伍」三拍显式拨到位，之后每档才交给「下一个难度」推上去。
- **列表里挑条目靠「横坐标」这一维**：活动条目与普通条目的绿字**同色同字号**，
  颜色 / 尺寸 / 形状都分不开（同一个 UI 组件）；能分开的只有语义位置 —— 右下角是
  「入场」、左下角是活动标记。⇒ 通用结论：**同色同类控件要靠语义位置而不是外观
  区分**，且必须先认「这一页是列表」（只靠「有绿字」会在队伍准备页误命中，
  那页的「战斗开始」也是绿的）。
- **`countdown_only` 是「整段换道」，不是「多加一个早退」**：只读巡检打开后
  `_side_decision` 直接走 `_countdown_decision`，主线的任何动作都发不出去。若改成
  「在原有判据前面插一条 Episode 详情页分支」，一旦没走到那一页（读不到字、转场慢、
  停在别处），后面的判据就会照常点「准备战斗」—— 而这一趟的全部意义是**只看不打**。
  ⇒ 通用结论：**「只读 / 只认不点」的支路要把后续点击整体切断，不能靠在前面加早退。**
- **通用教训**：阶段机**只有明确证据才推进**，认不出的页面一律原地等、超时失败退出，
  不猜不硬点；接力用的页面常是「几个候选页里认出当前哪一个」，且同一页的可点 /
  不可点两态都要各自接住，别只接一个分支，认不出就单列一类、绝不并进别的结论；
  凡判据依赖会被遮罩或平移改动的那块画面，都要问「盖上来 / 拖过去它会变成什么」。

## 只读巡检（支线刷新倒计时）

普通支线每两周刷新一次，换期要用户自己去做。所以**每日任务跑完所有路线之后**再走
一趟入口链，只到 Episode 详情页把左下角那行「剩余 N 天 N 小时」读下来（OCR），
读数存 `side_story_countdown.json`，界面「今日游戏便签」里挂在待办下面那一行。

三条口径，改之前先读：

- **只读**：见上「判据为什么这么设计」最后第二条 —— 整段换道，一个会开始打图的
  按钮都不许点。
- **读不到不猜**：OCR 没认出字就返回「这一页归我管、但不动手」，交给状态超时收场，
  绝不拿上一帧 / 上一页 / 默认值顶替。没装 `rapidocr-onnxruntime` 时整段静默跳过。
- **不影响整轮结论**：读不到就是「这次没读到」，不是「今天没做完」；干跑 / 按过 P /
  整轮中止三种情况直接不做。它是收尾动作，**不是一条路线** —— 不进每日任务的
  `outcomes`，也不参与成功 / 失败判定。

## 危险边界

- **会花资源的是「准备战斗 / 战斗开始」**：进错关卡会真消耗行动力打错本。靠
  「地图稳定后才点」「只认图标、每帧定位」「平移有上界、找不到超时兜底」三道拦住误点。
- **据点是一次性次数**：靠状态制门控「离开」、靠 `entry_exhausted` 读真相源，不靠
  自己计数；点「返回」退场交给段落账本，不许静默跳过下一个据点。
- 认不出 / 超时 / 状态机推不动 → 安全停止留证，不猜着继续点，见
  [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- **别改用户拍板的口径**：①→②→③→④ 一条运行内连起来、不拆成手动几段；
  两个据点在 BOSS 之前、BOSS 最后收工；`entry_exhausted` 只作「这一段打完」、
  不作收工；终点读游戏自身的「次数用尽」文案，不再自己数「打满几次」。
- 全局危险动作与拦截机制见 [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
