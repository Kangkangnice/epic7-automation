# 英雄图鉴库与中英对照的更新流程

竞技场避战名单 / 优先名单按图鉴库列出英雄：**名单里的名字就是 `heroes_pokedex/` 下的文件名**，
职业 / 属性 / 星级来自同目录的 `meta.json`。因此「新英雄上线」这件事要落到三处：
补头像文件、定中文名、更新分类表。

本文给出固定的数据源与可复用的作业顺序。**新增英雄时按本文执行，不要临时找别的站。**

> **日常新增只看第二节**：中文名定好后一条命令入库（`tools/add_hero.py`），
> 头像、分类表、查重都由它完成。第三节的七步是**首次建库 / 全量重建**用的，不需要每次重跑。

---

## 一、固定数据源（只有这四个）

| 用途 | 地址 | 说明 |
|---|---|---|
| 英文名 + 职业/属性/星级 + 头像 | `https://epic7db.com/heroes` | 服务端渲染，`data-name / class / element / stars` 直接在 HTML 里 |
| 国服中文名（角色页） | `https://wiki.biligame.com/epic7/api.php` | MediaWiki API。**必须带 `User-Agent` 与 `Referer`**，裸请求返回 HTTP 567 |
| 国服官方公告 | `https://e7.qyzlgame.com/jx/e7Notice/` | 返回 JSON 数组；`index_N.html` 翻页，翻到 404 为止 |
| 新英雄头像（epic7db 未收录时） | `https://epic7helper.com/hero/<小写英文名>` | 角色页里有 `/img/heroes/<slug>_icon.png`，112×112、圆形裁切，与 epic7db 同一套图标口径 |

官方公告是**最高权威**。公告正文为静态 HTML（`/jx/e7Notice/YYYYMMDD/ID.html`），可直接下载。
截至 2026-11 共 196 条，时间跨度 2023/06（国服公测）至当月，其中「更新公告」163 条。

⚠️ epic7helper 只用于**补头像**：它的角色页有技能与面板，但中文名不能当官方译名用。
2026-11-17 用它补了 epic7db 尚未收录的蕾诺娅（Renoa）与黎洁特（Lisette）：
两站图标**同源** —— 拿同一名英雄（伯里安）比对，中心区域相关 0.9962、尺寸同为 112×112；
两名新英雄再与旧截图做 ORB 交叉核对（内点 147 / 90，门槛 20）确认是同一人才落库。

⚠️ 其余来源已实测不可用，别再试：gamekee 是 SPA 且 `/v1/bdRoster/*` 一律返回「缺少游戏信息」；
onstove 官方繁中站数据走 `e7api.onstove.com`，接口未找到；萌娘百科无此分类；
巴哈姆特直连失败；百度百科星图是空壳（单个词条可被搜索命中，只能用于抽查）。

## 二、新增一名英雄（日常，一条命令）

**怎么知道出了新英雄**：跑 `python -m auto_game_unified.tools.refresh_hero_meta --check`，
报告里「外部库比上次多出 N 名」逐条列英文名；或直接看国服更新公告 / 游戏内新卡池。
外部库滞后一到两周属正常，漏一两个不构成换源理由。

### 第 1 步：定中文名

顺序固定，前一步没有结果才走下一步：

1. **官方公告**（最高权威）：`e7.qyzlgame.com/jx/e7Notice/`，全文检索英文名对应的卡池公告，
   或按「全新5星英雄『X』登场」句式找；月光 / 转职英雄只差修饰语时，先搜已确认的基础名。
2. **技能特征**：公告里没有时按技能描述搜（例如「封印 拘禁 沉默 射手 五星」），
   **不要按音译名搜**（Kane→该隐、Nahkwol→落月、Tori→兔菈玫都是音译搜不到的）。
3. **gamekee 首页名单**：含意译名（落月、蕾娅这类）。

拿到中文名后与英文名、职业、属性、星级核对一次。epic7db 未收录的，
职业属性从 `epic7helper.com/hero/<小写英文名>` 的角色页标题取
（例如 `Lisette — Epic Seven Light Soul Weaver`）。

### 第 2 步：一条命令入库

```
python -m auto_game_unified.tools.add_hero --zh 蕾诺娅 --en Renoa
```

- epic7db 收录了这名英雄时，职业 / 属性 / 星级自动取，不必手填。
- 未收录时补上分类：

  ```
  python -m auto_game_unified.tools.add_hero --zh 落月 --en Nahkwol --job 射手 --element 火 --stars 5
  ```

- 工具做四件事：取头像（epic7db 直连 → epic7helper 兜底）、统一转 112×112 PNG、
  与库内已有头像查重、写 `meta.json` 并更新条数。
- 耗时：直连命中约 5 秒；需要读外部英雄库整页时约 1 分钟（只有缺分类或直连全 404 才会读）。

### 第 3 步：复核

```
python -m auto_game_unified.tools.refresh_hero_meta --check
python -m pytest tests/test_hero_catalog.py tests/test_arena_hero_lists.py tests/test_add_hero.py -q
```

第一条不应再报「新增可归类」（epic7db 未收录、用 epic7helper 补的英雄会出现在
「本次未达门槛但保留」里，属正常），第二条全绿。
最后打开竞技场名单，确认英雄出现、可勾选、按属性 / 职业 / 星级能筛到。

### 第 4 步：命令拦下了怎么办

| 提示 | 原因 | 处理 |
|---|---|---|
| 疑似同一张图已在库里：「X」相关 0.9xx | 该英雄已存在（别名或错位），或同角色的新形态 | 先核对 X 是不是同一人；确属不同形态加 `--force` |
| 英文名已挂在「X」名下 | 英文名重复 | 确认后加 `--force`，否则换英文名 |
| 头像已存在 | 同名文件已在库里 | 旧图先移入 `_obsolete/`，再加 `--force` |
| 两个来源都没有该英文名的图标 | slug 猜不中，或英雄太新 | 手动放一张 112×112 PNG，再用 `--skip-avatar` 只写分类 |

⚠️ `--force` 只跳过查重与覆盖保护，**不放宽任何判据**：中文名是否官方、分类是否正确仍由人确认。

查重口径：中心 50% 区域相关，**同一张图 1.000、同角色不同形态 0.04~0.43**
（实测安洁莉卡 / 光之天使 / 罪戾的安洁莉卡，优芬妮 / 度假风 / 深渊）。
阈 0.95 且领先第二名 0.05 才拦；`--force` 之后仍会打印分数，留痕。

## 三、首次建库 / 全量重建（一次性，不用每次跑）

### 第 1 步：拉全量英文名单

抓 `epic7db.com/heroes`，得到每名英雄的 `name / job / element / stars / avatar`。
头像落盘为 `avatars/<name>.webp`（文件名把非 `[A-Za-z0-9_-]` 一律换成下划线；
注意 HTML 实体先不反转义，`Baal &amp; Sezan` 会落成 `Baal__amp__Sezan.webp`）。

### 第 2 步：拉国服 wiki 角色页

`list=categorymembers&cmtitle=Category:角色` 取页面标题，再取每页源文。
页面里有 `|区服=s1 s2` 字段：**只有 `s2` 表示国服尚未上线**，这类不能标「国服已上线」。
页面字段同时提供 `稀有度 / 职业 / 属性`，用于第 4 步校验。

### 第 3 步：拉全部官方公告

逐页取 `jx/e7Notice/` 直到 404，再下载全部「更新公告」正文。

### 第 4 步：配对（按优先级，前一步没结果再走下一步）

1. **官方公告卡池句式**
   `「X」&「Y」…（召唤|卡池）` 可抽出开过卡池的英雄名，一轮约 150 个，覆盖全部版本更新。
   另有 `全新N星英雄「X」登场`、`新增全新三色3★英雄「A」、「B」、「C」` 两种写法。
2. **拿已确认的基础名做全文检索**
   月光 / 转职英雄只差修饰语时，在公告全文里搜基础名（如「艾庭」），上下文直接给出官方全称。
   本办法纠正过一批错译：`Sealed Eye Surin`＝封眼苏琳（不是封印之眼）、
   `Wretched Rose`＝悲叹萝季（不是悲惨）、`Monarch of the Sword Iseria`＝宝剑君主伊赛丽亚、
   `Boss Arunka`＝组长亚露嘉、`Aubade Ludwig`＝黎明序曲鲁特比。
3. **三元组 + 拼音**
   两边都按 `(属性, 职业, 星级)` 分组，同组内用 `pypinyin` 转拼音、`rapidfuzz` 打分排序，
   平均每组约 4 个候选，人工判定 top1。

### 第 5 步：交叉校验（缺一不可）

- **三元组必须全等**：wiki 的「稀有度/职业/属性」对 epic7db 的「星级/职业/属性」。
- **公告反查**：把结果与第 1 步抽出的官方名做拼音比对，精确命中的升级为「官方公告」来源。
  本办法抓出过实际错字：`Fenne` 应为**斐妮**（曾写作裴妮）。
- **唯一性**：中文名不得重复，英文名不得重复。

### 第 6 步：落库

1. **头像一律用 epic7db 的官方头像**（`avatars/<name>.webp` 转 112×112 PNG，文件名用官方中文名）。
   OCR 时代的游戏内截图**全部弃用**：实测 389 个里有 21 个「文件名」与「头像内容」不是同一个人
   （亚敏、克劳乌、克萝爱、露娜、岚、洛曼、玫勒赛德丝、索尔、雅卡泰丝、雷伊、雷奎姆洛、雷欧等，
   与对应官方头像的 ORB 内点为 0）。用错图当模板会连带把识别也带错。
2. 库里多出来的旧文件（`_2` / `_3` 重复件、`unknown_*`、与正确名重复的 OCR 错字件）
   一律移入 `heroes_pokedex/_obsolete/`，**不删除**。`library_names` 只扫一层目录，不会列进名单。
3. 重建 `meta.json`：只收库里确实有图的英雄，分类跟着英文名走。

### 第 7 步：验证

```
python -m pytest tests/test_hero_catalog.py tests/test_arena_hero_lists.py -q
```

两者全绿即视为未破坏界面契约。改完在界面上打开竞技场名单，确认新英雄出现且可勾选。

**另做一次一致性体检**（每次换头像后必跑）：逐个把库内 PNG 与该英雄的官方头像做 ORB，
内点 < 20 的即为「文件名与头像不是同一人」，必须清零。

```
python .reverse/work/_herodata/_audit_pokedex.py
```

2026-11-17 全量换官方头像后实测：**可疑 0**，仅蕾诺娅 / 黎洁特两名
epic7db 未收录者沿用原图。

⚠️ 换头像会改变识别结果。当时 `test_recorded_list_page_is_recognised` 与
`test_weak_match_is_reported_as_unknown_instead_of_guessed` 双双变红，查明原因是
**旧模板本身有错**：「安洁莉卡.png」并非安洁莉卡本人，导致真帧里两个格子的她被漏认。
换成官方头像后这两格对安洁莉卡模板内点 163 / 172、第二名仅 6 / 8，裁图目视亦确认。
据此订正了测试期望，原「弱证据」案例因前提消失改为盯空槽。
**遇到测试变红先查模板对不对，不要先去调阈值。**

## 四、判据与红线

- **不许按音译硬猜中文名。** 已实测会错：`Kane`＝该隐（不是凯恩）、`Nahkwol`＝落月（不是纳克沃尔）、
  `Robin`＝露彬（不是罗宾）、`Tori`＝兔菈玫（不是托莉）、`Leah`＝蕾娅（不是莉亚）。
- **国风命名的英雄不遵循音译规则。** `Nahkwol`（落月）、`Mei Lin`（梅铃）都属于此类，
  搜音译永远搜不到，必须靠技能特征或公告。
- **三元组不一致的一律不许入库**，宁可留空。
- **未收录分类的英雄照常列出、可勾选**，不隐藏、不猜一个分类填上。
- **不删除原文件。** 与正确名重复的 OCR 错字文件移入 `heroes_pokedex/_obsolete/`，
  `library_names` 只扫一层目录，不会把它们列进名单。

## 五、常见坑

- 公告**不写属性与职业**（写法是「5星英雄『X』登场！」），属性职业在另一段
  「角色属性&职业：寒气属性、战士」。按句式抽名字拿不到分类，分类要走 wiki 或 epic7db。
- 同一英雄官方存在两种写法：未知的开拓者佛里蒂丝 / 未知开拓者佛里蒂丝；
  波涛裂痕艾碧拉 / 波涛的裂痕艾碧拉。以**首次出现的公告写法**为准。
- 同前缀英雄容易串：`Ken`（肯恩）与 `Kane`（该隐）是两个人；
  `暗行者席德` 与 `流浪王子席德` 是两个形态，不要合并。
- epic7db 是社区站，会滞后一到两周。连续数月零新增才视为停更，漏收一两个不构成换源理由。
- **epic7db 尚未收录的新英雄**（例：2026-09 的黎洁特 Lisette、2026-10 的蕾诺娅 Renoa）：
  中文名从公告取，属性职业改查 `https://epic7helper.com/hero/<英文名小写>`，
  页面标题即形如 `Lisette — Epic Seven Light Soul Weaver`。用
  `tools/add_hero.py --zh … --en … --job … --element … --stars …` 一条命令补齐，
  **不要**留在「未收录分类」里。
- 图鉴库里若出现与已有英雄重复的旧头像（OCR 错字造成，例：斗目 / 浓育 / 督导），
  用 ORB 与该英雄逐一比对即可确认身份：**内点 100 以上、且第二名的 3 倍以上**即为同一人
  （实测斗目=血剑卡琳 176、浓育=夏率 335、督导=教母 146；不同人则在 40~60 且拉不开差距）。
  确认后移入 `_obsolete/`，不要删除。

## 六、脚本与产物位置

| 用途 | 路径 |
|---|---|
| **新增一名英雄（日常）** | `tools/add_hero.py`（取图 + 查重 + 写分类表） |
| **刷新分类表 / 查外部库新增** | `tools/refresh_hero_meta.py`（`--check` / `--write`） |
| 抓公告列表与正文 | `.reverse/work/_herodata/_fetch_notices.py` |
| 按句式抽英雄名 | `_parse_notices.py` |
| 用基础名反查公告 | `_search_notices.py` |
| 三元组 + 拼音配对 | `_pair_by_group.py` |
| 公告名录反查校对 | `_crosscheck_official.py` |
| 落库（改名 / 补图 / 重建 meta） | `_apply_roster_update.py`、`_finalize_roster.py` |
| 识别重复头像 / 未收录身份 | `_identify_orphans.py` |

中间产物：`e7_notice_list.json`（公告清单）、`e7_notice/*.html`（公告正文）、
`avatars/*.webp`（英文名头像）、`_official_names.json`（公告官方名录）。
这些都在 `.reverse/work/_herodata/`，不进仓库。

回滚：`_rename_log.json` 记录了改名与新增；改动前的完整图鉴库备份在
`.reverse/work/_herodata/pokedex_backup_20261117/`。
