# 装备制作 `craft_equipment`

## 这条路线在游戏里干什么

在钢铁工坊用讨伐材料制作装备：先选讨伐（决定材料与可制作的套装范围），再选部位
（六个部位之一），把「制作次数」切到 10，点「制作」并确认，一批做出 10 件。
做完可以整理（出售或萃取不要的），也可以直接重新制作。

一次运行只做一个「讨伐 × 部位」组合。轮数默认 20 轮，合计 200 件，可在界面次数框调整。
制作消耗该讨伐的材料与金币；出售与萃取不可撤销，勾选范围由游戏内「快速选择」的预设规则决定，
本助手不判断装备价值。

## 页面链路

```
大厅 →（右上角蓝四格）快捷菜单 → 第 3 行第 3 列「钢铁工坊」
     → 左侧竖排第 1 个图标「制作装备」
     → 顶部 5 个讨伐（双足飞龙 / 魔像 / 报丧妖 / 阿吉玛纳克 / 卡戴斯）
     → 中央 6 个部位（上：武器；右上：项链；右下：戒指；下：鞋子；左下：铠甲；左上：头盔）
     → 右侧「制作次数 1 | 10」+ 绿色「制作」
     → 确认弹窗「制作装备10次」（正文「要消耗下列制作材料，制作装备10次吗?」）
     → 制作动画（约 0.5~1 秒）→ 结果页「制作完毕」
     → 不整理：点「重新制作」直接弹回确认弹窗
     → 整理：点「整理」→ 底部换成工具栏 → 「快速选择」→「出售」/「萃取」
        → 二次确认弹窗 → 回到工具栏 →「重新制作」
```

⚠️ 与 2026-11-17 需求口述的三处差异，以实机为准：

1. **「整理」不是另一个页面**：它把结果页底部换成工具栏（快速选择 / 出售 / 萃取 /
   确认 / 重新制作 / 取消），标题仍是「制作完毕」。因此「整没整理」靠工具栏判据区分，
   不靠标题。顺带一个后果：整理态的「重新制作」在右下方，未整理态的在同一排偏左，
   两个位置不同，必须用两张模板分别定位。
2. **制作次数默认是 1**：进页面时「1」是白底选中态，材料数字显示 400 / 210,000
   （10 件量）只是沿用上一轮的记忆。不确认就点制作会做成 1 件。
3. **游戏内名字与攻略站不同**：国服写「报丧妖」「阿吉玛纳克」「卡戴斯」，
   不是「女妖」「阿兹马纳克」「凯德斯」。界面文案与代码注释一律用游戏原文。

## 判据为什么这么设计

判据配置在 `games/epic7/evidence/craft_equipment.py`。

- **「未选部位」只认底部提示**：`home_hint`（「请选择要制作的装备。」）在选中部位后
  消失（同区域分数从 0.9966 掉到 0.1058），是全套判据里最干净的一条。
- **「已选部位」只认绿色制作按钮**：`craft_button` 随部位出现，未选部位时不存在。
  两者用 forbidden 互斥，不靠「有没有高亮」这种弱判据。
- **标题不能单独判页**：`result_title`（「制作完毕」）在三种确认弹窗下仍能拿到 0.9902
  （半透明遮罩不压暗标题）。所以三种弹窗排在判定顺序最前，结果页与整理态都把
  `confirm_hint` / `sell_confirm_hint` / `extract_confirm_hint` 写进 forbidden。
- **两种确认弹窗靠正文区分，不靠按钮**：出售弹窗的右按钮是蓝「确认」，萃取弹窗是
  绿「萃取」，两者位置相同。判定用各自的正文锚点（「确定要出售选中的」/
  「要萃取装备以获得装备根源吗?」），按钮只作点击目标。
- **件数不进模板**：出售正文是「确定要出售选中的N件道具?」，N 随勾选数量变，
  所以 `sell_confirm_hint` 只裁前半句。同理制作确认弹窗的标题含「10次」/「1次」，
  判据用正文里固定的「要消耗下列制作材料」。
- **档位判据的阈值取 0.90**：`qty_10_selected` 这个区域在结果页能拿到 0.8468
  （装备网格的白块），0.90 让两侧余量都不低于 0.10。
- **讨伐与部位用固定坐标点击**：两处图标位置由界面布局固定，来源页身份由
  「制作页」判据把关；点完部位后必须看到绿色「制作」按钮才继续，坐标点空即安全停止。
- **数量档位用固定坐标补点**：控件位置固定（画布 (1857, 797)），点完由
  `qty_10_selected` 复核白底是否落在「10」上，没落上就再点，仍有界。

## 危险边界

- 「制作」与「出售/萃取」都不可撤销。制作只在确认弹窗的正文锚点与绿色按钮同时命中时
  发一次；出售与萃取只在「快速选择已勾选」之后发一次，二次确认弹窗必须认出对应正文。
- 状态机用两个独立闩锁记录「本轮已点确认」「已点出售/萃取」，点击被吞掉也不重发；
  真被吞掉由转场验收超时报故障并落诊断。
- 档位不是 10 时不许直接制作；点完「10」必须复核白底位置。
- 未登记页面（金币不足 / 材料不足 / 背包已满以外的陌生页）一律安全停止并落整屏诊断，
  不以「等超时」收场。
- **装备背包已满**走全局弹窗通道（`global_popups.EquipmentBagFullTemplates`）：
  认出文案后点「取消」关掉弹窗，在 `Runtime.blocking_popup` 留一句话，主循环按
  `EquipmentBagFull`（`ResourceExhausted` 的子类）正常收工，退出码 2，不记失败。
  素材一套（正文 + 「取消」），2026-11-18 按真机帧重做；PC 后端按同名覆盖规则回落同一套，
  认不出就退回「未登记页面」安全停止，不会乱点。
- 开局接力只落在制作页（未选部位 / 已选部位）；确认弹窗、结果页与出售/萃取弹窗紧邻
  不可逆动作，刻意不接力。
- 本路线默认**不放行 PC**：素材来自模拟器当前客户端帧，PC 后端按路线跳过并在日志点名。

## 现行事实

- 2026-11-17 模拟器整屏夹具覆盖制作页、五个讨伐、六个部位、
  两档数量、确认弹窗（三种入口）、结果页、整理工具栏、快速选择后、出售弹窗、
  萃取弹窗与出售后态。
- `--live --confirm RUN --max-cycles 2`（不整理）退出码 0：导航三步全绿
  （大厅 1.000 / 快捷菜单 0.997 / 装备制作页 1.000），两轮各 10 件，
  日志「完成一遍 cycles=2 件数=20」，收尾回大厅。
- `--live --confirm RUN --max-cycles 2`（出售）退出码 0：整理 → 快速选择 →
  出售 → 确认 → 重新制作，两轮各 10 件，收尾回大厅。
- `--live --confirm RUN --max-cycles 2`（萃取，魔像 + 戒指）退出码 0：换讨伐与
  换部位都生效（日志「选「魔像」讨伐（顶部 2/5）」「选「戒指」」），
  整理 → 快速选择 → 萃取 → 确认 → 重新制作，两轮各 10 件。
- 开局接力实测：把游戏停在「制作页（已选部位）」再启动，日志
  「开局=接力 页面=制作页（已选部位） 落点状态=保持 动作=跳过回大厅与路线导航」，
  不重新导航，直接 10 件、退出码 0。
- 收尾回家的退化路径：停在结果页时按 ESC 回制作页；**从制作页再按 ESC 在模拟器上
  无效**（12 秒无变化），`HomeReturn` 自动改走「快捷菜单 → 酒馆」回大厅。
  这不是本路线的判据问题，回家流程本来就有这条兜底。
- 2026-11-17 22:03、22:06 两次 `--max-cycles 10` 各跑满 100 件、退出码 0，
  期间未触发背包上限（背包仍有空间），未出现误点与重复制作。
- 每次点「制作」后约 2 秒会打一条「结论待确认=UnrecognizedScreen」：
  制作动画与结果页淡入之间有一到两秒不在任何页面判据里。结论门槛要求两帧一致才采信，
  实测均为单帧、随后自动认出结果页。这是**观察噪音，不是失败**；若某天它变成两帧一致，
  会按「未识别页面」安全停止并落诊断，不会误点。
- 离线回归覆盖页面识别、黑屏停手、两轮计数、出售顺序、萃取确认框与游戏内名称。资源不足仍缺真机反例。[路线回归](../../tests/test_epic7_craft_equipment.py)

## 已知缺口

- **金币不足 / 材料不足没有真机帧**：制作时余额充足，无法触发。两者按未登记页面
  安全停止，不猜、不点。
- ~~装备背包已满缺可用素材~~：2026-11-18 已按真机帧重做，并**删掉旧的两张**
  （`global/pc/equipment_bag_full_message.png` 与 `_confirm.png`）。现在只有一套：
  `global/equipment_bag_full_message.png`（正文）与 `global/equipment_bag_full_cancel.png`（「取消」）——
  正例 0.9737 / 0.9718，四张无关帧最高 0.27 / 0.43。
  删除理由（同一帧实测）：旧正文 0.8426（只比阈值 0.82 高 0.023，图比实机小 1%，放大
  到 1.010 倍才是 0.9796）；旧按钮 0.7100（阈 0.85）—— 这条弹窗只有取消 / 整理 / 扩充
  三颗，旧图画的「确认」根本不存在，最接近的反而是「整理」，而那是会改用户背包的按钮。
  留着比没有更危险：PC 分支会静默拿到一张指错按钮的图。
  新变体先收集回归帧，按[共享视觉接入规则](../PC_TEMPLATE_MIGRATION.md)用来源、文本和可用按钮验收。
- **PC 客户端**：试点完成一次共享视觉制作。正式生产入口和整理、出售、萃取分支仍按
  [PC 迁移矩阵](../TODO.md#pc-迁移矩阵)逐项验收。
- 「快速选择」的筛选规则由使用者在游戏内维护，助手只点按钮、不读规则内容；
  规则配错会卖掉本不想卖的装备，这是刻意保留的边界。
