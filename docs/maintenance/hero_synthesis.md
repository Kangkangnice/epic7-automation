## 这条路线在游戏里干什么

把列表里多余的英雄当材料，喂给目标英雄刻印记忆、抬献身技能，顺手把用不上的英雄传送换资源。
**SSS 英雄一律优先保护、绝不拿去当材料**，普通英雄才进刻印；**合成吃材料、传送不可逆**，
所以认不准时宁可不点。逐个英雄翻到卡片看：是不是 SSS、刻印按钮有没有红点，该刻印就进
刻印页加材料，认不出就安全停下等，不猜着继续点。

## 页面链路

```
英雄列表 → 英雄详情（翻卡）→（刻印记忆页 → 加材料 → 合成结果）/（传送页 → 选择 → 确认 → 传送结果）→ 回英雄列表 …
```

- 合成结果、传送结果、SSS 警告都是**覆盖层**，必须先确认关掉，才轮到点底下的材料卡。
- 「英雄已达最高献身技能级别」那条黄条不是识别故障，是**业务结论**：这个英雄不能再刻印，
  命中就换下一个英雄。
- 「获得奖励」这类弹窗也可能被全局弹窗守卫抢先关掉；归属（谁去关）决定业务后果，见判据节。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **判据锚点一律必需、不许可选，补充提示不许混进证据画像**：本路线没有「可选判据模板」。
  缺一张模板要在加载期、构造期、证据校验、护栏测试四道关当场起不来（fail-closed）。
  因为覆盖层判据一旦「可选」而缺图，`_xxx_present` 会返回 False，「覆盖层必须先关掉」这道闸
  **静默失效**，程序会去点覆盖层底下的材料卡 —— 合成消耗材料、不可逆，日志却一行异常都没有。
  「已达最高献身级别」那颗是**可选字段**（PC 无图即 None、模拟器恒 False），只能挂在模板对象上、
  在状态机分支里判，不能登记成证据画像里的判据锚点（那样会被 `_assert_anchor_templates`
  判「判据锚点缺模板」直接起不来）。⇒ **可选模板最恶的形态是「判据整个不存在」**；
  **判据不许静默降级**；**判据型模板不许可选，可选的是补充提示而不是判据本身**。
- **SSS 徽记一锚点、多长相 = 多候选 × 多尺度**：同一枚徽记，前排展开大卡与后排被压暗的小卡
  是两种画法（多候选，任一过阈取最高分），还会因排在材料列表第几位被画成不同大小（多尺度，
  只向下扩、没有更大的画法）。⇒ 靠「逐尺度匹配」排除「同一枚徽记换个尺寸就落进死区、判据
  沉默」的对象；**排除掉「压暗 / 变灰」这条直觉** —— `TM_CCOEFF_NORMED` 对整体乘性亮度不变，
  变暗在数学上解释不了掉分，真正原因是尺寸。候选模板与主模板同等必需，空候选组也要被拦。
- **不做「落死区才展开多尺度」的省时优化**：那样会在「单尺度量到 NON_SSS、换尺度其实过阈」
  时**漏判**，而漏判 NON_SSS 会让 SSS 材料卡被 `_find_up_card` 当普通材料点下去（不可逆）。
  宁可慢，不可漏。传送页同样只验「当前高亮行」，禁止把别处卡的 SSS 当成目标。
- **判据沉默必须出声**：多尺度只救已知档位，万一还有更小的档落进死区，`next_action` 返回 None
  ⇒ 不打分、不报警、日志空白 ⇒ 刻印页干等到超时。所以刻印页等待要打心跳（带评级 / 最高分
  依据），依据与「刻印页超时」共用同一份；首次进入等待还要留一张现场帧供回放。
  ⇒ **判据沉默的形态是「什么都不做」**，它不走到任何超时分支，正常重试路径上一张图都不留；
  **`score=None` / 认不出是关键信号，必须单列「未知」，绝不并入别的结论**。存帧失败绝不许打断主循环。
- **转场验收不许依赖「这一帧认出动作」**：「材料进槽了没有」原来只从动作对象取值，这一帧判据
  沉默就生不出动作 ⇒ 值取不到 ⇒ 转场永远判不出成功 ⇒ 重试到超时。修法是机器每帧现算观察值
  （槽位 / 行号是**纯色块统计，不依赖任何判据模板**）写进独立通道，取不到动作对象才回落。
  ⇒ **判据与观察值两条独立通道都能出货**，这是修复成立的前提；默认 runner 只看页面身份、不认
  动作，因为「材料进槽」是同页内容变化才需另找依据，错在把取值通道绑在动作对象上。
- **转场契约开关：先对齐字段、再打开**：开关读基类的 `in_page_evidence`，本路线原来用自造的
  `source_observation`。名字不齐时开关开着也管不到同页动作 —— 它们的 `target_pages` 里塞了
  当前页，检查「`target_pages` 或 `in_page_evidence`」时被前者满足 ⇒ **形式合规、实质没用**：
  本页永远在集合里，分不出「点了没生效」和「点了生效」。⇒ **打开开关前先确认「路线自造的
  证据字段名」和「开关读的字段名」是不是同一个**，否则开关只是变好看；开关与豁免二选一。
- **PC 红点靠模板锚点、不靠几何口径**：列表「刻印记忆」红点，PC 静止态画得更大更靠外、还连着
  一条同色斜带，按模拟器收紧的几何口径（内缩规则）会把它裁掉 ⇒ 时认时不认，而颜色完全合格。
  ⇒ 放宽搜索区 / 加「像素够多就当有红点」必然误报（战斗 / 剧情 / 大厅同坐标有整片暖色 UI），
  **模板匹配才是能证伪的图形锚点**。修法是 PC-only 模块包装 `_red_dot_present`，原判据为真直接
  短路、PC 图只补漏；判据图缺失直接抛错、**绝不静默降级成「没红点」**；公共业务文件一个字节不改。
  反向护栏在 `tests/test_hero_synthesis.py` 与 PC 专项用例。

## 危险边界

- **材料不可逆、SSS 优先保护是用户拍板的业务口径**：认不出是不是 SSS 就绝不点材料卡；覆盖层
  判据必须齐全（不许可选，缺了会静默失效点到覆盖层底下）；传送前有独立确认页、阶段单向推进，
  确认后不再发确认动作。全局危险动作与拦截机制见 [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
- 认不出 / 超时 → 安全停止留证，不猜着继续点，见
  [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)。
- 不许把判据模板改回「可选」、不许为了过单张截图降阈值、不许改回自造证据字段名。
