## 这条路线在游戏里干什么

月光剧场的奖励每周刷新、是存量（别人先领完就没了），所以放进日常里每天顺手看一眼。
从大厅进「支线故事」点开剧场，一幕一幕看剧情、领奖励，中间可能自动触发战斗；
有免费额度就免费看，免费没了就花手上已有的门票接着看，但**绝不用金币买门票**。
一趟跑完的标准是「往右换不动了」——那一刻免费额度和手上门票都处理完了，收工回大厅。

## 页面链路

```
大厅 → 支线故事页 → 剧场选择页（横向海报，中间放大为当前剧场）
  → 分集页（点「进行观览」）→ 观览指南弹窗 → 剧情页（点字幕推进，中途可触发战斗）→ CLEAR → 分集页（领奖）→ 剧场选择页 …
  → 没有免费额度时：分集页点「进行观览」→「使用剧场门票」→ 看完一幕撤
                 或 →「购买剧场门票」→ 只点取消、撤出并记下「券用光」
  → 右边没有海报 ⇒ 收工
```

- 入口在支线故事页，复用导航锚点 `lobby_side_story`；进列表页先**归位到最左**再往右扫。
- 「入场」「进行观览」「观览指南 / 使用门票 / 购买门票 / 获得奖励」这些弹窗都盖在底页上，判定顺序见下节。
- 剧场之间轮转、每个剧场美术不同，是这条路线判据的主要难点；跑路线时顺手把各剧场的分集页 / 战斗帧攒进样本目录，属于附带动作、绝不影响主线。

## 判据为什么这么设计

每条写的是「靠哪一维排除外观同类、语义不同的对象」，不是调阈值的经验值。

- **入口绿 F 不再当闸门（用户后来本人改口径）**：原来「入口没有绿 F 就停止」和「免费打完还能用门票接着打」自相冲突——免费额度用完后入口就没 F 了，而那时恰恰是门票该上场的时候。⇒ **入口 F 只写日志、不拦路**，改看「这一幕有没有 Free / 券还没确认用光」这一维；删掉旧分支后，收工理由只剩「往右换不动」一条，别再写「入口无 F」当收工理由。
- **进列表页先归位到最左**：游戏记住的是「上次看的那个剧场」，只往右扫会把左边的免费整个漏掉；「到最左」与「到最右」用同一口径（中间海报不再变）。归位**不能靠「改状态 + 返回空帧」推进**：`preview()` 的 `finally` 会把状态整体回滚，那种写法永远推进不了；要返回「已到最左」、调用方当帧接着往下处理。⇒ 凡「靠改状态推进」的新逻辑都要分清幂等（宽限等待是安全的）与状态变更。
- **「进行观览 / 入场」都通向花钱，三道防线一道不许拆**：门票不足点「进行观览」会弹「购买剧场门票（金币）」确认框。① 页面判定顺序把购买弹窗排第一（它盖在分集页上、底页元素仍可见，晚判一步就会去点「进行观览」）；② 只点取消，命中点固定在左侧、测试钉着「点不能落到购买上」；③ 业务闸门只放行「有 Free」或「还没确认券用光」的剧场，没有任何证据时绝不点入场 / 观览。取消后必须置放弃标记 + 把这个剧场登记进跳过名单：不置会「取消 → 又点观览 → 又弹购买」，不登记会「退回列表（Free 角标还在）→ 又入场 → 又弹购买」——**两条都是死循环，而中间那一下会真花钱**。放弃走 `abandon-theater` 而非 `leave-theater`：都点左上返回、都不再进这个剧场，但只有后者算「完成一幕」，别合成一个动作（否则单轮上限会把「被劝退」当成「跑完一幕」）。
- **「进行观览」四个字走白掩膜**：那是白字压在绿色渐变上，亮度随按钮状态变；原样比会把「只是把分集页压暗」的观览指南 / 购买 / 获得奖励弹窗也命中（白字仍然像）⇒ **raw 会破掉页面排他性**。换白掩膜后这些负例全不命中。这条与下面「返回键」是同一个理由：转掩膜不只是「认得出」，更是「**在弹窗上认不出**」。
- **两个门票弹窗处理相反，身份只能靠标题判**：「购买剧场门票」（花金币）只点取消，「使用剧场门票」（花已持有的券）点确认花掉；两者版式几乎一样，**按钮只当点击锚点**，拿按钮判会把「花金币」和「花券」串掉（会真花钱的错）。这条原来根本不存在：弹窗不在页面表里 ⇒ 状态机以为还在分集页、反复重试点观览、最后判死，就是「没长眼睛」。连带三条：① `watch-episode` 的出口必须写全所有可能落点，少写一个、那一帧的动作会被整个吞掉、干等到超时；② 放弃之后不许再花——`_at_use_ticket` 开头先看放弃标记，置位后只走取消，哪怕这一帧确认按钮清清楚楚（否则「确认定位不到 ⇒ 点取消」的兜底会被下一帧的「确认优先」反过来花掉券）；③ **`target_pages` 宁可多写落点、绝不少写**，多写只是提前一帧算转场完成、下一帧照样按真实页面决策，少写会永久发不出去；唯一禁区是**不能把来源页写进目标**（那会让「点了个寂寞」被判成转场完成）。
- **字幕点击点必须避开「进行观览」**：剧本结束画面变回分集页，「进行观览」正好压在原来的字幕区上。⇒ 选一个「分集页是空白区、剧情页仍在字幕框内」的点，别用「复用支线故事」带过来的箭头坐标（那一帧本路线同位置是空白、没有箭头）。同理 CLEAR 过场**不会自己消失、必须点一下**（静等会白烧超时才失败）；**复用只复用判据、没复用点击点**，判别一律以「CLEAR」字标为准、别照着「这帧应该有 »»」去找（会把真 CLEAR 帧判成异常画面）；CLEAR 是一次性过场，**别给它加画面指纹**，好让「同名动作点几次没换页就判死」的账照常生效。
- **点字幕连着点会撞主循环同名动作账**：主循环对同名动作有「一定时间内只点一次 / 点几次没换页就判死」两条规矩，一集剧情要点几百次。⇒ 动作名带**画面指纹**（画面一变就换名字 ⇒ 账当新动作重新记＝真的在推进；画面真不动 ⇒ 名字不变 ⇒ 照常判死，安全边界不变）；稳定签名**只认动作族**（指纹不能进稳定签名，字幕逐字打出来两帧天然不同，签名跟着变就永远凑不齐、一次都点不下去）；指纹里**必须挖掉会闪的 ▼**（闪烁动画算进去「每帧都在变」恒成立、`点了没反应` 永远发现不了），但**字幕框必须算进去**（同一背景连说十句时只有字幕在变，那就是真推进）。
- **「右边没海报了」用海报区域的画面差，不用整帧逐字节**：版面还在动（海报有光效）时逐字节判等不成立；换海报与「同一剧场两次点开」的画面差相隔很远，用区域幅度这一维能分开。
- **「进过剧情」当场记账，不等橙点**：分集页「刚入场」和「看完了」长得一模一样（观览按钮亮、没有橙点），只在领奖时记账 ⇒ 橙点一没认出就判「没看过」、再点一次观览、白看一遍把免费额度烧光。⇒ 「看到剧情页」是能被画面证明的强证据，「橙点亮了」只是它的下游结果；记账后分集页只可能「有橙点就领奖、没橙点就撤」，永远不会点第二次观览。
- **橙点判「能不能领」，不用下载按钮本身**：按钮在「可领 / 已领」两状态下长得一样，拿它判会反复领。橙点是脉动动画（模板在动画低点会认不出 ⇒ 奖励漏领是业务失败，不是「不会误领就行」）⇒ 改成「模板 **或** 固定色相的橙色像素计数」双判据（脉动只改透明度、不改色相，像素计数不受影响），再加一段刚看完一幕的宽限期；**像素区域必须小**（放大后战斗里的橙色特效会把判据顶穿），**宽限用秒不用帧**（轮询间隔可调、测试有假时钟，按帧等会撞超时；为和状态超时共用一根时间轴注入时钟）。
- **▼ 与返回键裁到控件本体，换剧场 = 换美术资源**：这条路线在多个剧场间轮转、每个剧场的海报与分集页背景都不一样，**只要模板里含背景，就一定会在某个剧场随机失效**——▼ 半透明过渡态撞上角色手臂换底图、返回键撞上亮蓝天背景，是同一个病的两次发作，不是两个独立 bug。⇒ 新增模板先问「**这块背景在这个控件出现的所有页面上都一样吗**」，答不上来就裁到控件本体；别改成「降阈值」（那是把「认不出」换成「认错」，误认成剧情页的代价是在别人页面上点字幕点）。`entry_card` 裁不了：模板整块就是入口卡片的人物宣传立绘、没有控件本体可留，它是入口的唯一判据、游戏换图标就进不去，只能重裁，**别为了保险把区域放宽成整屏**。
- **不排他的控件只当点击锚点**：`back_button` 在所有页面左上都是同一个返回控件，到处都命中 ⇒ 只用来「按哪儿」，从不当页面判据（模板中心还正好是点击坐标，重裁后才落在箭头中心）。`ticket_confirm` 的分离度靠**区域窄**不是阈值：观览指南弹窗那枚「确认」是同一个蓝色控件，放宽区域就会贴着阈值命中它、而它正好在确认位置 ⇒ 宁可定位不到（走「取消 + 放弃剧场」兜底）也不放宽。
- **战斗判据走投票制，不靠共享判据**：共享的「战斗场景」判据要求左侧行动列白占比高，而本路线行动列是彩色圆头像、从判据层面就永远不成立 ⇒ 补三枚自有战斗 HUD 锚点、过半才算战斗帧；**共享判据留着**（将来它在本路线修好也照常生效），别改成只信自有锚点、也别把票数降到一（单枚在过渡帧会飘）。这三枚锚点有的仍含会变的血量数字 / 具体角色头像，换队伍换敌人就可能只剩一票 ⇒ 待补不同队伍的样本后改成只看固定 UI。
- **战斗交接与刷图路线三处不同**：① 战斗是剧情自动触发、没有开战按钮 ⇒ 走「停在本帧无动作就移交」；② 战斗打完通常**回剧情页继续说话**、不是回结算页 ⇒ 「打完」的判据名单里必须有剧情页的 ▼（漏了就判成未知画面、干等报假故障）；③ 不在战斗画面时一律报「未知」、不给自动开关坐标——剧情页右上角那三个灰掉的图标凑得出「手动」形状，真按坐标点下去点的是**暂停键**、剧情当场卡住。「战斗场景」单独用也不可靠（亮色立绘与白闪过渡帧会骗过它，且误报只出现一瞬、存证帧抓不到）⇒ 必须加「且没有 ▼」那道与门。
- **停在剧情页上收尾 = 一定回不了大厅**：剧情页右上角没有「跳过」，找「跳过 ›」的导航器在这页恒判不出、按 ESC 也不吃 ⇒ 只要在剧情页收尾必然失败，跟判据质量无关，病灶在**收尾路径**。⇒ `MoonlightRunner._close_out` 收尾前先把字幕点完（有上限、只认推进字幕这一支、绝不点别的），离开剧情页后立刻回家；这**只覆盖正常收尾**，异常退出走主流程那条、拿不到本路线状态机，仍会报「回首页失败」但真因照旧往外抛。
- **PC 差异每个「整行文字」控件单独量**：共享模板的字号在 PC 上既不保证一样大、也不保证差在小比例缩放能兜住的范围里 ⇒ 按真机帧重裁 PC 覆盖图，别再靠调阈值。**花钱级排他必须守住**：「使用剧场门票」的 PC 标题绝不能命中「购买剧场门票」（认错就会点确认把金币花出去），靠的是「使用 / 购买」前两个字字形完全不同。分集页只有一颗判据、在 PC 上会被画大一点 ⇒ 登记缩放兜底，**不能改走 raw 口径**（raw 在三张压暗弹窗帧上会破排他性）。⇒ 以后凡是「点了个换页动作、画面也对、但转场就是不成立」的现场，先量目标页那颗唯一判据的原样分数、再比白字包围盒。

## 危险边界

- **花金币买门票：明令禁止**（用户「不支持用金币买就行」）。靠上面「三道防线」拦住误点，任何情况下「购买剧场门票」只点取消。
- **花已持有的门票：允许**（用户拍板「花掉那张券」），但**一个剧场只花一张**——同一时间每个剧场只有一集可看，下一集是时间锁、券也打不开，一幕看完就撤。
- **券花光了仍要继续扫免费**：用户明确「如果券花完了，免费的还没打完，肯定还继续打」。`_tickets_exhausted` **只拦「无 Free 的剧场」**，有 Free 的照进照打；别把它改成「券没了就整条收工」，那会违背口径。入口绿 F 从改口径起只当日志提示，不做停止条件。
- **怎么知道券用光**：认「购买剧场门票」这个弹窗（游戏亲口说没券），**不读票数**——分集页底部那枚数字含义未实证，按规矩不能拿猜测当判据。
- **取消 / 放弃之后不许再花**：置位后只走取消，哪怕确认按钮清清楚楚；也不再进这个剧场，避免「取消 → 又入场 → 又弹购买」的死循环。
- 认不出 / 超时 → 安全停止留证，不猜着继续点，见 [TRANSITION_CONTRACTS.md](../TRANSITION_CONTRACTS.md)；全局危险动作与拦截机制见 [SAFETY_MATRIX.md](../SAFETY_MATRIX.md) 第一节。
- **通用教训**：判据要能证伪（拆掉它测试得变红、别留空护栏）、模板不含会变内容、别为过单张截图降阈值或放宽区域、反向验证要成对且先证明用例跑起来、**凡是会导致漏领 / 卡死的识别缺口一律当 bug 修掉、不留在表里当「可接受风险」**。
- **事故编号只作索引**：历史编号沿用下来、并不按时间对齐，还有插队的小节号；改文档时别为讲清顺序重排或复用编号，更别重复。
