# 企鹅批量购买 `penguin_purchase`

## 这条路线在游戏里干什么

在圣域「精灵之森」右下角打开成长祭坛，从「企鹅巢穴」分组购入企鹅。一轮购入
单次上限 50 只，默认 10 轮合计 500 只；次数框表达的是轮数，可调整，不按企鹅只数计算。
数量不是 50/50 时先点「最多」补齐，复核到 50/50 才购入；跑满轮数按现有路线惯例返回大厅。
购入消耗红叶且不可撤销；本项不领取精灵之森三行产出，也不处理圣域内其它建筑。

## 页面链路

```
大厅 → 圣域主页（沿用圣域收菜的导航链）
     → 精灵之森（点右下角「成长祭坛」，不点「领取奖励」）
     → 成长祭坛弹窗（四列商品同屏：企鹅蛋 102 / 下级精灵之花 170 /
        上级 850 / 最上级 4,250 红叶；顶部「企鹅巢穴」「精灵之泉」为分组标签）
     → 数量弹窗（1/50 显示单价 102；点「最多」后 50/50 显示总价 5,100）
     → 「企鹅成长完成！」弹窗 → 关闭 → 回到成长祭坛，一轮结束
```

⚠️ 与 2026-11-15 需求登记时的口述有两处差异，以实机为准：

1. 「成长祭坛」点开后**不是**两级页面（分类列表 → 企鹅巢穴购买页），而是同一张弹窗
   里并排四列商品；「企鹅巢穴」「精灵之泉」是分组标签，实点不换页。
2. 数量弹窗的报价随数量变化：1/50 是单价 102，50/50 是总价 5,100；购入后红叶
   余额减少 5,100，与 50 × 102 一致。参考实现记录的「5,100」由此得到核实。

因此「先选企鹅巢穴」由页面判据落实：必须同时认出分组标签与第一列 102 红叶报价，
且购买按钮的搜索区域只罩第一列。不给一个点了不换页的标签单发动作，否则主循环
会把它判成「没转场」反复点击。

## 判据为什么这么设计

判据配置在 `games/epic7/evidence/penguin_purchase.py`，模板与真机夹具张数见
[`docs/STATUS.md`](../STATUS.md)「按路线的现行事实」。

- **购买四锚点**：点扣费按钮前必须同帧具备弹窗标题「购买商品」、资源类型（红叶图标）、
  固定报价、确认按钮「购买」，外加数量 50/50。任一缺失即安全停止，不猜、不点。
- **数量与报价配对**：`quantity_50_50` 判满额，`full_price`（5,100）与 `unit_price`（102）
  判报价。1/50 帧认单价、50/50 帧认总价；两颗价格锚点同区域互斥，不能只认「有价格」。
  全库反向验证里满额帧单价 0.8248、初始帧总价 0.7520，故两颗状态判据阈值取 0.85 / 0.90，
  正例均为 1.0000。
- **同名不同义的排除**：精灵之森三行材料里也有「企鹅巢穴」；成长祭坛后三列也是绿色
  「购买」按钮；宠物商店另有绿色「购买」与 500 / 1,000 报价。页面判据用「购买商品」
  标题 + 物品名 + 「最多」按钮 + 确认按钮四颗固定锚点，后三列商品不进第一列的搜索区域，
  宠物商店帧在本路线全部锚点上均为零命中。
- **半透明遮罩**：数量弹窗帧上成长祭坛标题仍 0.91、完成弹窗帧上仍 0.86，精灵之森标题
  在弹窗帧上仍 0.83。因此页面组合不靠单颗标题，判定顺序固定为
  完成弹窗 → 数量弹窗 → 成长祭坛 → 精灵之森 → 圣域主页，并给森林页加禁止项。
- **「点击关闭」不排他**：通用控件在别的奖励弹窗上可到 0.9876，只作已确认完成弹窗后的
  点击目标，不参与判页。
- **圣域主页入口复用**：`sanctuary_home_row` 直接指到 `templates/sanctuary/forest_row.png`，
  与收菜路线共用同一颗锚点，不另存副本。

## 危险边界

- 扣费按钮「购买」每轮只发一次：状态机在动作发出瞬间置购买闩锁，点击被吞掉也不重发；
  真被吞掉由转场验收超时报故障并保存诊断，绝不刷成两次购入。
- 完成弹窗「关闭」同样只发一次。
- 「最多」是幂等按钮，允许有界补点（上限 3 次）；补点后仍不到 50/50 即停止，不购入零散数量。
- 报价与数量不配对、红叶不足、出现未登记页面一律安全停止并落整屏诊断帧与证据分数，
  不以「等超时」收场。
- 开局接力只落在圣域主页 / 精灵之森 / 成长祭坛；数量弹窗与完成弹窗紧邻扣费动作，
  刻意不接力，照旧从大厅重新导航。
- 本路线默认**不放行 PC**：素材来自模拟器当前客户端帧，PC 后端按路线跳过并在日志点名，
  其余勾选照常执行。

## 现行事实

- 2026-11-15 模拟器实机逐页采帧，10 张整屏夹具覆盖大厅、圣域主页、精灵之森、
  成长祭坛、数量弹窗两态、第二轮数量态、完成弹窗与两类反例。
- 真实购入一轮后红叶余额减少 5,100；第二轮打开数量弹窗仍是 50/50、5,100，
  证实游戏记住上一轮数量。
- `--live --confirm RUN --max-cycles 1` 完整链路退出码 0（含半路接力命中圣域主页），
  日志「完成一遍 cycles=1 企鹅=50」，收尾回大厅。
- `--live --confirm RUN --max-cycles 2` 连续两轮退出码 0：第一轮补点「最多」，
  第二轮沿用 50/50 直接购入，日志「完成一遍 cycles=2 企鹅=100」，收尾回大厅。
- 2026-11-15 22:11 使用者填 20 轮实跑：前 10 轮正常购入 500 只，第 11 轮起助手不再动作，
  画面停在成长祭坛、四列报价与第一列购买按钮都正常，45 秒后报状态超时。根因是轮数上限
  同时写在状态机（默认 10）与主循环（次数框 20）两处，状态机提前收工而主循环仍在等待。
  已改为开跑前由 Runner 把界面次数同步给状态机，**上限只由次数框决定**；
  这一条已上收为注册规范，见 [`EXTENDING.md`](../EXTENDING.md) 第 4 节。
- 离线护栏 26 条（页面识别、整轮动作顺序、购买不重复、报价配对、反例排除、
  转场契约、接力边界、轮数上限），循环决策层另有 15 条。
