# 主线补星 · 维护手册

> 本页只讲「为什么这么设计」和「改的时候别踩什么」。
> 素材张数、路线条数、放行状态一律看 [STATUS.md](../STATUS.md)，本页不写死数字。
> 施工流水与实跑日志见 [`CHANGELOG.md`](../../CHANGELOG.md) 与项目交接记忆；
> 已知缺口集中在第六节与 [`docs/TODO.md`](../TODO.md)。

## 一、这条路线在游戏里干什么

把主线 Episode 里**没满 3 星**的小节补到满星。用户口径（2026-11-09）：

- 只补左列前 6 项：**第6时代 + Episode 1~5**。外传 Episode 与 Episode 6 **不补**。
- 满星的判定是「这一章的星数写成了 `A/A`」，不是「打过这一关」。
- 一轮 = 把 6 个 Episode 从头扫一遍，次数不可调（`cycles_editable=False`）。
- 体力走主线那套（`stamina.py`），不建第二套补体力流程。

## 二、页面链路

```
大厅 →「战斗」→ 关卡列表页（story_ready）
  └─ 底部左起第三个蓝色树状图标 →「选取Episode」面板（episode）
       ├─ 篇章卡片未满 → 点进去 → 小节列表（stage_list）
       │    └─ 没绿勾的小节 → 选中 →「准备战斗」→「选择队伍」→「战斗开始」
       │         → 战斗 → CLEAR → 结算确认 → 直接回小节列表 → 继续
       └─ 本章清完 → 点底部时间轴图标 → 回篇章面板
  六章扫完 → 收工
```

⚠️ **开场两步是强制的（2026-11-10 用户纠正）**：上面「关卡列表 → 点时间轴 → 选第 1 项」
以前写在文档里、代码却没做。旧实现把 `story_ready` 认成 `STAGE_LIST` 后直接找绿勾，
停在外传 / Episode 6 时会把不在补星范围内的关卡也打掉。现在 Runner 开跑先武装两步：
落在小节列表就先点时间轴回「选取Episode」；落在外层面板就先**显式点左列第 1 项**
（第6时代），然后才按前 6 项扫篇章。准备 / 结算页不再就地接力——认不出属于哪个
Episode，接着打同样会越界。

三条**容易想当然**的实测结论：

1. **横向翻篇章只能滚轮，拖拽完全无效**（曾试卡片上、两排空隙、时间轴线上，画面差 2.4~3.9）。
   向下滚 = 往右翻；这个能力在 `core/pc_window.py::wheel`，经 `core/runtime.py` 通道进入 Runner。
2. **关卡页按 ESC 直接退回大厅**，不是逐层退。回篇章面板要点**底部那颗时间轴图标**（和进来时同一颗）。
   左上角「< Episode N」箭头与篇章面板自己的返回箭头是同一控件（互命中 0.9965），当不了判据。
3. **打完一关点结算「确认」直接回小节列表**，没有主线那条 `next_stage`。

## 三、判据为什么这么设计

证据清单在 [`games/epic7/evidence/story_star.py`](../../games/epic7/evidence/story_star.py)，
状态机在 [`games/epic7/story_star.py`](../../games/epic7/story_star.py)。

| 判据 | 做法 | 为什么 |
|---|---|---|
| 页面身份 | `episode_title` / `stage_help`+`timeline_icon` / `battle_start` / 结算四锚点 | 结算页是半透明遮罩，**必须排在整页判据最前面**，否则会对着被盖住的按钮点 |
| 篇章满星 | 星标定位 + 斜杠左右两串数字的**形状互相关** | 满星必然写成 `A/A`；不识别数值，换个账号、换个位数都不用改。满星最低 0.829、未满最高 0.761，阈 0.75。切字符块前必须按行投影取最长连续段，否则卡片高光会把最右那个字撑宽，同字形从 0.99 掉到 0.59 |
| 小节满星 | 徽章右下绿勾，**两张模板** | 同一页里第 1 行那颗勾比其余大一圈，单模板只覆盖一种（曾漏判 3 个满星行） |
| 战斗 | 主线 `StoryStateMachine.observe_battle` + 本路线右上角 HUD 白掩膜补正 | ⚠️ **`battle_controls.py` 不要动**，共享判据的容差与亮度门槛一律不放宽。见下 |

### ⚠️ 战斗判据：一条已经被验证过的结论，别推翻它

[`PC_TEMPLATE_MIGRATION.md`](../PC_TEMPLATE_MIGRATION.md) §1 第 2 条写得很清楚：
**「战斗界面 —— 不用管，它和其它判据一样在 PC 上直接成立」**。主线在 PC 上跑通战斗，
正是这条结论的验证。

2026-11-10 排障时，我曾拿一张补星链路里的战斗帧（判 `battle_unrecognized`）
去改 `battle_controls.py` 的共享容差（30→35、白占比下限 0.08→0.05）。**这是错的**：
用一张帧怀疑一条被验证过的结论，而且改的是所有 PC 战斗路线共用的判据。
**已全部回退**，全库 452 张夹具的 `battle_scene_visible` 回到 27 张，零翻转。

**那张帧为什么判不出，2026-11-10 已定位**：客户端把整套 UI 画小约 3%，三项
共享读数同时擦边 —— 四格底座圆心上移 31 px（容差 30）、右上控制区白占比
0.065（下限 0.08）、左侧行动条 0.104（下限 0.12）⇒ 五项观察全假、监督等满
45 秒报 `battle_unrecognized`。它不是补星独有，而是这一档 UI 尺寸下共享判据
没有兜底；处理见下一节，**共享判据仍未动一行**。

### 战斗画面的本路线补正（2026-11-10）

按世界首领战的同款做法（`world_boss.py` 用本路线锚点补 `battle_visible`），
只给补星自己补一条证据：右上角那组固定图标 `? / ×2 / 自动 / 暂停`，裁自
07:50 那张失败帧，走**白掩膜**（亮背景、暗技能演出都成立），搜索区四周留
30~60 px 容纳 UI 位移。

- 尺度按 `SCALE_FALLBACK_STEPS` 逐档扫：另一档 UI 尺寸上原尺寸只有 0.80、
  扫描后 0.96。名单**不登记**进共享 `SCALE_FALLBACK_ANCHORS` —— 这颗锚点只服务
  本路线，登记会把全局名单和它的护栏测试一起拖进来。
- 分离度：真战斗帧 ≥0.9596，补星链路的非战斗页 ≤0.3137，阈 0.85；全库
  410 张可比夹具审计零冒牌（命中的都是同样带这组 HUD 的战斗 / 场景页）。
- **只在共享判据判不出、且帧有效时补正**；结算页与无效帧保持原结论，不许把
  「认不出」粉饰成「战斗还在打」。
- 边界：这组图标在迷宫探索页等场景里也有，但补星链路不会走到那些页面；判据的
  证伪范围就是本路线的「篇章面板 / 小节列表 / 准备战斗 / 结算」四页。
- 复核：全库 455 张夹具的 `battle_scene_visible` 仍是 27 张，**零翻转**。

回归夹具 `battle_scaled_ui.png` / `battle_dark_effect.png` /
`battle_after_skip.png` 与反向护栏（抽掉模板、去掉尺寸扫描都必须变红）都在
`tests/test_story_star.py`。

### PC 上「UI 画小约 3%」的正确解法

[`PC_TEMPLATE_MIGRATION.md`](../PC_TEMPLATE_MIGRATION.md) §2.4b 已记载这个现象，
规定的顺序是：**先换比对口径 → 再扫模板尺寸（`SCALE_FALLBACK_ANCHORS`）→ 都不行才补 `pc/` 图**。

本次 `episode_title` 在另一帧上从 1.0000 掉到 0.8040（阈 0.85）⇒ 整页判「认不出」。
当时的处理是补了第二张候选图 `episode_title_alt.png`（双候选，阈值不动，反例
关卡列表 0.638 / 准备页 0.518 都不命中）。**这属于「都不行才补图」那一档**，
但按规范更该优先试尺寸扫描——**下一位接手请复核是否改用 `SCALE_FALLBACK_ANCHORS`**，
别把补图当成通行做法。

**复核结论（2026-11-10）**：本次新增的战斗 HUD 锚点按 §2.4b 的顺序走了
「白掩膜换口径 → 尺寸扫描 → 才补图」，扫描只在本路线内做（见上一节）。
`episode_title` 的双候选已有正反样本验证，改成尺寸扫描要重验全部反例、
收益不抵风险，**本轮不动**；不要把补图当成通行做法这条仍然成立。

### 框架语义（踩过，别改回去）

- 主循环真正调用的钩子是 **`_perform_action`**（`runner_base.py` 第 185 行）。
  基类里还有个 `_click_action`，**全项目零调用点**，覆写它等于没写。
  滚轮 / 返回键的换发必须在 `_perform_action` 里。
- **`next_action` 返回 `None` = 宣布收工**，主循环立刻回家。
  「暂时找不到按钮」必须抛 `UnrecognizedScreen`，不能 `return None`。
- **模板文件必须同时登记进 `REGIONS` / `THRESHOLDS`**，否则 `evidence.atom()` 直接 KeyError。
- CLEAR 页那颗「>」是淡入动画元素，离线 1.0000、实跑中间帧够不到阈值。
  用页面内固定落点 `CLEAR_CONTINUE_POINT`，不拿它当模板。
- **星标派生的点击落点必须先验画布边界**（2026-11-10 12:21 实跑血的教训）：
  篇章卡片是横向轮播，右边缘那张常常只露出星标，`星标 + (150, 90)` 会落到画布外
  （(1909,505) ⇒ (2059,595)）。窗口层对此是**致命错误**
  （`拒绝在 PC 游戏渲染区外点击`），一句话把整条路线带走。
  更隐蔽的是：这种卡片的满星判据窗口也被画面裁掉了，读数**本来就不可信**。
  所以顺序必须是「先判落点在不在画布内 → 在才去读满星 → 不在就右滚把它露出来」，
  不许反过来先判满星再点。滚到头仍只有半张时走 `clamped_click_point` 兜底，
  **不许直接跳下一个 Episode**（那是静默漏掉未满小节）。

## 四、危险边界

| 危险动作 | 拦住误点的依据 |
|---|---|
| 点小节开打（消耗体力） | 复用主线 `stamina.next_stamina_decision`；叶子买到上限走 `StaminaExhausted` 干净收尾 |
| 滚轮翻页 | 落点在两排卡片之间的空白处，不落在卡片上（落在卡片上会点开它） |
| 全局动作次数 | `StoryStarRunner._MAX_ACTIONS = 200`，判据失灵时也不会无限循环 |

⚠️ **五步验收尚未走完**：11-10 真机已验「干跑 → 接力接管 → 连续 4 关完整闭环 →
按 P 安全停止」，但**六章扫完收工 / 资源耗尽 / 两轮 `--max-cycles` 未跑到**
（那轮在第 1 章里连打 4 关后主动停止，退出码 130）。见第六节与
[`SAFETY_MATRIX.md`](../SAFETY_MATRIX.md)。

## 五、现行事实

- 模板、夹具张数与 PC 放行名单：看 [STATUS.md](../STATUS.md)（由 `tools/gen_status.py` 生成）。
- 只有 PC 素材，在 `PC_ONLY_ROUTES` 里；模拟器跑会缺图，是**故意 fail-closed**。
- 桌面分组：按需（`GROUP_ONDEMAND`），次数不可调。
- 接力：只接**篇章面板 / 小节列表**；准备战斗 / 结算页刻意不接（认不出属于哪个
  Episode，接着打会越过第 6 项范围）。停在小节列表仍省掉「回大厅再进主线」那一趟，
  但开场两步照走（见第二节）。**不恢复遍历进度**：`episode_index` 从 0 重来，
  满星章节会被快速跳过。
- 状态：`episode` / `stage_list` / `prepare` / `results` / `done`。
