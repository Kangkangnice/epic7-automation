# PC 客户端接入指南

收到「把〈路线名〉移植到 PC」，从 [§3](#3-一句话移植到-pc) 开始。目标、例外预算及生产切换标准见
[跨端共享视觉契约](decisions/0009-universal-vision-contract.md)。已支持的组合以
[当前现状](STATUS.md) 为准，真机授权、采集和诊断走[实机验收手法](howto/live_verification.md)。

## 跨端一致的边界

PC 客户端与模拟器运行同一个游戏，页面结构和控件位置一致，业务代码不分叉；差异只落在
画面补边、模板渲染和窗口 I/O 三处。按 2026-11-03 至 11-10 的实跑记录（雷电模拟器 + PC 客户端，
简体中文、`1982×1132` 画布）：

- **共享模板直接可用**：认页面、认按钮默认走共享素材；只有实跑发现某页确实认不出，才补 `pc/` 同名图。
- **战斗界面判据在 PC 上直接成立**：主线与月塔已在 PC 上实跑通过战斗段，不需要平台分支。
- **滑动可用**：刷书签、骑士团捐赠、迷宫强化石三条已实机跑通；幸存者与主线补星的滑动在 PC 上尚未复验（见 §2.2）。
- **「认不出」不都是缺图**（2026-11-06 六条路线一次性推真机后的修正）：约三分之一是真缺图，
  另两类更常见 —— 判据命中了不可点的同类控件，或页面认得但落点名单没登记该页。先排除这两类再补图。

以上结论只对上述客户端与语言成立。换客户端版本、换游戏语言或改画布后需重新验证。

## 1. 跨端共用的画布和坐标

### 1.1 基准画布与坐标映射

游戏内容常用尺寸为 `1920×1080`。PC 校准客户区后，把内容放到 `1982×1132` RGB 画布的
`canvas[52:1132, 0:1920]`，上方留 52 像素，右侧留 62 像素。路线按统一画布的当前命中点发出动作，
PC 适配器负责把 `(x, y)` 换成客户区的 `(x, y - 52)`，再按输入方式换算窗口偏移。

### 1.2 截图口径与旧素材

现行真机帧保留顶部和右侧补边。旧的 PC 帧曾把 `1920×1080` 内容非等比拉满画布，比例和背景都不同。
排障先确认夹具口径。保全当前客户端完整帧和来源，使用仓库采集入口。详见[采图手册](TEMPLATE_CAPTURE.md)
和[旧素材的技术记录](https://github.com/Kangkangnice/epic7-arky-assistant/blob/9308cdf9b3625e847e7736d1debfc4186bd153f7/docs/PC_TEMPLATE_MIGRATION.md)。

### 1.3 三类证据不要混用

同一张画面在不同位置有三种用途，混用会把「能认出来」当成「能跑通」：

| 类别 | 位置 | 作用 | 判据 |
| --- | --- | --- | --- |
| 运行时识别素材 | `games/epic7/templates/<路线>/`，平台覆盖放同名 `pc/` 子目录 | 随程序加载，直接决定是否点击 | 紧裁、不含会变内容、裁自当前客户端真实画面；加载路径由 [template_paths.py](../games/epic7/template_paths.py) 解析 |
| 回放测试截图 | `tests/fixtures/epic7_<路线>/` | 离线回放与反例验收，程序不加载 | 保留当帧整屏与来源；用于证明改判据前后行为一致 |
| 实机验收记录 | `runtime_logs/`、`runtime_diagnostics/`、[安全矩阵](SAFETY_MATRIX.md) 的逐路线证据表 | 证明某个客户端、某个账号状态下真的跑完一轮 | 含起止页、真实业务结果、未覆盖分支；授权与留存口径见[实机验收手法](howto/live_verification.md) |

项目目标是**一套识别素材跨端使用**：PC 侧优先复用模拟器素材，只在确实无法共用时补 `pc/` 覆盖图，
新增平台专属模板不是默认做法。判定边界：一张 PC 截图只证明该帧能识别，不证明路线兼容；
路线兼容性要按 §3 的步骤验证转场与业务结果。

## 2. 真实差异清单

### 2.1 窗口 I/O 与权限

模拟器使用雷电的 ADB 输入通道。PC 由 [Epic7PcWindow](../core/pc_window.py) 按目标窗口和进程定位，
使用 BitBlt 取客户区图，进入路线前确认画布和权限。截图全黑、被最小化、窗口选错、输入受权限限制时，
先验证适配器和前置环境。按 [当前现状](STATUS.md) 核对实际验证过的客户端。

### 2.2 滑动、滚轮和 ESC

PC 默认后台点击。滑动、拖拽、滚轮和 ESC 走前台输入，动作完成后尽力还原原活动窗。
关闭桌面设置「不占用前台」可切到前台。PC 的滑动用 `SendInput`，手势的实际时长和距离需要用
目标画面确认。截图有证据但输入没送达时，保留同一动作的前后帧和通道信息，排除权限、焦点和控件遮挡。

### 2.3 现有 PC 覆盖路径

现行生产入口仍由 [template_paths.py](../games/epic7/template_paths.py) 解析共享图和已有同名 PC 图。
现有部分代码另有少数已知的平台搜索区或阈值差异，归入 [待验证与缺口](TODO.md)。
迁移时检查实际加载路径。已有覆盖先保留原行为，验证共享方案通过后按路线切换。

### 2.4 局部 UI 尺度

基准画布相同，局部 UI 控件仍可能跨版本或会话改变物理尺寸。先测多个稳定锚点，确认属于画布误差、
局部缩放还是布局变化。默认使用受限多尺度找候选，仍按当前帧的落点、前景和控件状态验收。

### 2.5 世界首领战的历史样本

世界首领战已有 PC 局部素材，历史上的补图记录可作为字体、描边和结构验证的测试来源。
共享视觉试点用标题和控件共同验收页面，灰态控件可证明页面已经进入；点击要验证启用态。
旧素材及原分数见 [既有迁移记录 §2.5](https://github.com/Kangkangnice/epic7-arky-assistant/blob/9308cdf9b3625e847e7736d1debfc4186bd153f7/docs/PC_TEMPLATE_MIGRATION.md)。

### 2.6 定位失败发生在哪一层

按窗口与截图、模板表示和搜索区、前景与业务语义、输入及转场顺序排查。分数低时保留当前帧、区域、
模板版本、相似候选和拒绝原因。页面存在而按钮未启用，继续走安全停止或已登记分支。

## 3. 一句话移植到 PC

**用户指令**「把〈路线名〉移植到 PC」。执行者从 `ModeSpec` 和现有测试找到路线、选项和业务完成条件，
复用模拟器路线，从验证一直做到该路线的 PC 放行检查。沿用用户的路线配置，实机验证限制为一个业务轮次。
有多个会花费不同资源的分支时，使用已授权的分支和范围。仅在实机缺登录、资源或授权时需要用户介入，
执行者直接采集程序需要的现场帧。

### 模拟器端一次准备

新增路线时将页面锚点、当前可用的按钮证据、必要的文字和搜索区域、预期目标页及完成证据随模拟器实现一起交付。
同名按钮通过来源页和业务条件区分。为正常流程及最接近的危险反例保留自动回放，例如灰态、遮挡、资源不足、
同名取消或没有本轮支付上下文。后续移植直接复用这些素材、证据和状态机。参见 [新增路线约定](EXTENDING.md)。

### 默认执行顺序

| 步骤 | 检查与通过结果 |
| --- | --- |
| 1. 建立隔离运行 | 用现有共享素材构建路线、导航、全局弹窗和回大厅模块。临时目录物理排除所有 `pc/`，验证加载路径。配置 PC 窗口采集与输入权限，确认归一画布和当前点位映射有效。 |
| 2. 先回放再点击 | 用已有双端完整帧核对页面、动作、当前落点、转场和业务完成。检查已知遮挡、同名、禁用、无资源与异常弹窗。PC 缺帧时先只读观测或走已确认的无消耗步骤自动采集。支付前检查当前客户端的数量、价格及按钮。 |
| 3. 用公共规则解决差异 | 先诊断窗口、画布、匹配表示、页面和输入哪一层失败。画法变了用公共尺度、低通、色彩或受限 OCR。布局变了用页内区域和当前图标位置。真有新页面时按业务含义补共享转场和反例。局部修复后用刚保存的帧回放，确认通过再执行受影响部分。 |
| 4. 一轮实机闭环 | 由该路线的实际业务计数限制为一轮。从大厅开始，自动执行到结果或入账并返回大厅。保留开始页、消耗前后、结果及回到大厅的证据。测试过程中不得重复发起已提交的购买、制作或开战。 |
| 5. 接正常入口并验证 | 对已验收的路线，让命令行和桌面入口使用同一套共享策略。检查正常入口仍加载零 PC 覆盖图，模拟器原有回归通过，PC 放行和生成状态与验收范围一致。终端输出说明是否首轮通过、实际覆盖哪些分支和有哪些现场阻塞。 |

**移植开发的目标是首轮连续实机通过。** 「一轮」指从大厅开始到业务成功和回大厅，无人工补点、改配置、
换图或中途续跑。干跑、分段实跑和离线回放分别记录。若首轮阻塞，执行者用自动诊断回归对应缺口，
保护已发出的不可逆动作。批量路线的轮次衔接先回放，有额外实机风险时再覆盖相应分支。

### 公共 OCR 如何复用

试点使用同一个本地 RapidOCR，从指定区域提取文字、置信度和文字框。
路线声明业务上要核对的文字和页面条件。引擎统一处理放大和原尺寸回退。字体描边、抗锯齿、光效或角标让模板
得分下降时，文字仍可能说明这是哪个控件或哪一个报价。按钮没亮、当前页面不对、证据冲突或目标消失时禁止点击。

| 实测差异 | 同一规则的处理方式 |
| --- | --- |
| 宠物小屋图标被礼包角标盖住 | OCR 确认「宠物小屋」，用同一菜单格中经过位置核对的图标执行点击。文字标签和实际热区可以分开。 |
| PC 显示「可免费领养 1/1」 | 核对领养页面、免费标记、剩余额度和当前领养按钮。原模拟器模板仍可作正例。 |
| 首领战「确认」被放大后漏读 | 用公用引擎原尺寸回退，保留同一文字与位置校验。其它路线使用相同回退。 |
| 企鹅与装备有相似的购买或制作确认框 | 核对来源页面、本轮发起记录、配置对应的数量和报价，再从当前帧确定提交按钮。 |

### 何时可以判断迁移通过

- 新增 PC 运行模板、平台专属阈值和分叉状态机均为零。PC 验收截图可作为本机回放和诊断证据。
- 已声明的主流程通过连续实机验收，正常入口与模拟器回归通过，未覆盖的分支按实际范围发布。一次自然资源耗尽只能验收对应的安全停止分支。
- 扩大公开稳定支持时，按[路线稳定版验收](howto/route_acceptance.md)分别提交雷电、STOVE 或 Steam 的实机记录。

### 已验证的范围

2026-11-19 在实机试点中，隔离了 PC 覆盖目录，复用了模拟器侧的 46 个已标注样本。
PC 验证了宠物免费领养与商店检查、企鹅当次 50 只购买和装备当次 10 件制作。
世界首领战和竞技场的分段验证仍按实际覆盖范围记录。以上是试点证据，正式共享入口接线、
双端连续闭环和放行以 [当前现状](STATUS.md) 与各次审阅记录为准。

## 4. 采集与放行入口

- **用户现场**按 [排错手册](TROUBLESHOOTING.md) 留存脱敏诊断。应用默认在本机保存。
- **开发接入**按 [新增路线指南](EXTENDING.md) 提供共享证据和反例，复用 [页面转场契约](TRANSITION_CONTRACTS.md)。
- **历史夹具**和已存在的 PC 覆盖迁移期间可用于回归。采集时不允许拉伸桌面截图、由模糊帧猜点或把模拟器原图装作 PC 实机证据。
- **放行**按 [治理规范](../GOVERNANCE.md) 记录后端、客户端版本、起始页、真实业务结果与未覆盖分支。
