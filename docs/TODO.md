# 自动化稳健性待办

本文件记录六条路线的转场稳健性、日志证据和 PC 迁移工作，供后续开发者和 Agent 接续。它不是缺陷清单：没有实机证据的内容只标记为风险或待验证，不写成已确认 Bug。

## 证据等级

- **已具备**：代码和自动化测试能直接证明；若涉及真实画面，另需实机验收记录才能声明实机支持。
- **部分具备**：已有检测、重试或诊断，但尚未形成完整的来源—目标—业务成功契约，或缺少足够实机证据。
- **待实证**：当前只能提出风险，需要补充固定截图、录屏、运行日志或可复现测试。

## 优先级

- **P0**：资源安全、误点防护、支持范围真实性。
- **P1**：转场闭环、重试语义、日志和诊断证据。
- **P2**：复用、文件拆分和长期维护成本。

## P0：安全与支持声明

- [ ] **六条路线危险动作逐项列出 fail-closed 条件**。重点包括英雄材料/传送、竞技场资源消耗、远征进入、剧情与狗粮的体力消耗。验证：关键模板缺失、冲突或 `UNKNOWN` 时，测试证明不会执行危险点击。
- [ ] **建立实机支持证据表**。每条路线分别记录模拟器固定样本、dry-run、1 轮实机、2 轮实机和异常恢复结果。验证：只有证据齐全的组合才能在 README 标记“支持”。
- [ ] **PC 后端保持开发中声明**。当前 `templates_pc` 仅代表候选证据，不代表任何路线已完成迁移；英雄合成 PC 动作目前未启用来源/目标转场契约。验证：逐路线通过 [PC 模板迁移清单](PC_TEMPLATE_MIGRATION.md) 后再改变声明。
- [ ] **不可逆动作防重复**。对传送、确认消耗等动作增加事务边界或等价证据，避免目标已经成功但回执识别失败时再次点击。验证：构造“动作成功、确认帧丢失”的回放测试。

## P1：转场、日志与诊断

- [ ] **剧情**：按 [页面转场契约](TRANSITION_CONTRACTS.md) 审计导航、进入关卡、准备战斗、结算和下一关；先补固定样本和失败日志，再决定是否改代码。
- [ ] **竞技场**：检查所有目标状态是否要求稳定帧；对刷新、选择对手、进入战斗、结算分别记录来源和目标。单帧误判目前是审计风险，不是已确认缺陷。
- [ ] **远征**：把预览阶段的隐式 `expected_state` 映射成可打印的动作目标，失败恢复时记录原事务目标。验证：日志能够解释每次状态变更和重试。
- [ ] **狗粮**：补齐页面切换与循环完成契约，验证“点击未生效”会重试且不会提前增加轮次。
- [ ] **助手自动**：定义无需导航时的合法启动页集合，以及“已接管/已结束”的业务证据；启动页为 `UNKNOWN` 时保存诊断并安全停止。
- [ ] **英雄合成**：持续收集相同外观副本的点击前、动态峰值、稳定后帧与 ROI 数值；日志必须把“观察到运动”“转场确认”“英雄事务完成”分开。
- [ ] **统一失败诊断最小集**：最终全屏、来源裁剪、目标裁剪、关键分数、动作名、尝试次数和原事务目标。验证：仅凭一次诊断包可以回答失败发生在哪个契约字段。
- [ ] **统一日志词汇**：`动作候选`、`执行点击`、`等待确认`、`转场未确认`、`转场确认`、`业务成功`、`安全停止`。验证：禁止在目标证据前输出“成功”。

## P2：复用与维护

- [ ] **评估共享 `TransitionContract` 数据结构**。先从两条路线提取重复字段和测试，再决定是否加入公共层；不要为了单次使用提前抽象。
- [ ] **让独立 Runner 逐步对齐公共语义**。竞技场和远征无需立即改继承关系，先统一动作日志、目标保留和诊断格式。
- [ ] **评估拆分 `hero_synthesis.py`**。该文件已经较大，但拆分前必须先有状态机与关键事务的回归测试。候选边界：观测、材料安全、传送事务、切换证据；本轮不做重构。
- [ ] **形成可复用的固定样本回放夹具**。同一份页面样本用于识别、决策、转场确认和日志断言，减少“测试检测器但没测试业务闭环”的空档。
- [ ] **文档随代码验收**。新增模式或后端时，同步更新 README、用户手册、架构、转场契约示例、路线矩阵和 PC 迁移表。
