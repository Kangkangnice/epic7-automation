# 开局接力覆盖面

本文回答一个问题：**每条路线的每一个环节，是不是都能「停在那儿就从那儿接着跑」？**

截至 2026-10-07 的答案是：做到了 **8 / 12 条路线**（2026-09-24 是 7 / 9，2026-09-25 加了迷宫强化石，
2026-10-07 加了社区签到）。还没做的四条是狗粮、英雄合成、活动挂机、社区签到 —— 理由写在
`games/epic7/modes.py::RESUME_EXEMPT` 里，模块加载时自查，漏表态直接 import 报错。

⚠️ **2026-09-29 起本文件不再维护「环节数 / 能接力」的总分分母**（旧口径写的是
「36 / 58 个可停靠环节」，而每加一条路线分母就要重数一遍，改漏了没人会发现）。
下面那张覆盖矩阵才是事实来源。

（2026-09-18 修正：英雄合成的 10 个状态里有 2 个是**等待状态**、不是画面，原先按 10 计入环节数是错的，分母由 47 改为 45。）

2026-09-24 起，接力不再只是「文档上说要做」：三条卡点都落到了代码上
（表态 / 接线 / 判据），见 `docs/TRANSITION_CONTRACTS.md`「接力契约」与
`tests/test_resume_contracts.py`。下面是**覆盖面**的事实记录。

审计方式（只读，不点击不截图）：逐条路线枚举状态枚举 → 用真的 `detect_resume_point` 跑该路线**每一张夹具**（含 navigation 夹具）→ 再全库跑 `battle_scene_visible` 交叉核对。脚本与输出在 `runtime_logs/_audit_resume.py` / `_audit_out.txt`、`_audit_shop_resume.py` / `_audit_shop_resume_out.txt`（刷书签判据全库负例扫描）、`_audit_hero_anchors.py` / `_audit_hero_anchors_out.txt`（英雄合成逐帧锚点覆盖）、`_audit_knights_cross_route.py` / `_audit_world_boss_cross_route.py` 与各自 `_out.txt`（骑士团捐赠 / 世界首领战的接力判据全库负例扫描）（本机产物，不入库）。

## 先分清两件事

| | 含义 | 现状 |
| --- | --- | --- |
| **运行中能不能处理这个页面** | 循环跑到这一页时，状态机的 `next_action` 认识它、知道点哪 | 各路线基本都做了 |
| **开局能不能从这个页面接力** | 你人工把游戏停在这一页，然后启动助手，它从那一步接着跑 | **11 条路线做了**（其余 4 条见 `RESUME_EXEMPT`，另 2 条无导航自动豁免；逐条见下方覆盖矩阵） |

这两件事很容易混，用户看到的症状也可能来自后者。典型例子：竞技场的**免费刷新确认页**和**友情券赠送页** —— 运行中状态机都会正确处理，但你把游戏停在那一页再启动助手，它不认识，会一路受控返回大厅从头重走。

## 逐路线明细

### 主线 story — 8 / 8 全通

关卡入口（`story_ready` / `prepare_battle` / `watch_story`）、队伍准备（`start_mission`）、助手选择（`select_team`）、跳过确认（`skip_confirm`）、剧情播放（`skip`）、战斗中（`battle_scene_visible`）、结算类（`results_confirm` / `clear` / `reward`）、通关提示与额外奖励与下一关入口（`complete` / `bonus_reward` / `next_stage`）全部能接力。局内接力不按 `Back`，直接交战斗监督等结算。

### 远征 expedition — 12 / 12 全通

远征主页、通缉传单列表、难度选择、难度确认、准备战斗（营火）、队伍选择、战斗中、战斗结果、公开招募结果、招募确认、招募后返回、返回主页。
另外导航链上的**战斗菜单 / 赛季菜单 / 远征主页**三级都能接力（`entry` 落点，跳过它之前的转场）。

### 月塔 tower — 7 / 7 全通

能接力：月塔主页（入场）、楼层列表（选择队伍）、准备战斗（队伍页）、战斗中、**三选一装置页**（未选卡 / 已选卡都认得出，判据相同）、结算页（下一层）、**战斗失败结算页**（2026-11-01 补：认出即按 `FloorTooHard`「这一层打不过」正常收工，退出码 2 —— 那一帧上状态循环一个状态都认不出，不显式接就会回大厅重打同一层再输一遍）。

⚠️ 仍缺一环：**「阶段选择」屏**（每月首次进场弹一次，2026-10-08 起按用户要求暂不实装，遇到走「认不出」安全路径）。已拍板的行为是「按游戏默认选中的阶段直接确认」，等取到实机帧补判据后接进接力。

判定顺序 `_TOWER_RESUME_ORDER`：主页 → 三选一确认 → 结算页 → 准备战斗 → 楼层列表 → 三选一 → 战斗中。
与远征有两处**实质差异**：

1. **三选一装置页刻意不接** —— 它是「已承诺选择」的中间态，接管进去只会重复点卡。
   所以 `CARD` 在接力顺序里排在 `CARD_CONFIRM` **之后**（先判确认态），且
   落到三选一页时**只认「已选卡」那条路**、不点新卡（会覆盖用户已选好的那张）。
2. **赛季菜单是跟远征共用的一屏** —— 所以 `TOWER_RESUME_PAGES` 里**不能**放
   `season_menu`：放了的话，停在赛季菜单时启动月塔会接力进去，但那一屏对月塔来说
   只是**路过**，真正的落地页是 `tower_home`（靠月塔卡片标题锚点认，与远征主页判据不同）。
   `tests/test_tower_resume.py` 有一条专门钉这个「共用页不进白名单」。

⚠️ 若停在**别的路线的战斗**里启动月塔，与远征同源：那一局会被监督完再原地接着往下走。

### 竞技场 arena — 6 / 6 全通

能接力：竞技场模式选择（额外入口）、对手列表、对手详情、队伍选择、战斗结果页、结果确认中、战斗中。

一轮六个环节（列表 → 详情 → 队伍 → 战斗 → 结果 → 确认中）**全部接得住**，外加「模式选择」这个额外入口。
判定顺序：模式选择（靠 `observed_page`）→ 对手详情 → 队伍选择 → 对手列表 → 战斗结果页 → 结果确认中 → 战斗中。

**2026-09-16 补齐了最后两步**，两个坑都是「判据」问题、不是「锚点」问题：

| 补的是 | 当年的障碍 | 怎么解决 |
| --- | --- | --- |
| **战斗结果页** | 识别它的 `confirm` 锚点**与远征结果页共用** —— 实测远征 `result.png` 上这个锚点拿 0.9448，高过 0.90 阈值。没有排他证据就接力，会把远征的结算当竞技场的接着跑 | 裁了三个竞技场专有内容锚点：`result_rating`（「积分」面板标题，**胜负都会出现**）、`result_victory`（「VICTORY」横幅，只有赢才有）、`result_defeat`（「DEFEAT」横幅，只有输才有，2026-09-25 从真机输局帧补）。在 `arena.result_arena` 页里与 `confirm` 组成合取判据，阈值 0.80。⚠️ 2026-09-25 真机复测：`result_rating` 真机只有 0.38（失效），两个横幅才是实际依据 —— victory 赢帧 0.8761、defeat 输帧 0.9871~1.0000，全库 227 张夹具里除结果页外最高分别 0.2724 / 0.3828。**少了 `result_defeat`，人停在输局结算页时接力会认不出来**，退回「回大厅 → 重新导航」 |
| **结果确认中** | 状态机的 `_STATE_TEMPLATE` 里没有这一状态的锚点 | 它其实就是段位提升弹窗，`find_rank_promotion_confirm`（绿箭头 + 确认按钮 HSV 双锚点）早就认得出（实测 0.9993 / 1.0000），只是此前没接进接力链 |

两个「运行中会处理、停在那一页不接力」的弹窗：**免费刷新确认页**、**友情券赠送页**。它们是弹窗而不是环节，不列入环节数，也不打算接力。

另有两条不放进环节数、但已经接住/显式排除的画面：
- **买票弹窗压住的队伍页**：`battle_start` 在弹窗下仍然可见（0.9996），会被误判成队伍页，接力过去直接点到购买按钮上，故用 `no_ticket` 显式排除。
- **局内**不在状态机里认（4 张局内实时帧只有 1 张能靠 `auto_off` 认出来），改由 `detect_resume_point` 用 `battle_scene_visible` 兜住。

### 世界首领战 world_boss — 6 / 6 全通（2026-09-24 补齐）

6 个可停靠画面全部接得住：世界首领战主页、选择辅助队伍、配置队伍、战斗中、战斗结算、战斗级别奖励。
另外**导航链中间站**骑士团主页也接（`entry` 落点，跳过「回大厅 → 进骑士团」两级）。

| 要点 | 做法 |
| --- | --- |
| **判据** | 直接用状态机自己的 `observe_page`（六个锚点 + 右上角「跳过」+ `battle_scene_visible`）—— 与运行期**同源**，不另定阈值、不加新锚点 |
| **局内** | 落 `BATTLE`，`WorldBossRunner` 靠 `resumed_from` 跳过状态机、直接把这一局交给战斗监督（不按 Back、奖励不丢） |
| **结算页的歧义** | 同一个「战斗结果」画面分两支（点确认弹奖励 / 点确认回主页），靠 `state is LEVEL_REWARD` 分岔，而接力只看到一帧 ⇒ **保守取「奖励还没领」那一支**。敢这么取的前提是：两支点的是**同一个按钮**（(1730,1036)），猜错也只多一次无效点击、下一帧状态机自己拨正 |
| **不接力** | `RESULT_CONFIRM`（不是画面，是内部记号）、行动力不足弹窗（不可逆）、骑士团两个弹窗与 `lobby_with_knights` |
| **负例扫描** | 全库 226 张（`runtime_logs/_audit_world_boss_cross_route.py`）：本路线 18 张里 13 张认得出。跨路线命中 19 张 = 17 张**别的路线的战斗帧**（`battle_scene_visible` 本来就认任何一条路线的战斗画面，story / expedition 同样如此）+ 2 张**别的路线的骑士团主页**（同一张真页面，不是误判）。**零真实误命中** |

⚠️ 局内判据分不出「这是哪条路线的战斗」：停在别的路线战斗里启动世界首领战，会先把这一局监督完再接着跑
（2026-09-26 之前是「监督完再回大厅重新导航」，那条恢复通道已随用户「回家就是结束」的拍板整段删除）。
这仍比老流程好 —— 老流程在局内会卡在「未知画面等待唤醒」直到返回大厅预算耗尽、退出码 1。

### 骑士团捐赠 knights_donation — 3 / 7（2026-09-24 补齐）

7 个可停靠画面里接了 3 个：骑士团主页、骑士团活动·资源支援、骑士团活动·每周任务。

4 个刻意不接，**理由是三类不同的东西**（写在 `knights_donation._RESUMABLE_STATES` 上方）：

| 画面 | 为什么不接 |
| --- | --- |
| 请求支援弹窗 / 支援资源确认框 | **不可逆**：点确认要消耗掉当天的唯一额度。接力到这一页等于助手替你按下确认 |
| 获得奖励弹窗 | 判据**不排他**：`reward_title` 在 `epic7_hero/reward_popup.png` 与 `epic7_story/bonus_reward.png` 上同样成立（实测），接力过去会按骑士团弹窗的坐标点到别人的弹窗上 |
| 骑士团活动（页签未识别） | **没有正例**：11 张夹具没有一张判成它，全库扫描也没有跨路线误命中。判据没在真帧上验证过就不接 |
| （弹窗的通例） | 弹窗本来也**不需要**接：回大厅那一下 Back 会先关掉它，下一帧就在底页接管，效果一样更安全 |

| 要点 | 做法 |
| --- | --- |
| **判据** | 状态机自己的 `observe_page`（与运行期同源） |
| **不拨状态** | 本状态机**每帧重判页面**，拨了下一帧就被覆盖，只会制造假象 |
| **负例扫描** | 全库 227 张（`runtime_logs/_audit_knights_cross_route.py`）：本路线 11 张全部判得出；跨路线命中 4 张 = 2 张 world_boss 的骑士团主页（**同一张真页面**，不是误判）+ `epic7_hero/reward_popup.png` 与 `epic7_story/bonus_reward.png`（**真误命中** ⇒ 所以奖励弹窗不接） |

### 迷宫强化石 labyrinth_stone — 15 / 17（2026-09-25 完整链路）

16 个可停靠画面里接了 15 个：战斗菜单·一般页、迷宫列表、迷宫详情页、准备战斗页、开场剧情、
迷宫房间、地图页、传送确认弹窗、认不出标题的双按钮弹窗、商人房、商店页、迷宫内战斗、
暂停菜单、放弃确认框、右上角快捷菜单。

| 要点 | 做法 |
| --- | --- |
| **判据** | 状态机自己的 `observe_page`（与运行期同源），不另定阈值 |
| **停在迷宫里** | `detect_resume_point` 顺手 `mark_entered()` —— 否则回到迷宫详情页会被当成「还没进场」，又点一次「选择队伍」把人再送进迷宫 |
| **传送确认弹窗** | 接，但接上去**一律按取消**（没有 `teleport_armed` 就不是本路线叫出来的传送，而传送要花 3 士气） |
| **不接 购买确认框** | 点下去就花钱，而接力只看到「停在某个购买框上」这一帧，**认不出这一行买的是什么**（万一是你自己点的「强化拳套」）。宁可回大厅重走一遍 —— 与骑士团捐赠「不可逆弹窗不接」同一条规矩 |
| **不接 大厅** | 本路线的终点，认不出来才对 |

### 圣域收菜 sanctuary — 2 / 3（2026-09-29）

三个可停靠画面里接了两个：**圣域主页**（`sanctuary.home`）与**精灵之森**
（`sanctuary.forest`）。状态枚举里的第四个值 `FINISHED` 不是画面，是「本轮已收工」的记号。

| 要点 | 做法 |
| --- | --- |
| **判据** | 状态机自己的 `observe_page`（与运行期同源），不另定阈值。本路线的页面识别是**纯锚点**、不依赖状态机上下文 ⇒ 开局只有一帧也判得出来 |
| **不拨状态** | 本状态机**每帧重判页面**，拨了下一帧就被覆盖，只会制造「日志说拨到了 A、实际画面是 B」的假象 |
