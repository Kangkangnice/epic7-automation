# 失败诊断包与排查流程

本页供维护者接收和分析运行失败证据。使用者按故障排查的步骤保留现场和提交脱敏材料。[故障排查](TROUBLESHOOTING.md#提交有效问题现场)

桌面任务以运行失败结束（退出码 1）时，助手在数据目录的 `reports/` 生成本次诊断包。用户强行结束任务时跳过自动打包。[生成入口](../desktop/worker.py)

## 二、包内结构

| 路径 | 内容 |
|---|---|
| `README.txt` | 提交方式与隐私处理说明 |
| `report.json` | 版本、后端、输入通道、退出码、失败路线、失败动作、Top 分数、日志与画面清单 |
| `investigate.md` | 阅读顺序 |
| `logs/` | 失败路线的日志（本体与一份轮转）、外层进程日志 |
| `frames/` | 失败画面；证据目录（名称见 `report.json` 的 `failure.evidence_dir`）内为 `evidence.json`、`source.png`、`target.png` |
| `config/` | `run.json` 运行条件、`environment.txt` 版本与系统信息 |

截图复用路线实际采集的游戏画面。识别失败或进入已接入的重试分支时，暂存截至该刻的最近 5 张；恢复后释放这份暂存，继续跟踪下一次故障。未经过这些分支而直接抛错时，取抛错前最后 5 张。取图不足 5 张就保留已有的数量。每日编排以本次首条失败为准，回大厅和后续路线不会覆盖它。

整屏图按采集顺序编号，文件名含本机采集时间。原始条目总量超过 10 MiB 时，整屏图转 JPG 并保留全部帧。含日志的 ZIP 可能超过 10 MiB。`reports/` 保留最近 10 份自动包。

生成器会对文本中已知的用户目录和账号名做替换。分享前仍按安全政策检查截图及文本，确认敏感信息已移除。[安全政策](../SECURITY.md)

## 三、维护者处理顺序

先取一页结论，再按顺序读包：

```bash
python -m auto_game_unified.tools.triage_report <诊断包路径>
```

工具输出版本、退出码、失败路线、失败动作、分数与阈值对照、画面与日志清单。
完整字段见包内 `report.json`。

1. **定性结束类型。** 对照实际业务回执、资源和最后画面。退出码提供线索，验收结论按业务标准判断。[路线开发与验收](howto/route_change.md#一次启动只有一个结论)
2. **确认失败路线与页面。** 查看 `failed_route`、`first_error` 和 `window_reason`，然后按 `frames` 清单从早到晚看。最后一张是留证时最近一次成功取图，取图本身失败时尤其要注意这两者的时间差。旧包缺少留证原因时，对照文件名和路线日志核实。
   - 如果动作前后多张帧逐字节相同，先区分游戏画面冻结和取图通道重复返旧帧，再按页面判据定位。社区竖屏取图见[竖屏通道](../core/portrait.py)。
3. **读分数。** `top_scores` 来自终止诊断的识别证据，按分数降序。重试前截图与终止诊断可能相隔多次尝试，证据目录名含终止诊断时间。
   - 分数略低于阈值：判据边缘，检查画质、缩放与比对口径。
   - 分数显著低于阈值：页面不符，或模板已随游戏改版失效。
   - `observed=true` 但页面仍判错：排他性不足，检查同页其他锚点是否被误认。
4. **看时间窗。** 在 `logs/epic7_<路线>.log` 中定位最后一次成功动作到第一个
   失败动作之间的记录，区分「点不动」与「转场未完成」。外层日志的
   `事件=结束` 一行给出退出码和最后输出。
5. **核对当前规则。** 查对应路线的维护手册、待办和相似反馈，理解有哪些行为是有意限制。
6. **复现和回归。** 用现场正例和最接近的反例先验证旧行为，再从实际入口核对修复。按影响面选择测试。[按改动选测试](../CONTRIBUTING.md#按改动选测试)
7. **记录结论。** 将故障、改动、验证和未覆盖范围写入 Issue 或 PR。需要更新的业务规则写回维护手册，缺失证据写入待办。[项目治理](../GOVERNANCE.md#资料放在哪里)

## 四、结论记录格式

```text
短码：
病根：
定性：页面改版 / 模板失效 / 状态机路径 / 时序 / 环境
证据：evidence.json 中 <atom> 分数 <score>，阈值 <threshold>
改动：<文件与动作>
验证：<红测试名> / 反向验证 <复现方式> / 回归 <范围与结果>
```

「定性」一项只能选一类。跨类时以最先触发失败的那一层为准，其余作为加重因素
记录，不并列。

## 五、证据边界

工作进程在成功取图前就失败时，自动包可能只有日志和运行条件。旧版或原生崩溃可另查已有日志与手动导出的材料。命令行直接运行路线时，已捕获的故障时间窗和路线日志保存在该路线诊断目录的 `last_failure.zip`，下一次故障会替换它。
