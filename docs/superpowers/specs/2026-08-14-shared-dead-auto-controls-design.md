# 第七史诗公共阵亡自动控件识别设计

## 背景与根因

竞技场实跑在 `2026-08-14 18:39:23` 和 `18:48:21` 两次以 `battle_unrecognized` 停止。两次战斗此前均已记录 `auto-confirmed`，失败画面仍在正常战斗，但阵亡角色的右下角自动槽位由蓝色变成红色。

当前共享分类器要求四个自动槽位的底部全部为蓝色。任意角色阵亡后，这个条件不再成立，分类结果持续为 `TRANSITION`；竞技场适配器因此不再暴露 `battle_visible`，45 秒未知页面计时到期后安全停机。心跳不是触发原因：监督器约每秒截图并识别，心跳只每 30 秒输出一次日志。

## 目标与范围

- 主线、竞技场、远征共用同一个 `AUTO / MANUAL / TRANSITION` 战斗控件分类器。
- 自动槽位允许存活蓝色和阵亡红色任意组合。
- 技能动画遮挡控件时保持 `TRANSITION`，不使用“非手动即自动”的否定判断。
- 保持现有约每秒采样、连续两帧确认、动画/未知画面最多 45 秒和自动按钮最多点击两次的监督规则。
- 不调整模拟器、不增加 OCR、不增加模式专用阵亡模板。

## 公共分类规则

公共模块 `games/epic7/battle_controls.py` 只观察右下角固定区域，不依赖战斗背景。

### AUTO

四个固定横向槽位都必须具有明确颜色证据：每个槽位可以是蓝色存活底座，也可以是红色阵亡底座。现场样本支持使用蓝色占比 `>= 0.40` 或红色占比 `>= 0.25` 作为候选门槛。

同时至少三个槽位必须检测到与固定横坐标对齐的圆形控件。圆形纵坐标允许覆盖正常位置和阵亡/当前角色下移位置，约为参考画布的 `1025..1070`；半径继续限制在自动小槽位范围。这个几何约束防止红色战斗特效单独造成误判，并保留现有“一个头像被特效遮挡仍可识别”的容错。

### MANUAL

保持现有规则：右下角三个大型技能圆环全部在预期位置、半径和亮边范围内时判定为 `MANUAL`。

### TRANSITION

不满足 AUTO 或 MANUAL 的画面均为 `TRANSITION`。技能动画、加载、黑屏、结算转场和未知页面不会因为缺少手动按钮而被推断为 AUTO。

## 公共监督流程

监督器每约 1 秒捕获一帧；“连续两帧”指连续两次分类标签相同，不要求像素相同。

- 连续两帧 `AUTO`：确认自动战斗。
- 连续两帧 `MANUAL`：点击自动按钮；首次未生效时重试一次。
- `TRANSITION`：不点击，并保留此前已经确认的自动状态。45 秒内控件恢复或进入结算即可继续；连续 45 秒仍无任何已知战斗/结算证据时保存诊断并停止。
- 结算识别始终高于控件识别，避免战斗结束时继续处理自动按钮。

主线和竞技场继续调用共享分类器。远征的 `observe_battle` 改为同样调用共享分类器，不再用“画面正在变化”直接推断 AUTO；画面变化只用于活动和业务进展看门狗。

## 测试与验收

- 把两张竞技场阵亡失败图加入回归样本，均必须识别为 `AUTO`。
- 现有全蓝自动样本继续识别为 `AUTO`。
- 主线、竞技场、远征现有手动样本继续识别为 `MANUAL`。
- 现有技能动画样本继续识别为 `TRANSITION`，且不能产生自动按钮点击。
- 主线、竞技场、远征三个适配器对共享分类结果映射一致。
- 增加监督器序列测试：已确认 AUTO 后经历少于 45 秒的 TRANSITION，再恢复 AUTO 或到达结果时必须正常继续。
- 运行完整离线测试；真实实跑仍由用户执行。
