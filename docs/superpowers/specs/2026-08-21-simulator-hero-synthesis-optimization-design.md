# 模拟器版英雄合成优化设计

## 目标

让模拟器版英雄合成可靠完成一轮三星列表遍历：SSS 当前卡跳过，非 SSS 且有红点的当前卡合成，非 SSS 且无红点的当前卡跳过；合成结果页面必须先关闭，再返回英雄列表，确认没有下一张卡后才计为完成一轮。

## 已确认根因

真实运行日志显示，合成确认后游戏会出现“刻印记忆”结果覆盖层。当前状态机没有该页面，直接识别到背景返回箭头并点击，导致未知画面和恢复重试。

翻卡动作使用左侧详情区域平均亮度的粗粒度值作为动作指纹。不同英雄可能产生相同指纹，公共 Runner 因此把正常翻卡误判为相同动作未推进，触发约 45 秒的重试等待。

现有回归只覆盖一张红点卡的完整链路，没有覆盖结果覆盖层和多张卡连续遍历。

## 设计

1. 在英雄合成状态机中加入模拟器结果覆盖层识别和关闭动作。识别优先级高于通用返回箭头；关闭后必须看到结果详情页，再允许返回英雄列表。
2. 结果关闭模板只加入模拟器 `templates/hero/`。PC 模板缺少该证据时保持现有行为，不因为模拟器素材改变 PC 加载。
3. 将卡片指纹改为由稳定详情区域的多项图像特征组成，避免仅使用平均亮度；动作名仍保留 `next_card_` 前缀，以兼容公共 Runner 的循环检测。
4. 增加多卡状态序列回归，覆盖普通卡、SSS 卡、红点非 SSS 卡、材料选择、结果覆盖层、返回列表和列表底部。
5. 不再使用“上一张 SSS 卡”的额外跳过规则；`prev_card_grey` 只做必要的兼容清理，最终判断完全基于当前卡。

## 验收标准

- 结果覆盖层不会触发 `back_to_list` 或未知画面唤醒点击。
- 当前卡判断符合三条确认规则。
- 连续不同卡不会因指纹碰撞进入 45 秒假等待。
- 多卡回归序列在没有下一张卡时恰好完成一轮。
- 英雄合成相关测试和全量离线测试通过。
- 离线验证完成后，再由用户打开模拟器进行一轮前台实跑验收。
