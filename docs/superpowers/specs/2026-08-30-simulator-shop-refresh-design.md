# 模拟器刷书签设计规格

## 目标

在现有《第七史诗自动助手》中新增模拟器版 `shop_refresh` 路线，自动检查秘密商店中的誓约书签与神秘书签，在确认商品身份后使用金币购买，并按用户指定次数消耗钻石刷新。

首版只支持模拟器，只购买这两种书签，不处理友情书签、装备或其他商品。路线初始标记为“实验功能”，必须完成用户实机闭环后才能转为正式功能。

## 参考项目结论

E7Helper 的刷书签流程提供了四项可借鉴的业务经验：

1. 先检查初始免费页面，再执行指定次数的付费刷新。
2. 分别检查商店顶部和滚动后的底部。
3. 点击购买后，在确认弹窗中再次识别商品身份。
4. 等待目标商品消失后才继续，避免动画期间误点其他商品。

不能照搬 E7Helper 的实现。它依赖旧客户端图色、固定坐标、固定睡眠和连续点击，缺少本项目要求的来源退出、目标进入与业务完成证据。其按商品类型去重的做法还可能漏掉同一批次中的第二个同类书签，统计代码也存在口径错误。

另一个较新的 Python/ADB 商店项目同样采用顶部扫描、滑动、底部扫描和固定三钻预算，但仍以固定坐标及时间等待为主，只作为流程交叉参考，不作为本项目架构基础。

## 固定业务口径

用户输入“刷新 `N` 次”表示：

- 先完整检查第 0 批初始免费商品；
- 完成 `N` 次付费刷新，每次确认消耗 3 钻石；
- 每次刷新产生的新商品批次都必须完整检查；
- 总共检查 `N + 1` 批商品；
- 第 `N` 次刷新后的商品仍要购买完目标物品，才允许结束。

`max_cycles` 在本路线中表示“已视觉确认完成的付费刷新次数”，不是检查页面数、点击次数或购买次数。

首版固定购买：

- 誓约书签；
- 神秘书签。

首版固定忽略：

- 友情书签；
- 所有装备；
- 所有其他商店商品。

资源规则：

- 发现目标但金币不足时，立即停止整条路线，不跳过并继续花钻；
- 刷新时钻石不足，立即停止；
- 资源不足属于正常资源结束，Runner 设置 `resource_exhausted=True` 并输出本轮统计；
- 未取得当前客户端资源不足截图前，未知购买/刷新弹窗只能保存诊断并失败关闭，不能用旧素材猜测。

## 本轮统计

统计只存在于当前进程内，不创建 CSV、JSON、数据库或历史统计页面。桌面日志区实时显示统计，任务退出前输出一次完整汇总。

购买一次代表获得一次抽卡机会，不显示书签枚数。两种书签必须分开统计。

统计字段：

- 目标付费刷新次数；
- 已完成付费刷新次数；
- 已确认钻石花费，等于完成刷新次数乘以 3；
- 初始页面誓约书签购买次数；
- 初始页面神秘书签购买次数；
- 付费刷新页面誓约书签购买次数；
- 付费刷新页面神秘书签购买次数；
- 两种书签各自的付费刷新命中率；
- 两种书签各自的金币花费；
- 总金币花费；
- 当前商品批次编号；
- 停止原因。

命中率定义：

```text
誓约书签命中率 = 付费刷新页面中誓约书签购买成功次数 / 已完成付费刷新次数
神秘书签命中率 = 付费刷新页面中神秘书签购买成功次数 / 已完成付费刷新次数
```

这里的“命中率”实际表示“每次付费刷新平均买到多少次”，不是“至少出现一次的页面占比”；极少数同批出现多个同类书签时，结果允许超过 100%。初始免费页面的购买单独展示，不进入付费刷新命中率。若一次刷新后的同一批商品出现多个同类书签，每次成功购买都独立计一次。

首版购买价格证据按当前客户端预期值设计：誓约书签 `184000` 金币，神秘书签 `280000` 金币。实施时必须用当前客户端购买确认截图验证；价格只在集中证据模块中维护。若实际价格与预期不一致，先按 `UNKNOWN` 安全停止并更新当前 fixture，不允许为了继续运行而忽略价格证据。

统计提交时机：

- 看见商品、点击购买和点击确认都不计购买；
- 购买弹窗离开、对应槽位变成已购买或目标商品消失、商店页面重新稳定后，才提交购买次数和金币花费；
- 刷新确认框离开、商品列表完成可解释转场、商店顶部重新稳定后，才提交一次刷新和 3 钻石；
- 手动停止、资源不足、异常退出和正常完成都必须在退出路径输出当前汇总。

## 架构选择

新增独立的 `ShopRefreshRunner`，不继承 `ModeRunnerBase`。秘密商店一批商品内包含多次购买、一次滚动和一次刷新，并且购买确认与刷新确认都是不可逆资源事务；强行套用普通“单动作切页面”循环会让状态和重试边界变得含糊。

独立 Runner 仍必须复用：

- `Runtime` 的截图、点击、停止、日志和诊断；
- `Epic7Navigator` 的大厅恢复和目标导航；
- `Epic7GlobalPopupGuard` 的全局弹窗处理；
- `core/supervisor.py` 的稳定帧和目标等待能力；
- `games/epic7/evidence/` 的集中视觉证据；
- `RecoveryGate` 的单轮有限恢复，但不可逆购买/刷新事务承诺后禁止恢复。

`ShopRefreshStateMachine` 或等价观察器保持纯视觉：输入当前截图，输出页面、商品行分类和候选动作，不直接点击。Runner 持有当前商品批次、已扫描区域、当前购买目标和统计事务。

## 页面与阶段

稳定页面：

- 大厅；
- 秘密商店顶部；
- 秘密商店底部；
- 誓约书签购买确认；
- 神秘书签购买确认；
- 刷新确认；
- 金币不足；
- 钻石不足；
- 未知页面。

Runner 阶段：

```text
导航进入商店
→ 顶部稳定
→ 扫描并清空顶部目标
→ 滚动到底部
→ 底部稳定
→ 扫描并清空底部新增目标
→ 当前批次扫描完成
→ 若已完成 N 次付费刷新则汇总退出
→ 否则执行一次刷新事务
→ 新批次顶部稳定
→ 返回顶部扫描
```

“清空目标”是指当前可购买目标都完成购买事务，并重新扫描确认没有剩余目标；不是看见一次“无目标”单帧就继续。

## 商品行识别

视觉证据集中在 `games/epic7/evidence/shop_refresh.py`，维护模板、区域、参考尺寸、阈值和页面组合。业务状态机不得重复定义已集中化的模板路径或阈值。

每个商品行独立分类为：

- `COVENANT`；
- `MYSTIC`；
- `OTHER`；
- `UNKNOWN`。

只有 `COVENANT` 和 `MYSTIC` 允许生成购买动作。以下情况必须为 `UNKNOWN`：

- 关键模板缺失；
- 两种目标分数过近，无法唯一分类；
- 商品图标或名称低于各自阈值；
- 商品和购买按钮不能证明属于同一行；
- 弹窗遮挡或动画导致行结构不完整；
- 页面顶部/底部身份不明确。

顶部和底部必须使用明确的槽位或非重叠行区域。不得仅用“本批次已经购买过某种书签”的集合去重，因为同一批可能出现两个同类目标。

## 页面转场契约

### 进入秘密商店

- 来源页面：大厅稳定页。
- 来源证据：大厅既有联合锚点。
- 动作：点击当前客户端的秘密商店入口。
- 来源退出：大厅联合锚点离开。
- 目标进入：秘密商店标题、立即刷新区域和商品行结构连续稳定。
- 重试：仅在大厅仍稳定时有限重试。
- 成功：商店顶部稳定，不增加刷新次数。

### 滚动到底部

- 来源页面：商店顶部稳定，顶部扫描已完成。
- 动作：在经 fixture 验证的安全列表区域执行一次定向滑动。
- 来源退出：顶部锚点离开或列表发生符合方向的运动。
- 目标进入：底部/最后商品槽位连续稳定。
- 重试：顶部仍稳定且没有观察到运动时有限重试；来源离开后只等待底部。
- 成功：底部稳定，不增加刷新次数。

### 打开购买确认

- 来源页面：顶部或底部商店稳定页。
- 来源证据：目标商品分类唯一，右侧购买按钮与商品处于同一行。
- 动作：点击该行购买按钮。
- 允许目标：对应类型的购买确认框，或资源不足提示。
- 重试：原商品行仍稳定且购买确认框未出现时有限重试。
- 成功：确认框中的商品类型与原事务目标一致；不计购买。

### 确认购买

- 来源页面：对应商品的购买确认框。
- 正向证据：购买标题、同类型商品、金币图标、对应固定价格和确认按钮联合成立。
- 阻断证据：商品类型不一致、价格不一致、资源不足或证据冲突。
- 动作：确认按钮只点击一次。
- 允许目标：原商店页面、金币不足提示，或明确购买完成状态。
- 业务成功：确认框离开，原目标槽位已购买或目标商品消失，商店页面重新稳定。
- 重试：不可逆确认不重试；结果不明确时保存诊断并停止。
- 统计：仅业务成功时提交对应书签一次和金币花费。

若购买确认框中的商品身份与原目标不一致，只有稳定识别到取消按钮时才允许取消；取消后保留原目标并重新观察该商品行，超过额度后停止。

### 打开刷新确认

- 来源页面：当前批次顶部和底部都已扫描完成，商店页稳定。
- 动作：点击立即刷新。
- 允许目标：刷新确认框或钻石不足提示。
- 重试：商店来源仍稳定且确认框未出现时有限重试。
- 成功：刷新标题、3 钻石价格、钻石图标和确认按钮联合成立；不计刷新。

### 确认刷新

- 来源页面：刷新确认框。
- 正向证据：刷新标题、3 钻石价格、钻石图标和确认按钮联合成立。
- 动作：确认按钮只点击一次。
- 允许目标：商品加载/滑入过程、新批次商店顶部、钻石不足提示。
- 业务成功：确认框离开，商品区域完成稳定→运动或变化→重新稳定，新批次顶部成立。
- 同批外观问题：若新旧列表静态外观相似，可使用可解释的刷新动画作为辅助；若既无转场证据又无列表指纹变化，则为 `UNKNOWN`。
- 重试：不可逆确认不重试；结果不明确时保存刷新前、动态峰值和最终帧后停止。
- 统计：仅业务成功时增加一次付费刷新和 3 钻石。

## 日志要求

日志使用中文键值对，并明确区分候选、点击、转场和业务提交：

```text
模式=刷书签 批次=0/100 页面=商店顶部 阶段=扫描 行=2 分类=誓约书签 分数=0.94
模式=刷书签 动作候选=purchase source=商店顶部 目标=誓约书签 行=2
执行点击 动作=open_purchase_confirm 坐标=(x,y)
模式=刷书签 转场确认 动作=open_purchase_confirm 目标=誓约书签购买确认
模式=刷书签 执行不可逆动作=confirm_purchase 目标=誓约书签 尝试=1/1
模式=刷书签 业务成功=购买 目标=誓约书签 本轮次数=3
模式=刷书签 执行不可逆动作=confirm_refresh 尝试=1/1
模式=刷书签 业务成功=刷新 已完成=10/100 钻石花费=30
```

识别失败日志必须带证据键、实际分数、阈值、行号和最终结论。未知证据不得写“成功”。

## 当前客户端素材清单

实施 Agent 必须由用户一次提供一个稳定页面，AI 只读采集：

1. 大厅秘密商店入口；
2. 商店顶部无目标商品；
3. 商店顶部含誓约书签；
4. 商店顶部含神秘书签；
5. 商店底部与最后槽位；
6. 誓约书签购买确认；
7. 神秘书签购买确认；
8. 购买完成后的商品行；
9. 刷新确认；
10. 刷新转场与刷新后顶部；
11. 金币不足；
12. 钻石不足。

拿不到第 11、12 项时，不允许借用旧客户端素材；对应未知弹窗先安全留证停止，拿到当前截图后再补专用分支。

## 测试边界

离线测试至少覆盖：

- 顶部、底部和未知页面分类；
- 两种书签正例、其他商品反例和冲突分数；
- 商品与购买按钮同行约束；
- 同批两个相同类型书签都能购买；
- 顶部与底部重叠槽位不会漏买或重复购买；
- 滑动首次无效、正常转场和未知结果；
- 购买弹窗商品一致与不一致；
- 购买确认只点击一次；
- 商品未消失不提交统计；
- 金币不足停止且不提交购买；
- 刷新确认只点击一次；
- 新列表未确认不增加钻石；
- 相同静态外观但完整刷新动态成立；
- 无动态且无列表变化时安全停止；
- `N` 次刷新检查 `N + 1` 批商品；
- 第 `N` 次刷新后的页面仍被扫描；
- 初始页面不进入付费命中率；
- 两种书签分别统计；
- 手动停止、资源不足、异常失败和正常结束都输出汇总；
- 其他现有路线全量回归不变。

## 实施和真实验收顺序

1. 先采集页面并为视觉证据写失败测试。
2. 完成纯观察器和离线分类，不点击实机。
3. 完成顶部/底部滚动闭环。
4. 完成购买事务闭环。
5. 完成刷新事务和统计。
6. 注册 CLI、导航与桌面实验路线。
7. 运行专项测试、全量测试和编译检查。
8. 用户先干跑当前商店页。
9. 用户实跑 1 次刷新。
10. 用户分别验证一次誓约和神秘购买。
11. 用户实跑 10 次检查统计。
12. 用户运行完整目标次数。

实施 Agent 只能报告离线验证结果。路线是否真正跑通必须由用户完成整条实机闭环后确认；未完成前不得把桌面状态改为正式功能。

## 验收重点

最终审阅必须确认：

- 点击没有被写成业务成功；
- 不可逆确认不可能重复点击；
- 商品和购买按钮严格同行；
- 同类重复商品与上下页重叠都不会导致漏买或重复买；
- 最后一次刷新后的页面确实被扫描；
- 初始免费页面没有污染付费命中率；
- 购买与刷新统计只在业务完成后提交；
- 日志可以还原来源、动作、退出、目标和统计提交；
- 没有复制旧客户端模板、降低全局阈值或修改已有正式路线；
- 没有建立用户未要求的历史统计存储；
- PC 后端明确保持未支持。
