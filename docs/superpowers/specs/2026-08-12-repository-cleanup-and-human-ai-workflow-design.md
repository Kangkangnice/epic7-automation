# 仓库整理与人机协作流程设计

## 目标

把 `auto_game_unified` 整理为唯一正式工程，发布到 GitHub 私有仓库
`Kangkangnice/epic7-automation`。仓库应当包含可运行代码、识别模板、离线回归素材、
测试和接手文档，不包含旧项目、临时截图、运行日志、诊断现场或本地工具环境。

同时固化本次远征开发中形成的协作方式：用户负责操作模拟器，AI 只读观察页面、
采集素材、实现状态机和运行离线测试。除非用户针对某次操作明确授权，AI 不点击或控制模拟器。

## 仓库边界

Git 仓库根目录为 `auto_game_unified`，默认分支为 `main`，远程仓库为新建私有仓库
`Kangkangnice/epic7-automation`。

上传内容：

- `core/`、`games/` 和入口代码。
- 页面模板以及背景无关的稳定识别锚点。
- `tests/` 中的离线测试和必要的完整页面回归截图。
- README、架构、扩展、排错、素材采集和人机协作说明。
- 依赖清单与 `.gitignore`。

不上传内容：

- `runtime_logs/` 和 `runtime_diagnostics/`。
- Python、pytest 和编辑器缓存。
- 本地工具目录 `.tools`、`.workbuddy`。
- 旧工程、早期探针脚本、临时截图和验收过程帧。

- `README.md`：项目用途、三种模式、安装、命令、日志、停止方式、当前限制。
- `docs/ARCHITECTURE.md`：窗口局部坐标、模板识别、状态机、Runner、导航与安全失败。

## 人类操作、AI 只读观测协议

### 角色

用户负责：

- 描述从入口到循环完成的整体业务逻辑。
- 明确资源消耗、禁止购买、停止条件和循环计数位置。
- 在模拟器中执行每一步操作，把游戏停在稳定页面。
- 页面准备好后回复“好了”，实跑阶段亲自启动和观察游戏。

AI 负责：

- 把业务流程转成页面清单、状态转换和异常分支。
- 每次只要求用户前进到一个明确页面。
- 用户说“好了”后，只读抓取当前游戏窗口，不操作模拟器。
- 保存完整页面回归图，从稳定 UI 中裁剪背景无关锚点。
- 先写能够失败的离线测试，再实现当前页面的识别和动作。
- 输出清楚的中文日志，提供实跑命令，并根据用户反馈补回归测试。

### 单页采集循环

1. 用户说明整个模式的入口、主流程、可选分支和完成条件。
2. AI 整理页面清单，指出尚未采集的页面和可能的风险点击。
3. AI 一次只请用户进入下一个页面，不连续发出多步操作要求。
4. 用户操作游戏，停在稳定页面后回复“好了”。
5. AI 只读采集游戏窗口，记录页面名称、来源页面、下一动作及禁止区域。
6. AI 保存完整截图到 `tests/fixtures/`，裁剪模板到 `games/.../templates/`。
7. AI 先增加失败测试，确认失败原因正确，再写最少实现使其通过。
8. 当前页面离线测试通过后，再请用户进入下一页面。

### 异常处理

- AI 看不懂页面、转场或动态效果时，立即向用户询问，不重复盲试。
- 用户误点到其他页面时，等待用户重新定位，不擅自控制模拟器恢复。
- 不用放宽全局阈值掩盖单个模板问题；先检查坐标区域、动态背景和稳定锚点。
- 新弹窗或停机必须保存现场，先加入回归测试，再修改生产逻辑。
- 当前客户端未采集的分支必须写入限制清单；不能用旧客户端图片冒充已支持。

### 实跑分工

- AI 完成离线状态流、反例、超时和全量回归测试。
- 用户在前台运行一轮实测，AI按用户要求只读查看日志和当前帧。
- 实跑失败时，用户先停止或保留现场；AI分析最后动作、日志和截图。
- 修复后重新运行离线回归，再由用户进行下一轮实测。
- 未经用户明确授权，AI不得启动、停止、点击或控制模拟器。

## 发布与验证

实施顺序：

1. 补齐文档并扩展 `.gitignore`。
2. 按批准范围删除旧版和临时文件。
3. 扫描敏感信息及超过 GitHub 单文件限制的文件。
4. 运行 `python -m pytest -q` 和 `python -m compileall -q .`。
5. 检查 Git 暂存范围，只提交正式工程内容。
6. 新建私有仓库 `Kangkangnice/epic7-automation`，推送 `main`。
7. 使用 GitHub API/CLI 确认仓库为私有、远程提交存在且工作区干净。
