# 远征页面事务修复设计

## 目标

修复远征路线把“已点击”误当作“已进入下一页”的问题，并保证难度三已经选中时只点击确认，不会再次取消选择。

## 范围

- 远征仅使用来源页、目标页连续两帧和业务完成页来推进状态。
- 每次页面动作都记录来源、目标、重试原因和最终确认结果。
- 竞技场改为正式功能；只修改统一目录状态、用户可见说明和回归测试。

不改变 PC 后端，不抽象新的全路线公共事务框架，不改变战斗监督器的安全边界。

## 远征事务模型

`ExpeditionAction` 增加来源状态和允许目标状态。状态机在返回页面动作时保持来源状态不变；`ExpeditionRunner` 点击后观察来源和目标：来源稳定存在才有限重试，来源离开后只等待，任一允许目标连续两帧成立后才调用状态机提交。

难度动作先检测 `difficulty_3_selected`。已选中且确认按钮出现时，直接返回确认动作；未选中时才返回选择难度三动作。选择成功必须由“难度三已选中 + 确认按钮”连续两帧证明。

循环只在招募/胜利收尾后远征主页稳定出现时增加。

## 验收

- 当前传单故障图复放时，必须实际发出 `select-first-poster`，画面停在来源页时最多重试四次，不进入未知画面中央点击。
- 初始处于已选中难度三页面时，第一步只能是确认，不得再点难度三图标。
- 每个测试都先红后绿；远征专项、桌面目录专项、全量测试和 Python 编译检查通过。
- 实机验收仍由用户执行一整轮，AI 只报告离线验证结果。
