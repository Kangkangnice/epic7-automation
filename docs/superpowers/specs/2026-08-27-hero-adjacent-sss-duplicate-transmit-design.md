# 英雄合成：相邻同名 SSS 副本传送设计

## 目标

补齐模拟器版英雄合成中“同名 SSS 本体后的无红点副本”处理：仅当当前英雄紧邻上一张已确认的同名 SSS 英雄时，才把当前无红点、非 SSS 副本送入既有传送事务。

## 业务规则

| 上一张已确认卡 | 当前稳定卡 | 决策 |
| --- | --- | --- |
| SSS，名称相同 | 非 SSS、无红点 | 传送当前副本 |
| SSS，名称不同 | 非 SSS、无红点 | 跳过 |
| 非 SSS 或无上一张上下文 | 非 SSS、无红点 | 跳过 |
| 任意 | 有红点 | 保持既有刻印流程 |
| 任意 | SSS | 保持既有跳过流程，并更新上一张上下文 |
| 任意 | 名称或卡片切换未确认 | 等待，不传送 |

“名称相同”复用现有左侧英雄名称区域的视觉指纹，只用于相等比较；不引入 OCR，也不显示或保存实际名称文本。

## 状态与事务边界

- 在稳定确认当前卡为 SSS 后，保存 `(名称指纹, SSS)` 作为**仅下一张**的上下文。
- 上下文只在 Runner 已确认翻卡事务成功后，供下一张稳定英雄卡读取。
- 当前卡符合“同名 + 非 SSS + 无红点”时，创建当前副本的待传送上下文，复用已有传送页、目标卡安全分类、确认和奖励返回流程。
- 一旦读取到非匹配的下一张、进入刻印、完成传送或重新筛选，上下文立即清空，绝不跨越其他英雄或跨轮次关联。

## 安全与日志

- 不用“无红点”单独触发传送。
- 不能确认名称、评级、列表页或卡片切换时，不点击传送入口。
- 传送页仍执行既有的“高亮目标不是 SSS”检查。
- 日志记录：前卡是否 SSS、名称是否相同、当前红点状态、最终决策；在证据不完整时记录等待而非成功。

## 验证

1. `SSS ABC -> 非 SSS 无红点 ABC` 进入传送。
2. `SSS ABC -> 非 SSS 无红点 DEF` 仍跳过。
3. 单独的 `非 SSS 无红点 ABC` 仍跳过。
4. `SSS ABC -> 非 SSS 有红点 ABC` 保持刻印。
5. 未确认翻卡或未知名称时不触发传送。
6. 现有 SSS 材料中止后传送流程不受影响。
