# PC 共享模板与英雄筛选修复设计

## 背景与证据

PC 客户端已经统一输出 `1982x1132` 识别画布，并在真实运行中复用了模拟器模板。大厅与英雄信息页能够正确识别，但英雄合成第一次打开筛选面板后仍被判断为英雄列表，导致同一个筛选按钮被重复点击，面板在打开和关闭之间来回切换。

真实 PC 失败截图中的匹配结果为：

- `filter_level_label`：`0.755`，现门槛 `0.80`；
- `filter_attribute_label`：`0.768`，现门槛 `0.82`；
- `filter_star3_unselected`：`0.895`，现门槛 `0.90`。

此外，英雄合成仍通过目录名是否为 `templates_pc` 启用一套旧 PC 业务分支。该分支保存的是补边画布启用前的坐标和时序，例如筛选漏斗坐标为 `(1612,141)`；当前兼容画布上已经实测有效的统一坐标是 `(1540,191)`。因此不能为了标记 PC 后端而重新启用旧分支。现有测试分别验证了旧 `templates_pc` 流程和共享模板大厅识别，却没有覆盖“PC 后端 + 共享模板 + 统一英雄合成逻辑”的真实组合。

## 目标

1. PC 和模拟器只维护一套 `games/epic7/templates` 模板目录。
2. PC 和模拟器在业务状态机内使用同一套参考坐标、页面状态和转场契约；客户端差异只由窗口截图与输入层处理。
3. PC 筛选面板在第一次打开后能够被确认，不再因误判而反复开关。
4. 不降低 3S、材料、传送确认等安全决策的识别门槛。
5. 日志如实记录筛选面板各项证据分数及最终判断。
6. 模拟器现有英雄合成流程保持不变。

## 非目标

- 本次不校准英雄合成之外的 PC 路线。
- 本次不全局降低模板匹配阈值。
- 本次不重构英雄合成的业务决策流程。
- 本次不删除真实 PC 运行截图和测试夹具；它们继续作为回归证据。

## 设计

### 1. 删除旧 PC 模板目录

删除 `games/epic7/templates_pc`。引用旧目录的测试改为使用共享模板；只服务于旧模板实现、无法表达当前真实启动链路的断言一并删除或改写。真实 PC 截图夹具保留。

### 2. 统一业务状态机

不向英雄业务状态机传入 `window_backend`，也不启用旧 `pc_client` 分支。PC 窗口层继续负责把原始 `1920x1080` 画面补成 `1982x1132`，并把统一画布点击坐标换算回客户区坐标。

删除模板构建器对 `templates_pc` 目录名的推断。当前实测有效的共享坐标、模拟器转场契约和详细日志继续作为两端的统一业务逻辑。旧 PC 业务分支本次不做大范围重构，但不再保留任何可由模板目录触发的入口；后续只有在独立测试保护下才清理死代码。

### 3. 筛选面板采用组合证据

不统一降低所有阈值。仅对筛选面板的三个局部证据增加实测支持门槛，并要求多个空间位置固定、含义互相独立的证据共同成立：

- 面板锚点：`级别` 与 `属性`；
- 状态锚点：三星已选中或未选中。

画面只有在面板锚点与三星状态证据组合通过时，才判定筛选面板已打开。关闭画面必须不能通过该组合判断。3S、材料、传送等安全证据继续使用原门槛。

具体支持门槛由已保存的真实 PC 正样本和关闭面板负样本共同校准，不直接把当前得分写成门槛。

### 4. 转场与日志

`open_filter` 点击后必须看到“筛选面板已打开”的组合证据才算成功。若仍在英雄列表，才允许重试；若已打开但三星尚未选中，下一步只能选择三星，不能再次点击漏斗。

日志记录：

- `级别`、`属性`、三星状态的分数及各自门槛；
- 最终页面判断；
- 重试原因是“源页面仍存在”还是“目标证据不足”。

这样可以区分点击没生效与目标页面识别失败。

## 测试与成功标准

先补失败测试，再修改实现。

1. 使用 `20260829_185635_098904_manual_stop.png` 验证共享模板在 PC 模式下识别为筛选面板，并返回 `select_star3`，而不是 `open_filter`。
2. 使用 `20260829_174936_287634_retry_exhausted_open_filter.png` 验证关闭画面不能被误判为筛选面板。
3. 测试真实 `run_mode(window_backend="pc")` 仍使用共享 `templates` 和统一英雄构建逻辑，不会选择旧 PC 坐标。
4. 测试筛选打开后不会再次执行 `open_filter`。
5. 运行英雄合成完整单元测试、PC 启动链路测试和模拟器回归测试。
6. 本地实机验证至少完成筛选打开、三星选择、筛选关闭并进入首张英雄判断；日志与画面一致。

## 删除与兼容策略

`templates_pc` 是已跟踪文件，删除后可通过 Git 历史恢复。现有未提交的其他路线修改不纳入本次提交，也不做清理或格式化。
