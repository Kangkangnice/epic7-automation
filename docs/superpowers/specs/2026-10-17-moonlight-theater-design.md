# 月光剧场（`moonlight_theater`）设计规格

> 状态：**草稿，等用户逐条确认**。本文是《新增自动化路线指南》（`docs/EXTENDING.md`）
> 第 1 步的产物——先把口述业务整理成页面清单与状态流，**不猜坐标、不写状态机**。
> 确认之后才进入「一页一交互」的素材采集。

## 目标

新增一条路线，把本周「月光剧场」里所有**免费（绿 F）**的观览奖励打完领完，跑一遍即结束。

- 只支持模拟器；PC 端不在本路线范围内。
- 每周刷新一次，免费额度是**存量**，领完即消失。
- 剧情**不可跳过**（右上角没有 auto 图标），必须靠点击下方字幕推进。
- 中途可能进入战斗（默认自动）。

## 业务口径（用户 2026-10-17 口述，逐条）

1. 大厅点击「支线故事」。
2. 右侧点击「月光剧场」。
3. **只有月光剧场入口的左上角出现绿色 F 角标才继续**；没有绿 F 说明本周免费奖励已领完，
   路线**正常停止**（业务收工，不是故障）。
4. 有绿 F 则点击进入，停留在一个剧场页（横向排列的多个故事线 / 剧本，当前停在某一个）。
5. 判断**当前剧场**的左上角有无绿 F：
   - 无 ⇒ 往右点击下一个剧场，回到本步重新判断；
   - 有 ⇒ 点击右下角「入场」。
6. 入场后自动落在「可入场的某一集」页，点击下方「进行观览」。
7. 弹出「观览指南」弹窗（提示不可跳过），点击确认。
8. 进入剧情页：右上角**没有 auto 图标**⇒ 持续点击下方字幕推进。
9. 中途可能进入战斗（默认自动）⇒ 等战斗结束，之后可能继续剧情 ⇒ 继续点字幕。
10. 出现 **CLEAR** 字标 ⇒ 这一幕结束。
11. 自动回到刚那一集页，多出一个「观览奖励」⇒ 点右侧类似下载的图标领取。
12. 弹出「获得奖励」弹窗 ⇒ 点掉。
13. 点击左上角返回 ⇒ 完成一幕，回到剧场页（第 5 步）。
14. 循环 5~13，每次往右推进一个剧场。
15. **结束条件：右边已经没有剧场海报可点，且当前剧场左上角没有绿 F。**

### 未采集的页面（全部）

P1 之后的每一页**都没有当前客户端整屏帧**。按 `docs/TEMPLATE_CAPTURE.md`，
未采集的页面一律安全停止，不得用旧素材或推测坐标冒充支持。

## 状态流

```text
大厅
 └─点「支线故事」→ 支线故事页
      └─[入口卡片左上角绿 F?]── 否 ──→ 本周已结束（收工）
      └─是─点卡片→ 剧场选择页
            └─[当前剧场左上角绿 F?]── 否 ──→ 往右点下一个剧场（右边没了就收工）
            └─是─点「入场」→ 某一集页
                  └─点「进行观览」→ 观览指南弹窗
                        └─点确认 → 剧情页（无 auto）
                              └─反复点下方字幕
                                    ├─进入战斗 → 等结算 → 回到剧情页
                                    └─出现 CLEAR
                              └─回到某一集页 → 点右侧领奖图标 → 获得奖励弹窗
                                    └─点掉弹窗 → 点左上返回 → 剧场选择页
```

## 结束条件

**两条同时成立**才算本周结束：

1. 右边已经没有剧场海报可以点击；
2. 当前剧场左上角没有绿 F。

⇒ 正常收工（退出码 `0`，由 `main` 收尾带回大厅）。**不是故障**，也不该报错。

入口卡片没绿 F 时同理：直接收工，一个动作都不发。

## 待确认（**会阻塞编码**，请逐条拍板）

| # | 问题 | 我的判断 | 为什么要问 |
|---|---|---|---|
| Q1 | 「往右点击其他剧场」是**直接点右边那张海报**，还是点**翻页箭头**？ | 倾向前者（点海报即选中） | 决定是「点命中点」还是「点固定箭头」；也决定「右边没有海报可点」怎么判——是海报消失，还是箭头变灰 |
| Q2 | 一个剧场**能有几集**可入场？ | 倾向「一个剧场一幕」 | 若一个 F 对应多集，打完一幕回到 P3 时 F 可能还在 ⇒ 会重复入场；必须知道「返回后是否要再判 F 继续」 |
| Q3 | P4（某一集页）三种长相怎么区分：刚入场（只有「进行观览」）/ CLEAR 回来（多出领奖图标）/ 领完奖励（无图标但仍在同一页）？ | 靠「领奖图标在不在」+「观览按钮在不在」两枚锚点分三态 | 这是本路线最容易误点的地方：判错就会重复观览或漏领奖励 |
| Q4 | P3 上「当前剧场的左上角」是**海报图的左上角**还是**页面左上角标题区**？ | 倾向海报左上角 | 若是海报左上角，绿 F 会随海报位置移动 ⇒ 区域必须跟着海报走，不能用固定区域；若是页面区，一枚固定区域就够 |
| Q5 | P1 上「月光剧场入口卡片」的绿 F，与 P3 上剧场海报的绿 F，**是不是同一枚角标**？ | 未定 | 同一枚就能一张模板复用；不同就得各裁一张 |
| Q6 | 剧情页点字幕：**点哪个坐标**、**多快一次**、会不会点到别的按钮？ | 倾向「下方中央固定安全点、约 1 秒一次」 | 剧情页没有 auto，全靠点击推进；位置错了可能点到菜单或跳过类按钮 |
| Q7 | 战斗是**剧情自动触发**（我们不点开战按钮），对吗？ | 倾向是 | 决定用「无动作 ⇒ 交战斗监督」那条通道，而不是「点开战按钮再移交」 |
| Q8 | 「观览指南」弹窗的确认按钮、CLEAR 字标、领奖图标，**位置是否固定**？ | 需真机帧 | 固定就能用固定点 + 模板双判据 |
| Q9 | 是否要「开局接力」（人停在半路启动，就地接管）？ | 倾向**第一版不做**，进 `RESUME_EXEMPT` | 见下「已知风险」：剧情页与战斗画面的判据存在误判史，误接力的代价是磨到超时 |
| Q10 | 桌面助手里的**分组**（日常 / 赛季 / 活动）？是否进「每日任务」默认清单？ | 倾向 `GROUP_SEASON`（每周刷新）、**不进** `DAILY_TASKS` | 分组默认是「日常」，忘填会把每周路线混进日常里；而「每周重置」不符合「每日自然重置」的登记口径 |

## 架构选择（复用优先）

按 `docs/EXTENDING.md`，新路线**默认继承 `ModeRunnerBase`**，只声明差异：

- 交互模型就是「点按钮 → 转场 → 新页面」同构 ⇒ 不用独立 Runner。
- 战斗移交用 `_SETTLED_BATTLE_STATE`（停在战斗态且本帧无动作 ⇒ 直接交战斗监督），
  **不点开战按钮**——战斗是剧情触发的。
- `_REQUIRE_TRANSITION_CONTRACT = True`：新路线一律打开，每个动作带
  `target_pages`（换页）或 `in_page_evidence`（同页）。
- 全局弹窗（断网 / 亲密度 / 友情点 / 好友申请）走既有 `Epic7GlobalPopupGuard`，
  **不在本路线加本地分支**。
- 「获得奖励」弹窗与「点击关闭」类控件优先复用既有锚点（`sanctuary` 已证明它是游戏通用控件）。

## 素材采集清单（实施时「一页一交互」逐页要）

每页都需要一张 **1982×1132 的当前客户端整屏帧**，另加该页的稳定锚点裁图：

1. 支线故事页（右侧月光剧场入口：**有绿 F** / **无绿 F** 各一张）
2. 剧场选择页（**当前剧场有 F** / **无 F** 各一张；最右一张，用于判「右边没了」）
3. 某一集页（刚入场 / CLEAR 回来 / 领完奖励，三张）
4. 观览指南弹窗
5. 剧情页（多张：纯对话 / 带立绘 / 黑屏转场）
6. 战斗帧（确认与剧情页可区分）
7. CLEAR 过场
8. 获得奖励弹窗

## 已知风险（写在这里，别装作不存在）

| 风险 | 说明 | 处置 |
|---|---|---|
| 剧情页被判成战斗 | `battle_controls.battle_scene_visible` 有误判史：`side_story` 打完一关的**场景页**被它判成 True（`fodder/replay.png` 同因）⇒ 会把整段剧情交给战斗监督，磨到绝对超时 | 采集到剧情帧后**先量一遍** `battle_scene_visible`；若误判，本路线用更严的局部判据，**不改共享判据**（那会动 14 条路线） |
| 绿 F 用颜色判会被底图骗 | 圣域「照料」实测：绝对亮度差 57 点，其中 42 点是背景昼夜造成的 | 绿 F 用**模板**（字形 + 绿底）限定小区域判，不用「绿色像素占比」 |
| 领奖图标与「进行观览」同页 | P4 三态若分不开，会重复观览或漏领 | 两枚锚点各判一次，三态显式建模（Q3） |
| 同一个剧场若有多集 | 返回后 F 仍在 ⇒ 可能重复入场形成死循环 | 基类的动作重试上限 + 循环检测是兜底；语义上先确认 Q2 |
| 不做接力 | 人停在半路启动会走「回大厅 → 重新导航」 | 与 `fodder` / `side_story` 同一取舍，理由写进 `RESUME_EXEMPT` |
