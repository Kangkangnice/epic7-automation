# 第七史诗全局异常弹窗守卫设计

## 目标

把与主线、竞技场、远征业务无关的系统级异常弹窗放到共享截图入口处理。本次只覆盖已经采集到的“网络连接异常，请重新连接／点击重试”，不顺带猜测或处理尚无样本的维护等弹窗。

## 根因

现有网络识别模板已经由三个模式共用，但只在各模式的战斗观察器中调用。2026-08-13 20:10 的主线失败发生在大厅进入主线后的导航阶段，因此共享模板存在却没有执行机会。

## 结构

- `Epic7GlobalPopupGuard` 位于 `games/epic7/global_popups.py`，拥有网络弹窗的稳定确认、重试计数和失败诊断逻辑。
- `Runtime.capture()` 是导航、主线、竞技场、远征所有观察循环的共同截图入口。实时运行时给 Runtime 安装守卫；干跑和普通单元测试默认不安装。
- 守卫收到原始截图后先检查网络弹窗。未出现时原样返回；连续两帧出现时点击重试，并继续采集，直到返回一张没有该弹窗的截图给业务状态机。
- 业务状态机看不到被守卫消费的网络帧，因此导航、剧情、队伍、战斗和结算各自的超时不会在断网弹窗停留期间推进。

## 安全边界

- 同一次持续弹窗最多点击两次，间隔至少 3 秒；第二次后仍持续 15 秒，保存 `network_retry_failed` 诊断并停止。
- 弹窗消失即重置本次计数；以后再次断网可重新获得两次机会。
- 识别必须同时匹配消息正文和“点击重试”按钮，连续两帧一致后才能点击。
- 未知弹窗不盲点，仍交由现有业务监督器留证停机。
- P 键检查、日志、截图保留和退出码沿用 Runtime 现有行为。

## 验证

- 把 `20260813_201056_715894_navigation_lobby_to_story_ready_failed.png` 纳入 `epic7_global` 回归样本。
- 单元测试覆盖：两帧确认、最多两次、弹窗消失重置、业务只收到恢复后的截图、持续失败留证。
- 集成测试覆盖 Runtime 的统一截图入口，以及主线、竞技场、远征共用同一个守卫实例。
- 运行全部离线测试；不操作模拟器，真实测试由用户执行。
