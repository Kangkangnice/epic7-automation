# 中文交互式启动菜单设计

## 目标

为现有四种自动化模式增加一个独立的中文终端菜单。用户先输入功能编号，再输入正整数运行次数，随后以前台实跑方式调用现有入口。模式业务逻辑和原有命令行接口保持不变。

## 交互

菜单固定显示：

1. 主线
2. 竞技场
3. 远征
4. 狗粮（特别的时间之书 3-7）

用户输入功能编号后，再输入运行次数。空输入、非数字、编号不在 1 至 4、次数小于 1 时，输出中文错误提示并重新询问当前输入。输入合法后显示模式和次数，并开始一次任务；任务完成、资源耗尽、手动停止或运行失败后，启动菜单退出，不自动开始第二项任务。

## 结构

- 新增独立模块 `auto_game_unified.launcher`，只负责菜单显示、输入校验和参数组装。
- 启动器通过现有 `main.main()` 调用 `--mode <mode> --max-cycles <N> --live --confirm RUN`。
- `auto_game_unified.main` 的默认行为、干跑诊断和原有参数全部保留。
- 启动命令为 `python -u -m auto_game_unified.launcher`。

## 安全边界

- 只有功能编号和正整数次数均确认后才进入实跑。
- 菜单不直接控制窗口、截图或点击；这些职责继续由现有运行入口承担。
- 启动器原样返回现有退出码：完成为 0，运行故障为 1，资源耗尽为 2，按 P 停止为 130。

## 离线验证

- 验证四个编号映射到正确模式。
- 验证输入顺序是“功能编号 → 运行次数”。
- 验证无效编号和无效次数会中文提示并只重试当前问题。
- 验证调用现有入口时组装了实跑确认参数。
- 验证启动器返回现有入口的退出码。
- 运行全量离线回归，不操作模拟器。
