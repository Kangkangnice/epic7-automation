# PushPlus 终态通知设计

## 目标

当《第七史诗》自动化实跑自然完成、因允许的资源耗尽而停止，或出现运行故障时，向用户的安卓手机发送一条 PushPlus 通知。主线、竞技场、远征和狗粮共用同一套通知逻辑。只有带 `--live` 的实际运行会通知；离线诊断、离线测试以及用户按 `P` 主动停止时不发送通知。

## 方案选择

通知放在统一命令入口处理，而不进入各模式状态机。`main.py` 已经汇总运行结果并区分退出码，因此它是唯一需要接入通知的业务位置：

- 退出码 `0`：发送“自动化已完成”，包含模式、完成轮数、目标轮数和耗时。
- 退出码 `2`：发送“资源不足已停止”，包含模式、完成轮数、目标轮数和耗时。
- 运行异常：发送“自动化运行失败”，包含模式、简短错误原因、耗时及该模式的本地诊断目录。
- 用户按 `P` 导致的 `ManualStop`：保持退出码 `130`，不发送。
- 未带 `--live` 的干跑诊断：保持现有结果，不发送。

命令行参数校验失败、电脑断电、进程被系统强制结束等无法执行 Python 终态代码的情形不在首版覆盖范围内。覆盖这些情况需要独立看门狗进程，当前不引入。

## 组件与配置

新增一个小型 PushPlus 通知模块，负责：

1. 从环境变量 `EPIC7_PUSHPLUS_TOKEN` 读取 Token。
2. 使用 HTTPS POST 调用 PushPlus 消息接口。
3. 构造简短的中文标题和正文。
4. 使用 Python 标准库完成请求，不新增第三方依赖。

Token 不写入配置文件、日志、测试样本或 Git。未配置 Token 时自动化照常运行，终端只提示一次“PushPlus 通知未启用”。

## 失败隔离

通知请求使用 5 秒超时且首版只尝试一次。PushPlus 无法访问、接口拒绝或返回失败结果时，只在终端打印不含 Token 的警告；不得覆盖原始异常、改变既有退出码或把成功运行改判为失败。

异常通知只发送错误摘要，不发送 traceback、截图或日志全文，避免泄露本机信息。诊断图片仍保存在现有本地目录；首版消息仅给出该目录路径，因为本地图片不能直接由微信访问。

## 测试与验收

离线测试通过注入假的 HTTP 发送函数完成，不调用真实 PushPlus：

- 成功完成只发送一次成功通知，并保持退出码 `0`。
- 资源耗尽只发送一次资源通知，并保持退出码 `2`。
- `RuntimeError` 和其他普通 Python 异常各发送一次失败通知；原有返回或抛出语义保持不变。
- `ManualStop` 不发送，并保持退出码 `130`。
- 干跑诊断不发送，并保持现有退出语义。
- 未配置 Token 不发送，运行结果不变。
- 推送超时、HTTP 错误和 PushPlus 业务失败不改变自动化结果，输出中不包含 Token。
- 完整离线测试继续通过，不启动或操作模拟器，也不进行真实推送。
