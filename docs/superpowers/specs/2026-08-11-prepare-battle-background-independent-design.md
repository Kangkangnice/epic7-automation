# “准备战斗”去背景识别与逐关恢复设计

## 问题

最新失败现场仍是正常的主线关卡页面，右下角“准备战斗”清晰可见，但全彩模板分数只有 `0.753`/`0.766`，低于 `0.80` 阈值。原因是模板包含绿色按钮背景和关卡画面，不同章节的背景变化拉低了相似度。

同一次实跑还暴露出恢复额度按整次运行计算：前面遇到一次通知弹窗后，唯一恢复机会已被消耗，后续正常关卡页面识别失败便直接停机。

## 方案

1. 新增共享的 `find_prepare_battle_button`：只提取按钮中的低饱和度高亮字形，忽略绿色按钮和关卡背景。
2. 主线状态机和大厅导航共同调用该函数，避免两套识别规则漂移。
3. 现有两张“准备战斗”模板都参与匹配；任一字形匹配达到阈值即返回最高分结果。
4. 恢复额度从“整次运行一次”改为“每个尚未完成的关卡一次”。完成一关后，下一关重新拥有一次恢复机会；同一关第二次失败仍安全停止。
5. 暂不新增“支线故事通知”盲点处理。当前没有保存该弹窗样本，先依靠逐关恢复避免它消耗后续关卡的恢复机会。

## 边界与安全

- 只修改“准备战斗”识别及恢复计数，不调整其他页面阈值。
- 新识别仅搜索右下角固定相对区域，点击坐标仍由匹配中心按当前画面尺寸换算。
- 用关卡页正例和多个右下角其他按钮页面作为反例，避免把“下一关”“确认”等按钮误认为“准备战斗”。
- 本次仅运行离线测试，不启动、不点击模拟器。

## 验收标准

- 最新 `20260811_131233_266196_timeout_stage.png` 离线识别为 `prepare_battle`。
- 原有主线与导航样本继续通过。
- 右下角其他动作页面不匹配“准备战斗”。
- 自动化在某一关用过恢复后，完成该关，下一关仍能再恢复一次。
- 全量 pytest 与 compileall 均通过。
