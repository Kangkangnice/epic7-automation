# 第七史诗自动助手 v0.1.0 产品化设计

## 1. 目标

将当前面向开发者的《第七史诗》视觉自动化仓库，整理为普通 Windows 玩家能够安装、理解、运行、停止和反馈问题的免费开源工具。

产品正式名称为 **第七史诗自动助手**，内部英文标识为 `Epic7AutoAssistant`，GitHub 仓库建议使用 `epic7-auto-assistant`。首版版本号为 `v0.1.0`。

首版成功不等于扩大识别范围，而是让普通用户在一个明确支持的环境中无需安装 Python、无需使用命令行，也能安全运行现有路线；失败时能够自行导出足够的诊断证据。

## 2. 已确认的产品决策

- 面向公开的普通玩家，而不是仅供开发者使用。
- 免费、开源、非商业，代码采用 MIT License。
- 首版仅支持 64 位 Windows 和当前代码已经验收的雷电 14 渲染环境：模拟器渲染区 `1920 × 1080`，运行时归一化为项目基准画布 `1982 × 1132`。
- 首版不承诺 PC 客户端、其他模拟器或其他分辨率。
- 六条路线全部保留并公开：
  - 英雄合成：正式功能。
  - 主线、竞技场、远征、狗粮、助手自动：实验功能，启动前提示可能不稳定。
- 使用实用型中文图形界面，不追求复杂视觉设计。
- 默认完全本地运行，不建立用户账号，不上传日志、截图或遥测数据。
- 故障由用户主动导出诊断 ZIP，再自行上传 GitHub Issue。
- 程序只检查 GitHub Releases 是否有新版本，并提示用户前往下载，不做静默自动更新。
- 同时提供 Windows 安装版、便携版和源代码。
- 不重新实现英雄合成已有的 SSS、材料、传送、重试和诊断保护。

## 3. 非目标

`v0.1.0` 不包含：

- PC 客户端支持；
- 其他安卓模拟器支持；
- 多分辨率自动适配承诺；
- 云端账号、云配置或远程控制；
- 自动上传日志、截图或使用统计；
- 静默自动更新；
- 插件系统；
- 为减小安装包而用 C++ 或 Rust 重写识别核心；
- 大规模重构六条已有业务路线；
- 反检测、绕过游戏安全机制、读取内存或修改网络数据的能力。

## 4. 用户体验

### 4.1 主界面

首版界面使用 Python 标准库 `Tkinter/ttk`，至少包含：

- 产品名称、版本号和“非官方免费开源工具”标识；
- 环境检测结果；
- 六条路线及各自状态；
- 运行次数；
- 开始和停止按钮；
- 当前阶段、当前页面、最近动作和完成轮次；
- 实时中文日志；
- 打开日志目录；
- 打开诊断目录；
- 一键导出诊断包；
- 检查新版本。

界面中的路线状态固定为：

| 路线 | v0.1.0 状态 | 界面行为 |
|---|---|---|
| 英雄合成 | 正式功能 | 正常展示并允许在环境检测通过后启动 |
| 主线 | 实验功能 | 黄色“实验”标记，启动前显示一次不稳定提示 |
| 竞技场 | 实验功能 | 黄色“实验”标记，启动前显示一次不稳定提示 |
| 远征 | 实验功能 | 黄色“实验”标记，启动前显示一次不稳定提示 |
| 狗粮 | 实验功能 | 黄色“实验”标记，启动前显示一次不稳定提示 |
| 助手自动 | 实验功能 | 黄色“实验”标记，启动前显示一次不稳定提示 |

“正式功能”表示项目维护者将其作为首版主要支持路线，不代表官方授权、绝对零故障或零账号风险。“实验功能”表示代码可用但可能不稳定，不改变其内部既有安全停止原则。

### 4.2 用户流程

```text
安装或解压
→ 打开第七史诗自动助手
→ 阅读首次使用说明
→ 启动雷电模拟器并进入游戏
→ 执行环境检测
→ 选择路线和次数
→ 实验路线确认提示（如适用）
→ 启动独立工作进程
→ 实时查看状态
→ 正常完成、用户停止或安全停止
→ 必要时导出诊断 ZIP
```

用户不需要接触 Python、Git、模板目录或命令行参数。现有 CLI 继续保留给开发者和高级用户。

## 5. 系统架构

### 5.1 产品外壳

新增桌面 GUI 和产品服务层，但不复制业务状态机。GUI 只负责用户输入、显示和进程控制。

建议边界：

```text
Tkinter GUI
  → 环境检测器
  → 运行配置校验
  → Worker 子进程
       → 现有 main / modes / Runner / 状态机
       → Runtime 日志与诊断
  ← 结构化运行事件
```

### 5.2 独立工作进程

自动化不得直接运行在 Tkinter 主线程中。GUI 启动独立 Worker 子进程，原因包括：

- 避免截图、识别和等待阻塞窗口；
- 核心异常退出时 GUI 仍可显示原因；
- GUI 可以统一映射退出码；
- 停止协议和进程生命周期更清晰；
- 后续仍可独立运行和测试 CLI。

GUI 停止按钮优先发送与现有 `P` 停止等价的协作式停止信号。超过明确的收尾时间后仍未退出，GUI 才提供强制终止，并提示强制终止可能导致最后一份日志不完整。

### 5.3 结构化事件

GUI 不解析中文日志推断状态。核心在保留现有中文日志的同时，向 GUI 输出稳定的结构化事件。最小事件类型为：

```text
run_started
page_observed
action_candidate
action_clicked
transition_waiting
transition_confirmed
business_completed
retrying
diagnostic_saved
run_stopped
run_failed
```

每条事件至少包含：时间、模式、轮次、事件类型、可读消息。与转场有关时再包含来源页面、目标页面、动作、尝试次数和诊断路径。事件协议必须版本化，GUI 不依赖自由文本字段。

### 5.4 本地数据目录

安装目录视为只读，不在其中写入用户运行数据。配置、日志和诊断统一放在：

```text
%LOCALAPPDATA%\Epic7AutoAssistant\
├─ config.json
├─ logs\
├─ diagnostics\
└─ exports\
```

运行模板随应用安装并只读加载。便携版默认仍使用同一本地数据目录，避免解压目录无写权限；后续如有明确需求再增加真正的便携数据模式。

## 6. 环境检测

开始按钮只有在关键检查通过后才可用。首版检查：

- 操作系统为受支持的 64 位 Windows；
- 雷电 14 进程和唯一受支持的《第七史诗》/“雷电模拟器”窗口存在；
- 雷电实例能够通过现有控制台接口唯一映射到 `1920 × 1080` 渲染区；
- 游戏窗口可正常截图；
- 截图不是黑屏或异常尺寸；
- 窗口宽高比和基准分辨率满足现有识别要求；
- 必需模板文件存在且能读取；
- 模板包版本与程序版本匹配；
- 当前页面能够被所选路线识别，或能够走现有受控导航。

检查结果只使用三种用户可理解的状态：

- 通过：允许启动；
- 提醒：实验路线等非阻断事项，确认后允许启动；
- 阻止：环境不兼容或关键资源缺失，不允许启动。

首版不增加复杂的远程停用系统。游戏更新导致页面无法识别时，继续依靠现有 `UNKNOWN`、转场超时、失败关闭和诊断保存机制；维护者通过发布新版本或 Release 公告处理兼容性变化。

## 7. 业务安全边界

产品化不重新设计英雄合成业务。GUI 和 Worker 必须通过现有入口调用当前 Runner，不能绕过：

- SSS 优先识别；
- SSS 材料保护；
- 材料安全三态判断；
- 切换英雄动态证据；
- 来源页面和允许目标页面；
- 受限重试；
- 传送事务目标保留；
- 结果页和返回列表确认；
- 超时诊断和安全停止。

其他路线继续保留当前安全边界并标记为实验功能。本轮产品化只增加外围环境检测、运行隔离、停止和诊断导出，不借机批量修改业务判断。

## 8. 诊断导出与隐私

一键导出的 ZIP 至少包含：

- 应用版本；
- 模板包版本；
- Windows 基本版本信息；
- 模拟器和窗口尺寸；
- 所选路线与次数；
- 本次完整日志；
- 当前监控帧；
- 本次失败诊断截图；
- 结构化事件记录；
- 导出内容清单。

导出前必须排除：

- `EPIC7_PUSHPLUS_TOKEN` 及其他环境变量值；
- 用户主目录等不必要的绝对路径；
- Git 凭据、系统凭据和账号密码；
- 与本次运行无关的历史截图和日志。

导出完成后明确提示“诊断包可能包含游戏画面和玩家昵称，请在上传前自行检查”。程序不自动打开 Issue、不自动上传 ZIP。

## 10. Windows 打包

首版技术组合：

```text
Tkinter/ttk
+ PyInstaller onedir
+ Inno Setup
```

选择 `onedir` 而非强制单文件，避免每次启动临时解压、降低误报和简化资源加载。用户仍只通过一个安装程序和一个快捷方式操作。

发布产物：

```text
第七史诗自动助手-安装版-0.1.0.exe
第七史诗自动助手-便携版-0.1.0.zip
SHA256SUMS.txt
```

用户可见名称为中文，内部程序名和安装目录使用兼容性更好的英文：

```text
Epic7AutoAssistant.exe
Epic7AutoAssistant
```

构建必须使用干净的 64 位 Python 环境，不使用包含大量无关包的 Anaconda 环境。安装包排除：

- `tests/fixtures/`；
- 测试代码和缓存；
- 历史诊断和日志；
- 开发文档；
- OpenCV 不需要的人脸模型、视频资源和示例数据；
- 其他未被运行时导入的依赖。

体积目标：安装包下载约 `60～100 MB`，安装后约 `150～250 MB`。体积是验收指标，不为了突破 30 MB 重写核心。

## 11. GitHub 开源发布

公开仓库在首发前补齐：

- `LICENSE`（MIT）；
- 中文 README 和使用手册；
- `CONTRIBUTING.md`；
- `SECURITY.md`；
- Issue 故障模板；
- 功能建议模板；
- Pull Request 模板；
- 版本变更记录；
- 自动测试和 Windows 构建工作流。

GitHub Actions 应在干净 Windows Runner 上：

1. 安装固定版本依赖；
2. 运行编译检查和全量测试；
3. 构建目录版应用；
4. 运行 GUI/CLI 启动烟雾测试；
5. 生成便携 ZIP 和安装程序；
6. 生成 SHA-256；
7. 对发布产物生成可验证的构建证明；
8. 将产物附加到带标签的 GitHub Release。

应用只读取 GitHub Releases 的公开版本信息。发现新版本时显示当前版本、最新版本和变更说明入口，由用户主动打开浏览器下载。

## 12. 错误处理

GUI 将现有退出码映射为可读结果：

| 退出码 | GUI 结果 |
|---:|---|
| `0` | 已完成目标轮次 |
| `1` | 运行故障，显示原因和诊断入口 |
| `2` | 允许的资源耗尽停止 |
| `130` | 用户停止 |

Worker 异常退出、事件流损坏或 GUI 与 Worker 失联时，GUI 显示“工作进程异常结束”，保留已有日志，并允许导出诊断。GUI 不把未知退出当作成功。

## 13. 测试策略

### 13.1 保留现有回归

当前全量测试基线为 `548 passed, 71 subtests passed`。产品化不得降低现有业务测试覆盖，也不得把固定截图从仓库测试体系中删除。

### 13.2 新增测试

- 环境检测的通过、提醒和阻止分支；
- 六条路线状态和实验提示；
- GUI 配置到 CLI/Worker 参数的映射；
- Worker 结构化事件协议；
- GUI 停止与 Worker 退出；
- 退出码映射；
- 诊断 ZIP 内容和敏感信息排除；
- 更新检查的成功、无更新、离线和异常响应；
- 安装目录只读时的数据目录行为；
- 中文 Windows 用户名和中文安装器显示名；
- 打包后模板加载和最小 dry-run。

### 13.3 发布前人工验收

- 在没有 Python 的干净 Windows 环境安装；
- 安装、启动、停止、卸载；
- 便携版解压启动；
- 标准雷电环境检测通过；
- 错误分辨率被阻止；
- 英雄合成正式功能完成一轮；
- 至少一条实验路线显示提示并能进入现有流程；
- 断网时程序可用，仅更新检查失败；
- 诊断包可导出并人工确认不含 Token；
- GitHub 下载文件 SHA-256 与发布值一致。

## 15. v0.1.0 完成标准

- 没有 Python 的 Windows 电脑可以安装并启动；
- GUI 展示六条路线及正确状态；
- 英雄合成为正式功能，其他五条为实验功能；
- 环境不兼容时禁止启动；
- 自动化运行不阻塞 GUI；
- GUI 停止按钮和 `P` 停止可用；
- Worker 崩溃不会让 GUI 无响应；
- 日志、当前帧和失败诊断正常生成；
- 诊断 ZIP 可导出且不包含 Token；
- 安装包不包含 `tests/fixtures`；
- 安装版和便携版均通过干净 Windows 烟雾测试；
- 安装包目标不超过 `100 MB`，超出时必须提供体积清单和处理结论；
- 全量测试不少于当前基线且无失败；
- Release 提供安装包、便携包、SHA-256 和构建来源；
- 更新检查只提示，不静默安装；
- README、安装器和首次启动页包含一致的项目边界与风险说明。

## 16. 工作量预估

预计 6～10 个经过测试和审查的开发批次：

- GUI 与环境检测：1～2 批；
- Worker、停止和结构化事件：2～3 批；
- 诊断导出与配置：1 批；
- Windows 打包和体积优化：1～2 批；
- GitHub 构建、发布和文档：1～2 批。

最大不确定性不是 GUI，而是第一次在干净 Windows 环境验证 PyInstaller 依赖、杀毒软件提示、中文用户路径、模板加载和安装卸载行为。
