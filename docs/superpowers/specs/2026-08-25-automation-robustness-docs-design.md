# 自动化稳健性文档整理设计

## 目标

把英雄合成本轮实机闭环中已经验证有效的原则沉淀为仓库级文档，使后续开发者和 Agent 能够：

1. 明确一个动作的进入标志、离开标志、业务成功标志和失败证据。
2. 看见其他路线与该标准之间的差距，并从统一待办中逐项改造。
3. 按使用手册安全启动、停止、诊断模拟器或 PC 客户端路线。
4. 在不破坏当前已验证代码的前提下逐步提高复用性。

本次只修改文档，不批量重构业务状态机、Action 类型或 Runner：

- 新增使用手册。
- 新增视觉自动化转场契约规范。
- 新增统一待办，记录六条路线的审计结果、优先级和验收条件。
- 更新 README、架构、新路线指南和 PC 迁移文档的入口及过时描述。
- 运行文档一致性检查、编译检查和全量测试，并提交到本地 `main`。

英雄合成文件拆分、公共 Action 契约实现、各路线 Runner 统一和 PC 实机迁移均只进入待办，不在本次实施。

## 文档结构

### `docs/USER_GUIDE.md`

面向使用者，覆盖：

- 环境安装和六种模式说明。
- 中文启动器、命令行干跑和实跑命令。

- 常见故障的处理顺序和 PushPlus 的非业务故障说明。

### `docs/TRANSITION_CONTRACTS.md`

面向开发者和 Agent，定义每个可点击动作必须回答的六个问题：

1. 当前稳定页面是什么。
2. 哪些正向证据允许进入该动作。
3. 哪些噪声和未知证据必须阻止动作。
4. 点击后允许到达哪些页面。
5. 什么联合证据才算业务成功。
6. 超时或重试时保存哪些可复现证据。

规范同时定义三态安全分类、事务目标保留、循环完成锚点、动态切换证据、日志字段和 PC 迁移要求。英雄合成作为已验证参考，不要求其他路线直接复制其内部实现。

## 六条路线的审计口径

| 路线 | 当前结构 | 本次审计重点 |
| --- | --- | --- |
| 主线 | `ModeRunnerBase` | 动作缺少显式来源/目标页面；多种结算分支的循环完成依据 |
| 竞技场 | 独立 Runner | 转场确认稳定帧数、重试日志、资源购买事务边界 |
| 远征 | 独立 Runner | 转场重试、公开招募双层返回、未采集结束页面 |
| 狗粮 | `ModeRunnerBase` | 重新进行与循环计数、体力弹窗前后页面契约 |
| 辅助自动 | `ModeRunnerBase` | 内置 30 次循环与外层 cycle 的边界、无需导航的启动条件 |
| 英雄合成 | `ModeRunnerBase` + 专用契约 | 作为参考基线；记录 PC 契约尚未启用及大文件拆分待办 |

审计结论区分三类：

- 已具备：代码和测试均有正向证据。
- 部分具备：有目标状态检查，但日志或入口契约不完整。
- 待实证：缺少当前客户端完整截图或完整实跑，不能判断为支持。

## 稳健性原则

### 点击不是成功

动作成功至少需要目标页面证据；同页面内部切换还需要业务字段变化或可解释的动态过程。日志不得在只有点击或画面噪声时写“成功”。

### 未知优先停止

安全分类采用 `SAFE / UNSAFE / UNKNOWN`。高风险对象优先识别；`UNKNOWN` 不得降级为普通对象。缺少必需模板也属于 `UNKNOWN`，不能失败放行。

### 事务目标持续保留

传送、购买、合成等多步骤操作从入口确认开始保存目标，直到奖励或最终返回锚点稳定出现才清理。中间页面不得因为重新识别失败而换目标。

### 动态证据必须限定区域

动态变化只在能代表业务变化的区域内计算，并与稳定前后帧联合使用。英雄呼吸、武器、粒子、动态角标和背景动画不能单独证明业务成功。

### 一轮只在稳定入口计数

最后一次确认点击、结果动画或覆盖层消失都不是循环完成。必须重新看到路线定义的稳定入口后才能增加 `completed_cycles`。

## 验证标准

完成条件：

1. README 中模式数量、启动器菜单和 `MODE_SPECS` 一致，均为六条路线。
2. 使用手册中的命令能通过 CLI 帮助和参数校验静态核对。
3. 所有新增相对链接指向现存文件。
4. 待办覆盖六条路线、共享层和 PC 迁移，并包含可验证验收条件。
5. 文档不把候选 PC 模板表述为已支持，也不把推测表述为已确认故障。
6. `python -m compileall -q .` 与 `python -m pytest -q` 通过。
7. 最终工作区干净，文档提交位于本地 `main`。

## 非目标与后续边界

- 不移动或删除历史设计、测试 fixture、模板、日志目录结构。
- 不因为文件较大而立即拆分 `hero_synthesis.py`。
- 不在缺少实机证据时修改识别阈值、坐标或页面状态。
- 不声称任何 PC 路线已经完成迁移。
- 不创建远程 Issue 或推送远程仓库；统一待办保存在 Git 内，供所有本地或后续 Agent 使用。
