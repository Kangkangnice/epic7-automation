# 路线开发、更新与维护规范

每个有副作用的动作都要能回答四个问题：**现在能点什么、点后如何知道离开旧状态、什么证明到了预期状态、什么证明业务真的发生了。** 证据缺失时，路线应停在可解释、可排查的状态。

本页统一开发、维护、修复和体检的工作顺序。路线须声明的五项见[路线通用契约](../ROUTE_CONTRACT.md)，动作判据见[页面转场契约](../TRANSITION_CONTRACTS.md)，运行结论与放行门槛见[路线稳定版验收](route_acceptance.md)。每条路线的具体画面、判据与资源边界写在自己的维护手册。

## 1. 先定义这次交付

验收单位是 **路线 × 后端 × 客户端及版本 × 待验提交 × 设置分支**。默认分支、资源开关、只读和实际业务分别登记；列出影响结果的账号状态，以及入口是大厅、已在路线内的接力、桌面每日编排，还是路线规定的手动起点。合并范围按玩家可观察行为及实际调用方判断，参见[按行为做回归](../decisions/0011-behavior-based-regression.md)。

开工记录直接复用本次 PR、交接单或本地验收记录。先写[验收合同的六项](route_acceptance.md#2-开工前写验收合同)，加上受影响的动作和共享调用方、现场依据、明确禁止触碰的对象、准备怎么验证。新增动作还须写清前后状态。一次局部修复可引用原合同未改变的条目，点名本次要复验的差异。

| 变更 | 开工前明确 | 最小验证范围 |
|---|---|---|
| 新增路线或扩大支持 | 目标、数量、合法入口与终点，路线五项声明，页面与动作清单，接力策略与危险边界 | 新增组合的正常入口全过程、相关反例与放行证据 |
| 维护、游戏更新或 PC 移植 | 哪些客户端、账号变体、设置、模板或业务状态变化，哪些旧证据仍可引用 | 变化分支和相邻既有分支；涉及 PC 时验目标 PC 通道及原有模拟器回归 |
| 修故障 | 保存首个故障，写出应见的状态、预期动作或禁止动作，用真实现场构造能在旧行为下失败的回归 | 现场复现、修复回归、相邻反例，及受影响的正常入口、业务结果和收尾 |
| 改共享层 | 列真正经过该逻辑的路线、各自的入口和输入通道；记录收尾、资源和事件归属影响 | 受影响调用者并集，按[贡献指南](../../CONTRIBUTING.md#按改动选测试)选回归；共享或未登记的运行改动走全量离线回归，优先实机复验受影响的高风险组合 |

四类可以同时命中，验收取并集。游戏更新的降级、复验和恢复按[游戏更新手册](game_update.md)执行。

## 2. 所有动作都要长眼睛

动作包括点击、滑动、Back、入口导航、弹窗处理、战斗移交和收尾。任何会改变页面、选择、资源或业务计数的动作，都应能在正常执行链上找到判据。可复用已有导航、识别、事务或窗口机制，并用真实入口证明机制确实被调用。路线自带循环时，也要证明它有等价护栏。

| 五段证据 | 开工时写清的内容 |
|---|---|
| ① 来源进入 | 页面、子状态、窗口或设备、授权和目标对象。要点哪个控件，如何证明控件可用，哪些遮罩、禁用态、相似对象和未知状态会阻断它 |
| ② 候选动作 | 动作名、触发条件、坐标或控件依据、预期目标、预算和允许的副作用。发出输入时只记录尝试 |
| ③ 来源退出 | 说明旧页面或旧的页内状态如何被证明确实退出，以及如何识别黑屏、加载、动画、冻结帧或覆盖层 |
| ④ 目标进入 | 给出允许到达的页面或明确的页内新状态，以及它的正向判据。结束时也要验证终点；蒙层遮住目标时继续按当前状态和预算裁决 |
| ⑤ 业务完成 | 列真实结果、数量、资源核对和记账时机。纯导航动作的本步完成是目标可用，路线业务完成在承诺的业务回执处核对 |

同页动作使用可区分的前后状态，例如「页签 A 选中 → 页签 B 选中」或「同一商品可买 → 该行已购，价格和数量符合」。同页动作须声明页内证据并在运行中读出实际变化。页面和结论的稳定门槛沿用[转场契约](../TRANSITION_CONTRACTS.md#结论门槛全局强制)，用新采的相邻帧验证同一结论；冻结或缓存的重复帧不得充数。来源消失、目标到达、业务回执各自采证。

| 点后观测 | 运行行为 |
|---|---|
| 来源仍稳定，且动作明确可重试 | 在来源、对象、阻断条件仍满足时按间隔、次数和总时限重试 |
| 来源已退出，目标或回执尚在等待 | 保留原动作的目标与业务意图，等新画面；过了时限仍无结论则留证失败 |
| 目标或页内新状态稳定 | 确认本步转场；达到约定业务回执后才更新业务计数，同一笔只记一次 |
| 画面冲突、证据缺失、遇到覆盖层 | 暂停原动作。已识别覆盖层交给约定处理方，按复验条件接回。未知画面只允许契约中已证明安全且有上限的恢复 |
| 不可逆操作已发出，执行结果未明 | 停止再次提交并留证对账，即使确认框还在。用当前结果页、库存或可核对的业务状态决定后续处理 |

危险确认须同一操作现场核对授权、对象、可用控件及适用的价格、数量和资源余额或限额。程序重启、重复启动、回执迟到和异常收尾都须保持已经发生的业务事实。关键安全模板缺失应由护栏拒绝；两次点击之间有过等待或刷帧，本身不能证明可以再次扣费。

## 3. 从现场到交付

| 顺序 | 做什么 | 怎么验证 |
|---|---|---|
| 1. 画出本次路径 | 从玩家入口到业务回执再到合法终点。为每个动作填五段证据，注明接力点、覆盖层归属及断点后的下一步 | 对照真实页面及调用链，确认每个会改变下一步的状态都有判定与出口 |
| 2. 补齐变体与反例 | 列本次受影响的正常状态、记忆页签、账号或活动变体、遮罩、加载或冻结、空态、禁用态、迟到回执等适用场景。注明预期完成、有证据的停止，或未知时的安全行为 | 判据说明写明如何排除最相似的反例；用整帧、分数或其他量化依据复核，视觉阈值按[可证伪决策](../decisions/0002-criteria-must-be-falsifiable.md)处理。缺现场的分支登记待验及安全出口 |
| 3. 先回放失败再实现 | 修复前用现场帧、序列或等价可复现场景触发根因。优先复用现有识别、执行和事务设施，修改最小的行为边界 | 保存旧行为失败、新行为通过的测试节点和结果。护栏通过正常入口或真实循环验证，断言应发生的输入、明确禁止的输入、实际记账与终点 |
| 4. 验本次提交 | 依[实机闭环验证](live_verification.md)和[路线稳定版验收](route_acceptance.md#4-每次验什么)运行相应离线和已授权实机验证，保留本次计划的全部尝试。资源交易以同一次执行的请求、实际回执、用量和终点对账 | 日志能关联启动边界、前后状态、输入尝试、拒绝或等待原因、首个故障与最后结论。离线、历史、局部和干跑记录照实记录；公开稳定按现行发布门槛独立复核 |
| 5. 收口 | PR 或提交记录受影响分支和证据，维护手册更新变掉的规则，缺口登记到[待办](../TODO.md)，现状有变时用生成器更新 [STATUS](../STATUS.md) | 复核最终版本与验证版本一致；手册、声明和运行行为相符；本次支持范围、回退范围与待验分支可查 |

### 收尾和接力怎么验

- 开局能从半途中接管时，回放该入口与相似误入页；终态、不可逆确认页及豁免按[接力契约](../TRANSITION_CONTRACTS.md#接力契约路线准入的另一半)核对。接力已有业务的进度须来自可查状态。
- 空态、额度用完、冷却等必须有正向停止证据。只读达到约定读数按只读合同完成。业务已发生但退场失败，保留实得数量并记录本次失败。恢复动作完成后仍保留首个故障。
- 正常入口的单轮闭环、连续两轮或重复启动的离线回归、每日队列入口的真实交接各自取证。每次独立启动的结论只取一个，沿用 [五种运行结论](route_acceptance.md#3-一次启动只有一个结论) 和[量化门槛](route_acceptance.md#5-量化门槛和记录)。

在维护手册或本次验收记录写一行即可，已有判据和测试可引用。一个动作需要有可读的依据，运行期仍以真实证据裁决。

| 动作与入口 | 点前来源与阻断 | 点后旧态退出与新态进入 | 业务回执与计数 | 超时与恢复 | 反例、结果与证据位置 |
|---|---|---|---|---|---|
| 竞技场从「战斗记录」切到玩家选定的对战页签 | 先确认竞技场外壳且当前为非对战页签，按设置选择目标；未确认外壳则不点 | 旧页签退出，同时以玩家所选的对战列表判据稳定确认到达 | 本步只完成入场；挑战次数由后续真实结算计 | 来源仍成立时按路线预算处理，耗尽报入场故障并留证 | 已有现场帧和导航回放，见 [竞技场维护手册](../maintenance/arena.md)与提交 `5e876d9` |

## 4. 返工按故障追踪

返工统计用于找热点。以「受影响组合、玩家行为、失败机制」标识一条故障，记录原修复、复发现场和新反例。一次提交可以关闭多条故障，一条故障也可以跨多个提交。缺少记录时，历史只报告可观察的提交、改动块、函数和现有运行证据。

- **同一锚点第二次复发**：补能区分现场同类对象的反例，再决定是否改变判据。记录旧修法为何在该现场失效。
- **同一失败机制第三次修正**：停掉原有补丁方式，重新核对状态模型、动作回执、执行通道及责任层，先用同一现场证明新方案可证伪。若发现公共原因，列消费者并按共享变更验证。
- **确认或怀疑发生越权、重复提交、扣费异常、虚报完成**：立即暂停受影响组合的放行并对账，按[路线稳定版验收](route_acceptance.md#5-量化门槛和记录)恢复。
- 每次变更记录现象、根因、受影响行为、离线回放、实机结论或待验项。批量提交逐条列路线与行为；共享代码还要列消费者。历史返工数量用于安排复核；当前组合的技术证据和发布门槛决定能否签字。

`report_rework` 仍可看趋势。其首触路径日期和七天窗口是近似值；上线当天、标题分流、只改共享层、合并收口与未提交试错都会影响结果。工具的 `@@` 改动块反映 diff 规模，`--hot` 反映当前保留代码中的提交分布。要找具体返工，沿 diff 和现场证据复盘。对比历史数字时写清基线和统计口径。

## 5. Agent 体检与评分

**先核硬门，再算风险缺口分。** 对每个拟支持组合单独出表，固定待验提交。工作区候选单列并标明基线与改动来源。先从正常入口追实际执行链，列出导航、路线主循环、共用弹窗及收尾的输入点，再按表核证。汇总整条路线时列出全部组合和最差结论，按最高风险分排队。

每项只有三种评分状态。**通过 0 分**需可打开的依据覆盖项目所列全部适用要求；**缺证 10 分**指看得到声明、代码或部分样本，仍缺指定证据；**不通过 10 分**指已观察到冲突、失败或实际护栏缺失。先判不通过，再判缺证。未检查记为缺证。某子条件不适用时写出已核对的入口、声明或业务边界，其余条件照常判定。十项相加，范围 0–100，分数越高缺口越多。

| 项 | 通过所需证据 |
|---|---|
| 1. 范围与合同 | 六项验收合同、注册五项、设置与接力范围、维护手册相符；新旧证据可追到版本 |
| 2. 状态与变体 | 改变下一步的状态有正例与最近似反例或可复现场景；未知态能安全停止，覆盖层有处理归属及接回点 |
| 3. 动作前证据 | 所有作用于页面、选择或资源的输入点能追到可执行的来源、目标对象和阻断护栏；遮挡与冲突反例能阻止输入 |
| 4. 动作后证据 | 换页有来源退出和目标稳定，留在本页时有可区分的新状态，正常执行链实际读取这些证据 |
| 5. 等待与恢复 | 来源未变、黑屏或冻结、迟到回执、超时均有可观察结果及明确上限，重试或恢复不会绕开原护栏 |
| 6. 资源与授权 | 有副作用的分支有权限、对象、限额和禁止重复提交证据；有疑义的历史交易已对账。无资源分支有对应限制或核对记录 |
| 7. 业务与终点 | 完成量由真实回执更新；空态有正向证明，部分完成和首个故障保留；合法终点及适用的接力、串跑边界在执行链上有验证 |
| 8. 离线回归 | 有本提交的完整测试节点与结果，覆盖稳定版验收要求的适用类别；当前修复有旧失败、新通过证据；共享改动覆盖消费者 |
| 9. 实机闭环 | 待验组合有正常入口的授权闭环、全部已执行尝试的边界、预期/实得、用量和终点，原始材料可核；只读和干跑如实归属 |
| 10. 放行与复核 | 该组合有独立评审结论、证据与范围一致；尚未支持的设置、客户端和历史试用未被写入稳定声明 |

硬门结论按具体组合记录。已确认的违规、护栏缺失、当前实机失败或待对账交易记「阻断」；适用证据尚未齐全记「待验」；核完关键动作回执、安全、正常入口、业务与终点，并达到[稳定版验收](route_acceptance.md#5-量化门槛和记录)才记「通过」。

整改依次处理疑似或已确认的误点、越权、重复提交、虚报完成及待对账交易，危险动作护栏或证据缺口，其他运行阻断，其余待验。相同优先级先处理影响多个组合的共同根因，再看分数和影响范围。历史返工量另列。

评审交付可放在本次体检记录。每一行分数必须能复算：

```text
路线 / 后端 / 客户端及版本 / 提交 / 设置分支
入口、账号状态或环境代号、支持边界
硬门结论（通过 / 阻断 / 待验）和具体原因
每项编号 | 通过 / 缺证 / 不通过 | 分数 | 代码、测试结果、运行 ID 与日志位置 | 最小修复与复验条件
总分 / 当前支持结论 / 最高优先缺口
历史返工（可选，注明基线和口径）
```

同一条反例可支持多项结论，逐项写出它证明的要求。整改前后使用同一组合和准则，改变设置或版本时声明范围。测试列表、路径名和合规工具输出可作索引，评审须打开对应断言、执行结果及原始业务依据。

## 6. 对既有分析的复核

| 核对对象 | 复核结果与据此采用的规则 |
|---|---|
| 返工集中在哪里 | 旧分析在 84 个明确路线修复样本中将 75 个归为转场、判据和页面状态问题。这支持优先检查这三项，样本由明确修复标题筛出，推断限于该样本。基线 `5dc3593` 重扫 438 个提交，按路线汇总 200 次修正类提交命中，其中 88 次标题带 `fix`；同一提交可计入多条路线。社区签到 `4b82549` 同时改了竖屏取图、页面判据、动作与收尾；月塔 `5d22584` 同时改了共享事务循环；竞技场 `5e876d9` 的修复主要在共享导航。后续按故障和调用者复盘 |
| 代码声明能证明什么 | 基线 `5dc3593` 的 `route_compliance --strict` 给 21 条路线全部标「达标」，同时明确输出狗粮和活动的回执欠债。按评分第 4 项，狗粮动作回执记「不通过」10 分，证据是 `FodderAction` 的回执字段留空及注册豁免。单项校准不推导全路线总分 |
| 证据和旧评分怎么用 | [11 月 25 日体检](../ROUTE_HEALTH_CHECK.md)提供具体风险与证据线索。旧表只给维度权重，缺少分档规则，且混入历史返工、工作区状态，并把未放行客户端缺证并列进路线级分数。新体检固定组合与版本，检查证据和硬门，重新算分 |
| 实机结论怎么复核 | [装备制作历史证据](../SAFETY_MATRIX.md)记录一次制作完成 20 件后异常收尾。按合同是业务有实得、整次 `failed`，本次现场不可为补终点重做制作。旧体检建议的两轮、跨天或更多账号用于定位具体故障时可以取证；稳定准入以现行验收文档为准 |
