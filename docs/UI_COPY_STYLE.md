# 界面文案规范（说明 / 指南体）

> 适用范围：**所有面向使用者的固定文字** —— 路线说明、分组说明、启动提示、结果卡与
> 通知、状态词、各页面标签与提示、使用须知条款、以及「一句话结果」这类结算文案。
> 不适用：运行日志内容、诊断输出、代码注释、给开发者看的文档。
>
> 机器护栏：`tests/test_ui_copy_style.py`（口语词、平台名单硬编码、分组漏项）、
> `tests/test_desktop_catalog.py::test_the_interface_text_never_leaks_code_jargon`（实现术语）。
> 改文案先读本页，改完跑这两个文件。

## 一、表述基准（依据实际字符串，不是印象）

取自参考项目与竞品的**实际界面文字**：

- **绝区零一条龙**（`similar_auto_project/_reference/zzz-od`）的配置项说明：
  `应用完成后发送通知`、`只在节点失败时立即通知`、`需确保使用时没有启用输入法`、
  `出现剪切板失败时 切换到输入法`；界面标签：`图像加载`、`执行颜色过滤`、`颜色下限`。
- **竞品 REA**（`其他成熟的产品/`）的功能命名：`定时竞技场`、`商店提示`、`助手提示`、
  `定时任务`、`内置路线1 / 2 / 3`、`限时故事`。

共同点只有两条，照做即可：

1. **陈述行为与条件，不与使用者对话**。写「应用完成后发送通知」，不写「跑完就会通知你」。
2. **标签是名词短语，说明是短句**。写「执行颜色过滤」，不写「点这里把颜色过滤一下」。

## 二、五条硬规矩

1. **不用第二人称、不用祈使口语、不用语气词**
   禁止：你 / 您 / 请 / 别 / 点一下 / 就行 / 没必要 / 顺手 / 搞定 / 卡住 / 这时候 /
   这样 / 吧 / 啦 / 呢 / 啊 / 嘛。
   改用：**支持 / 不支持**、**需 / 无需**、**可 / 不可**、**固定 / 可调整**、
   **执行 / 不执行**、**即结束 / 即停止**。
2. **不写实现细节**
   禁止：识别 / 判定 / 阈值 / 模板 / 锚点 / 坐标 / 按钮 / 滚轮 / 拖拽 / 素材 / 后端 /
   字段 / 参数 / 代码 / 程序 / 算法 / 转场。
   写业务结果与业务前提：「战斗动画跳过」「需先将游戏停留在「观看故事」页面」。
3. **不写死会变的名单**：平台放行范围由 `PC_READY_ROUTES` 决定、启动时由
   `STARTUP_HINTS` 统一说明；文档与界面都**不逐条列已放行路线**。写死名单正是历史上
   反复过期的根因（PC 放行后没人回来改文案）。单条路线跑不跑得动，由
   `catalog.unavailable_note(mode, backend)` 按名单**算**出来显示（见第三节
   「路线状态提示」），同样不许写进说明正文。
4. **只写可验证的事实**：次数、默认值、固定项以 `MODE_SPECS` 为准；分组内容以
   `grouped_routes()` 为准。不写「以后会支持」，不写推测。
5. **不用 Markdown，不用「=」当解释符**。`**重点**` 会在 Label 里显示成星号；
   `点这个框 = 整组选中` 属口语加法号，改写为「勾选分组标题可整组选中」。

## 三、各类文案的结构

**路线说明**（`desktop/catalog.py::ROUTES[*].description`，三段，`\n` 分隔）

```
第 1 段：本路线执行的业务动作
第 2 段：可调整项 / 不可调整项 + 「一轮」的范围
第 3 段：「注意：」+ 消耗、不执行的操作、启动前提
```

**结算文案**（`games/epic7/daily_tasks.py` 与各 Runner 的 `route_note()`）

- 总账：`任务 N 项 · 完成 X 项 · 无剩余内容 Y 项 · 总用时 M分S秒`
- 明细：`<路线名> · <状态词> · <进度> · <收获> · <耗时> · <失败原因>`
- 状态词只来自 `STATUS_WORDS` 一处：完成 / 无剩余内容 / 失败 / 未执行 / 当前环境不支持。
- **只报收获，不做收支账**；没有可靠计数的路线只报由收工判据保证的结论，不编数字。

**界面标签**

- 名词短语：`检测环境`、`开始任务`、`安全停止`、`运行结果`、`取消关机`。
- 状态词统一：`执行中` / `已完成` / `待执行` / `已停止`。
- 提示句用陈述：`尚未执行环境检测。`、`需先执行环境检测。`、`至少选择一项后方可执行。`

**路线状态提示**（`desktop/catalog.py::unavailable_note()`，显示在说明卡标题正下方）

- 内容由名单算，不写在说明正文里：PC 上未放行 →「该路线尚未在 PC 客户端通过验收，
  运行计划将跳过此项。」；模拟器上只在 PC 提供 →「该路线当前仅在 PC 客户端提供，
  运行计划将跳过此项。」
- 判据必须与 `desktop/controller.py::resolve_plan()` 同源，否则会出现
  「界面说能跑、跑起来却被跳过」；`tests/test_ui_copy_style.py` 逐条比对两边的结论。
- 没有这行提示时整块隐藏，不留空白把标题与正文撑开。

## 四、常用改写对照

| 不要说 | 要说 |
|---|---|
| 替你刷主线 / 打哪一关由你定 | 执行主线关卡 / 关卡由启动前游戏停留的位置决定 |
| 打完点「重新进行」接着打 | 完成后执行「重新进行」继续 |
| 没得做了 / 本环境跑不了 / 没跑 | 无剩余内容 / 当前环境不支持 / 未执行 |
| 这轮没买到书签 | 本轮未购入书签 |
| 今天已经探险过 | 当日探险已完成 |
| 看了 4 幕 / 打了 2 场 | 完成观览 4 幕 / 完成首领战 2 场 |
| 还没读过 / 没读到 | 尚未读取 / 未读取 |
| 点这里查看 | 查看更新说明 |
| 还在电脑前请点「取消关机」 | 如需取消，可使用「取消关机」 |
| 只支持模拟器 | （不写；改由 `unavailable_note()` 按名单算，显示在标题下方） |

## 五、什么时候可以例外

- **合规与风险声明**（`desktop/onboarding.py::RISK_POINTS`）：必须写明「不读取或修改内存、
  网络数据与客户端文件」这类边界，允许出现技术名词 —— 这里的准确比通俗重要。
- **不可逆操作的警示**：可以说「不可撤销」「需确认」，但不许用「千万别」这类口语。
- **运行日志与诊断**：不受本页约束，按排障需要写。
