# 页面转场契约

自动化中的一次点击不等于业务成功。每个会改变页面或业务状态的动作，都应当写清楚“允许从哪里点击、看到什么才算进入、看到什么才算完成、失败时留下什么证据”。这份约定用于新路线开发、现有路线审计和实机故障复盘。

## 基本原则

总原则是：**点击不等于成功**，安全结论必须明确属于 `SAFE / UNSAFE / UNKNOWN` 三态之一。

1. **点击只是候选动作**：日志只能写“已点击/等待确认”，不能在目标证据出现前写“成功”。
2. **先确认来源，再允许点击**：来源页面不明确时，不靠坐标猜测；返回 `UNKNOWN` 并保存诊断。
3. **安全判断采用三态**：
   - `SAFE`：正向证据充分，可以继续。
   - `UNSAFE`：发现明确阻断证据，必须停止或转入安全分支。
   - `UNKNOWN`：证据缺失或互相冲突，不得按 `SAFE` 处理。
4. **缺少模板时关闭危险动作**：涉及选择材料、传送、消耗资源等动作，关键模板缺失必须 fail closed。
5. **确认目标来自原事务**：重试时保留第一次点击的目标页面和业务目的，不能用当前误识别页面覆盖原目标。
6. **动态区域不能单独证明切换成功**：人物呼吸、粒子、滚动动画只能作为“发生过运动”的辅助证据；成功仍需稳定页面标志或业务状态变化。
7. **进入与退出都要稳定**：建议在连续稳定帧或等价的去抖条件满足后确认页面，避免单帧误判。
8. **循环计数只跟业务完成绑定**：点击次数、过渡动画和重试次数都不能增加完成轮次。
9. **日志必须可证伪**：记录候选动作、来源证据、目标证据、重试原因和最终结论；“未确认”不能写成“成功”。

## 点击后的观测决策

点击后不能依靠一次性 `clicked=True` 等待超时，必须继续判断来源和目标：

| 稳定观测 | 含义 | 允许动作 |
|---|---|---|
| 来源仍在，目标未到 | 点击未生效 | 记录来源证据，在额度和冷却满足后重试 |
| 来源已离开，目标未稳定 | 正在转场或结果待确认 | 只等待，禁止重复旧动作 |
| 目标稳定进入 | 转场完成 | 记录来源退出和目标进入，进入下一状态 |
| 来源与目标冲突，或两者均无法判断 | `UNKNOWN` | 保存证据并失败关闭或执行契约声明的有限恢复 |

可逆导航动作只在来源仍稳定时重试。不可逆动作在来源消失后不得重试，因为业务可能已经执行而回执尚未出现。来源、目标和业务结果必须分别去抖；一个目标帧不能倒推此前每次点击都成功。

## 契约模板

实现或审查一个动作时，复制并填写以下字段：

```text
动作名称：
来源页面：
进入正向证据：
阻断证据 / UNKNOWN 条件：
点击坐标依据：
允许目标页面：
业务成功证据：
重试条件：
失败诊断：
循环计数影响：
```

字段说明：

- **来源页面**：动作被允许执行的页面状态。
- **进入正向证据**：确认已进入来源页面的稳定视觉或状态证据。
- **阻断证据 / UNKNOWN 条件**：明确危险标志、关键模板缺失、识别冲突或证据不足。
- **点击坐标依据**：固定布局、模板中心或经窗口缩放换算后的逻辑坐标。
- **允许目标页面**：点击后可以合法抵达的页面集合。
- **业务成功证据**：能够证明业务结果已经发生的证据，而不是动画或局部变化。
- **重试条件**：来源仍成立、目标未出现且未发现危险状态时，才允许重试。
- **失败诊断**：至少保存最终截图；高风险或难复现动作应保存前后帧、裁剪区和量化指标。
- **循环计数影响**：说明何时加一，通常只有业务完成证据成立时才加一。

## 推荐日志语义

```text
动作候选 action=<name> source=<page> evidence=<summary>
执行点击 action=<name> attempt=1/4 point=(x,y) targets=<pages>
等待确认 action=<name> observed=<page> remaining=<seconds>
转场未确认 action=<name> reason=<reason> retry=<n/4>
转场确认 action=<name> target=<page> evidence=<summary>
业务成功 action=<name> result=<result> cycle=<n>
安全停止 action=<name> state=UNKNOWN diagnostic=<path>
```

“转场确认”和“业务成功”是两个不同层次。例如进入合成页面只证明页面切换完成，只有结果页出现并被正确关闭后，才证明一次合成事务完成。

## 英雄合成示例

### 切换英雄卡片

- 来源页面：英雄详情/列表中的当前英雄卡片稳定可见。
- 进入正向证据：中心选中框、详情区域和列表结构满足英雄详情页条件。
- 点击坐标依据：下一张英雄卡片的固定槽位或经过标定的逻辑坐标。
- 允许目标页面：仍为英雄详情页，但选中事务必须经历可解释的切换过程。
- 业务成功证据：过渡动态已经结束，详情页重新稳定；能区分时使用身份特征，两个副本外观相同时不能只比较英雄立绘。
- 重试条件：点击后既未观察到切换动态，也未观察到稳定目标状态，并且来源页面仍成立。
- 失败诊断：保存点击前、动态峰值帧、点击后稳定帧和各 ROI 差异指标。
- 循环计数影响：无。

### 进入合成

- 来源页面：目标英雄详情页。
- 进入正向证据：合成/记忆刻印入口可操作，页面无弹窗遮挡。
- 阻断证据 / UNKNOWN 条件：入口置灰、页面身份不明或关键模板缺失。
- 允许目标页面：合成材料选择页。
- 业务成功证据：材料区域、确认区域等合成页稳定标志同时成立。
- 重试条件：详情页仍成立且目标页未出现。
- 循环计数影响：无。

### 选择材料

- 来源页面：合成材料选择页。
- 进入正向证据：材料卡区域和确认区域稳定可见。
- 阻断证据 / UNKNOWN 条件：任一候选材料识别为 SSS，或 SSS 判断证据不完整。
- 业务成功证据：安全材料已进入选中状态；仅“看见材料卡”不等于可以点击。
- 重试条件：只能在安全判定仍为 `SAFE` 时重试。
- 失败诊断：保存材料卡原图、SSS 检测区域、匹配分数和候选排序。
- 循环计数影响：无。

### 遇到 SSS 后退出并传送副本

- 来源页面：合成页或英雄详情页，且目标英雄已确认达到 SSS。
- 进入正向证据：SSS 为稳定正向证据，不依赖单帧动画。
- 点击坐标依据：先退出合成页，再进入传送流程；每一步单独确认。
- 允许目标页面：英雄详情页 → 传送选择页 → 传送确认/完成页。
- 业务成功证据：传送完成结果出现，随后回到允许的英雄页面。
- 重试条件：只对当前尚未确认的转场重试，不重复已经确认的消耗动作。
- 循环计数影响：按英雄处理事务定义计数，不按退出或点击计数。

### 关闭合成结果并返回列表

- 来源页面：合成结果页。
- 进入正向证据：结果标题或结果主体稳定出现。
- 允许目标页面：英雄详情页或英雄列表，以动作契约声明为准。
- 业务成功证据：结果页消失且目标页面稳定出现；不能用“已点击关闭”替代。
- 重试条件：结果页仍存在时可重试关闭；已经离开结果页时不得盲点原坐标。
- 失败诊断：保存结果页、点击后页面和最终超时截图。
- 循环计数影响：仅当本次合成结果已确认且收尾页面成立时完成事务。

## 模拟器刷书签示例

### 扫描一批商品

- 来源页面：秘密商店商品列表稳定可见，标题、`立即更新=3` 与同行购买按钮结构同时成立。
- 扫描顺序：先扫描顶部；随后执行一次列表滑动，只有观察到列表内容发生明显变化并重新稳定，才允许扫描底部。
- 阻断证据 / `UNKNOWN`：目标图标成立但同行购买按钮缺失时，只有该槽位刚刚完成过购买才可解释为“已售”；否则立即停止，不把识别不完整当成普通商品。
- 循环计数影响：顶部和底部都扫描完才完成一个批次；初始批次不计入付费刷新次数。

### 打开并确认购买

- 来源页面：誓约书签或神秘书签图标成立，且同一商品行的购买按钮可操作。
- 允许目标页面：与来源商品类型一致的购买确认框。
- 可逆重试：打开确认框后若目标未出现，只有原商品和同行购买按钮仍成立时才允许受限重试。
- 不可逆动作：购买确认最多点击一次；确认框离开后只等待业务结果，不再点击原确认坐标。
- 业务成功证据：购买框已经离开，原槽位仍能识别为同种书签但不再有可操作购买按钮；此时才分别增加誓约或神秘的购买次数与金币花费。
- 阻断证据 / `UNKNOWN`：确认框商品类型冲突、回执不明确、未知弹窗或未购买过的目标槽位缺少购买按钮时保存诊断并停止。

### 打开并确认付费刷新

- 来源页面：本批顶部和底部均扫描完成，且秘密商店的 `立即更新=3` 按钮稳定可见。
- 允许目标页面：当前客户端刷新确认框。
- 可逆重试：打开确认框失败时，仅在 `立即更新=3` 来源仍成立时受限重试。
- 不可逆动作：刷新确认最多点击一次；确认框离开后不得再次点击确认。
- 业务成功证据：确认框先离开，随后商品列表发生变化，并以不同于刷新前的列表指纹重新稳定为商店顶部。确认弹窗本身的变化不计为刷新动态。
- 循环计数影响：只有业务成功证据成立才增加一次付费刷新并记入 3 钻石；最后一次刷新后的新批次仍必须完整扫描。

### 本轮统计与安全边界

- 输入 `N` 表示执行 `N` 次付费刷新，共扫描初始页面加刷新后的 `N` 个页面，即 `N + 1` 批。
- 初始页面与付费刷新页面的誓约、神秘购买次数分开记录；付费命中率不包含初始页面。
- 只保留本轮日志汇总，不写历史统计文件。
- 金币不足停止整条路线；钻石不足停止后续刷新。当前不足资源页面尚无当前客户端固定样本时，未知弹窗按 `UNKNOWN` 安全停止。
- 首版只支持雷电模拟器；PC 后端在创建窗口和执行动作前明确拒绝。
- 誓约与神秘书签均已有当前客户端商品行、购买价格和购买后 `0/1` 已售槽位固定样本；两种真实购买事务均完成回放测试。代码不会把业务预期价格伪装成视觉结果；空跑仍输出候选类型、分数和同行购买按钮，供游戏更新后的重新验收。

日志示例：

```text
模式=刷书签 动作候选=purchase 来源=商店顶部 目标=誓约书签 行=2
模式=刷书签 转场确认 动作=open_purchase_confirm 目标=誓约书签购买确认
模式=刷书签 执行不可逆动作=confirm_purchase 目标=誓约书签 尝试=1/1
模式=刷书签 业务成功=购买 目标=誓约书签 本轮次数=1
模式=刷书签 执行不可逆动作=confirm_refresh 尝试=1/1 价格=3
模式=刷书签 业务成功=刷新 已完成=1/10 钻石花费=3
```

## 模拟器竞技场示例

### 选择对手与点击挑战

- 来源页面：含安全对手的列表，或已经选中的对手详情。
- 点击坐标依据：首次选择后固定本轮对手行与坐标；重试不得重新随机选择。
- 允许目标页面：对手详情，或普通/快速队伍页。
- 重试条件：来源连续存在且目标未成立时最多四次；任何一帧确认来源离开后不再点击旧坐标。
- 业务成功证据：目标页面连续两帧；单次按钮匹配或执行点击日志均不代表成功。

### 快速战斗切回普通战斗

- 来源页面：快速战斗按钮和白底闪电切换键同时成立，普通战斗开始按钮不成立。
- 允许目标页面：路线自己的普通战斗开始锚点连续两帧。
- 共享范围：模拟器主线、竞技场、远征和狗粮；PC 后端仍为实验开发范围。
- 重试条件：快速来源仍在时受限重试；来源离开后只等待普通页。

### 开启自动战斗

- 来源页面：战斗结构稳定，且右上角“自动关闭”图标连续两帧成立；不等待轮到我方出手。
- 动作：点击“自动关闭”图标中心，请求开启自动战斗。
- 允许目标：右下角人物头像布局连续两帧，蓝色、红色或混合头像均可。
- 重试条件：右上角关闭图标仍在时有限重试；关闭图标消失而人物头像暂未稳定时只等待，不再点旧坐标。
- `UNKNOWN`：敌方连续行动、技能动画或我方技能尚未出现都属于正常等待，不再使用 15 秒自动确认超时；仍受战斗无活动、业务无进展和绝对时限保护。

### 战前业务弹窗优先级

- 战前业务弹窗一旦出现首帧，立即冻结并重置已经稳定的背景白名单动作；不得在等待第二帧期间点击被遮罩后的“战斗开始”等旧控件。
- 业务弹窗连续两帧成立后才交回路线状态机；若只闪现一帧，背景动作必须从零重新满足稳定条件。
- 路线观察层应避免同时上报业务弹窗和背景动作，共享战斗监督器仍须独立执行相同保护。

### 刷新、旗帜与结算

- 刷新只在三名对手均明确不可挑战时执行；免费确认必须同时识别标题、“免费”和确认按钮，刷新后列表还要连续两帧且至少有一名安全对手。
- 首轮无票和中途耗尽共用同一购买事务：点击战斗开始后，购买框首帧先冻结背景动作，连续两帧后再进入购买判断。
- 友情点购买只接受左侧已选中的“100 友情点换 5 旗帜”：购买弹窗标题、固定报价与黄色选中框、购买按钮必须同时成立；动态“持有”余额不参与识别，右侧“30 钻石换 5 旗帜”永久禁止。购买弹窗仍在才允许重试，弹窗离开后不重复不可逆点击，目标队伍页稳定后才写入当天购买记录。
- 结果确认允许进入段位弹窗或直接回到列表；结果页仍在时有限重试，结果页消失后不盲点。
- 循环计数只在结算事务结束并连续两帧回到对手列表后增加，刷新列表不计数。

日志示例：

```text
模式=竞技场 页面=对手详情 动作候选=challenge 依据=来源画面锚点已确认
执行点击 动作=challenge 坐标=(x, y)
模式=竞技场 转场重试 动作=challenge 来源=对手详情仍在 尝试=2/4 坐标=(x, y)
模式=竞技场 转场确认 动作=challenge 从=对手详情 到=队伍选择 目标连续=2
模式=竞技场 轮次=1 业务完成=结算返回对手列表 目标连续=2
```

## 审查清单

- 动作是否同时定义了来源页面和允许目标页面？
- 危险动作是否有 `UNKNOWN` 分支，而不是把识别失败当作安全？
- 日志中的“成功”是否都有对应的业务证据？
- 相同外观、动态动画和弹窗遮挡是否会制造假阳性？
- 重试是否保持原目标，并避免重复执行不可逆动作？
- 超时诊断能否回答“点击前是什么、点击后变了哪里、为什么没确认”？
- 轮次是否只在完整业务闭环后增加？
